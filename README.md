# Litora

[![Go](https://img.shields.io/badge/Go-1.25.4-00ADD8?logo=go)](apps/lito-cli/go.mod)
[![Лицензия: MIT](https://img.shields.io/badge/Лицензия-MIT-green.svg)](LICENSE)

Исследовательская платформа для анализа береговой линии и рельефа дна Чёрного моря.
Litora объединяет вычислительное ядро на Go, API и веб-интерфейс: от локального
эксперимента в CLI до личного кабинета с историей расчётов и отчётами.

**Изучить методику → запустить расчёт → посмотреть результат → сохранить отчёт.**

## Что умеет Litora

- **Анализировать геометрию берега.** Вычислять box-counting размерность контура
  и строить обзорную карту на поставляемых данных Чёрного моря.
- **Исследовать сетки и рельеф дна.** Самостоятельный CLI содержит mesh- и
  seabed-сценарии; необходимые данные и внешние инструменты зависят от команды.
- **Разбирать береговые процессы.** Запускать демонстрационный сценарий эрозии
  Сочи и использовать CLI для калибровки CERC-модели.
- **Работать в личном кабинете.** Регистрироваться, запускать задания,
  отслеживать статус, отменять расчёты и возвращаться к собственной истории.
- **Просматривать и скачивать результаты.** Получать метрики, SVG-визуализации,
  файлы и машинно-читаемый manifest с контрольными суммами.
- **Автоматизировать работу.** Запускать CLI без платформы или обращаться к
  типизированному HTTP API, описанному в Swagger.
- **Изучать методы.** Читать общую документацию на сайте и в
  [пакете документации](packages/docs/content/).

Научные вычисления находятся в Go; API управляет доступом и заданиями, а web
показывает результаты. Формулы не дублируются между приложениями.

## Для кого

Для исследователей и инженеров — эксперименты с береговой геометрией и моделями;
для студентов и преподавателей — разбор методов на демонстрационных данных;
для разработчиков — CLI и API для построения собственных рабочих процессов.

Litora — исследовательский инструмент, не автоматическое заключение о безопасности
сооружений. Демонстрация эрозии не является гарантированным прогнозом размыва,
а обзорная карта не заменяет точную геодезическую съёмку.

## Два способа работы

| | Личный кабинет и API | Самостоятельный CLI |
| --- | --- | --- |
| Сценарии сейчас | Размерность, в том числе на своей линии; обзорная карта; демонстрационная эрозия | `source`, `map`, `dimension`, `mesh`, `seabed`, `erosion`, `calibrate-cerc`, `all` |
| Данные | Поставляемые наборы или своя небольшая линия GeoJSON для размерности; для эрозии настраивается число шагов | Входные данные и параметры по возможностям конкретной команды |
| Результаты | История в PostgreSQL, приватные файлы в S3, временные ссылки | Файлы в локальном каталоге, manifest по флагу |
| Зависимости | Аккаунт, API, worker, PostgreSQL и S3 | Go-бинарник; Gmsh/батиметрия для соответствующих сценариев |

Регистрация доступна по одноразовому приглашению от оператора.
Произвольные форматы и большие файлы через сайт, восстановление пароля и
подтверждение email пока не реализованы.
Production-развёртывание и восстановление ещё требуют staging-приёмки.

## Быстрый запуск всей системы

Нужны Docker Desktop / Docker Compose, Git LFS и Node.js 22.12+ с pnpm 10.15.0.
Go локально нужен только для разработки CLI; Docker собирает его самостоятельно.

```bash
git clone https://github.com/Nickitas/litora.git
cd litora
git lfs pull
pnpm install
pnpm up
```

`pnpm up` создаёт отсутствующий `.env.local` со случайными локальными паролями,
собирает приложения и поднимает PostgreSQL, MinIO, API, worker и web. Существующий
`.env.local` сохраняется. Первое скачивание образов и сборка могут занять несколько минут.
Если pnpm ещё не установлен: `npm install --global pnpm@10.15.0`.
При конфликте с Corepack сначала выполните `corepack disable pnpm`.

| Сервис                | Адрес                               |
| --------------------- | ----------------------------------- |
| Сайт и личный кабинет | http://localhost:5173/account       |
| Регистрация / вход    | http://localhost:5173/login         |
| Swagger               | http://localhost:3000/api/docs      |
| OpenAPI JSON          | http://localhost:3000/api/docs-json |
| API health            | http://localhost:3000/api/health    |
| MinIO Console         | http://localhost:9001               |
| MinIO S3              | http://localhost:9000               |
| PostgreSQL            | localhost:55432                     |

Порты настраиваются в `.env.local`. Логин MinIO — `S3_ACCESS_KEY`, пароль —
`S3_SECRET_KEY`. PostgreSQL использует `POSTGRES_*`. Пароли не коммитятся.
На существующих volumes пароль БД не меняется от редактирования `.env.local`.

Если `9000/9001` заняты другим проектом, укажите `S3_PORT=19000`,
`S3_CONSOLE_PORT=19001`, `S3_ENDPOINT=http://localhost:19000` и
`S3_PUBLIC_ENDPOINT=http://localhost:19000`. Консоль будет доступна на `19001`.

Получите ключ приглашения у оператора, откройте сайт, создайте аккаунт
(пароль от 10 символов), выберите сценарий и нажмите
«Запустить расчёт». В кабинете появятся статус, параметры, метрики, изображения
и ссылки на файлы. Доступны размерность, обзорная карта и демонстрационная эрозия
Сочи. Для расчёта «Размерность своей береговой линии» можно сразу нажать «Запустить
расчёт»: если свой файл не выбран, пример GeoJSON участка Сочи (OpenStreetMap,
ODbL) сохранится как приватный набор в вашем аккаунте. Для собственного контура
загрузите GeoJSON `LineString`, укажите источник и лицензию и выберите этот набор.
Допустимы
`EPSG:4326`, градусы, пары `[долгота, широта]`, 2–500 точек, до 64 KiB; научную
пригодность проверяет Go при выполнении. Регистрация реальная; демо-логинов нет.

```bash
pnpm logs        # журналы всех сервисов
pnpm down        # остановка; БД и файлы сохраняются в Docker volumes
pnpm up          # повторный запуск / пересборка после изменений
```

Не добавляйте `down -v`, если нужно сохранить пользователей и результаты.

## Разработка на хосте

Для Go требуется версия 1.25.4 или новее. Gmsh нужен для отдельных mesh-сценариев
самостоятельного CLI, но не для сценариев кабинета.

```bash
pnpm install
pnpm env:init
pnpm infra:up
pnpm build:cli
```

Затем в трёх терминалах из корня репозитория:

```bash
pnpm dev:api
pnpm dev:worker
pnpm dev:web
```

Если ранее запускали всю систему в Docker, сначала выполните `pnpm down`, затем
`pnpm infra:up`, чтобы освободить порты API/web. Vite проксирует `/api` на
`http://localhost:3000`; изменить адрес можно переменной `API_PROXY_TARGET`.
После изменения Go-кода повторите `pnpm build:cli`.

Настройки API/worker загружаются из корневого `.env.local`. Для нестандартного
размещения есть `LITORA_ENV_FILE`, `LITO_CLI_DIRECTORY`, `LITO_CLI_BINARY`,
`LITO_JOBS_DIRECTORY`, `LITORA_MIGRATIONS_DIR`. Таймаут задания — `JOB_TIMEOUT_MS`
(по умолчанию 300000). Если меняете порты, согласуйте `DATABASE_URL`,
`S3_ENDPOINT`, `S3_PUBLIC_ENDPOINT`, `WEB_ORIGIN` и proxy Vite.

## Как связаны приложения

```text
React → @litora/api-client → NestJS → PostgreSQL (очередь и метаданные)
                                          ↓
                              отдельный worker → Go CLI
                                          ↓
                                     MinIO / S3
```

API сразу возвращает задание `queued`; worker выполняет его асинхронно.
Доступ к расчётам ограничен владельцем. Access token живёт 15 минут и хранится
только в памяти браузера; refresh cookie — HttpOnly, ротируется при обновлении.
Пароли хешируются Argon2id. Signed URL файлов действует 15 минут.

В Swagger выполните `/api/auth/register` или `/api/auth/login`, скопируйте
`accessToken` в **Authorize**, затем вызывайте `/api/calculations`.
Доверенные источники запросов авторизации — `WEB_ORIGIN` и `API_ORIGIN`
(по умолчанию `http://localhost:3000` для Swagger).

```json
{ "kind": "erosion", "input": { "steps": 3 } }
```

Миграции находятся в `infra/postgres/init/`. API и worker применяют новые `.sql`
файлы автоматически и записывают их в `schema_migrations`; существующие миграции
после публикации не редактируйте, добавляйте новые. В локальном окружении bucket
создаётся автоматически, если это разрешено настройкой `S3_AUTO_CREATE_BUCKET`;
в production он должен быть создан оператором заранее. Для доступа браузера к файлам `S3_PUBLIC_ENDPOINT` должен быть
внешним адресом, даже если внутренний `S3_ENDPOINT` равен `http://minio:9000`.

## Самостоятельный CLI

```bash
pnpm build:cli
cd apps/lito-cli
./bin/lito --help
./bin/lito dimension --output output/example --manifest output/example/manifest.json
```

CLI не требует регистрации, API, БД или MinIO. Команды `source`, `map`,
`dimension`, `mesh`, `seabed`, `erosion`, `calibrate-cerc`, `all` сохраняются.
HTTP предоставляет три сценария на поставляемых данных и один на пользовательской
линии GeoJSON. Другие пользовательские наборы и сложные батиметрические цепочки —
следующие этапы из плана.

Служебный импорт старых результатов:

```bash
pnpm --filter litora-api artifacts:import -- ../lito-cli/output/example manual-import
```

Этот импорт создаёт задание без владельца; оно не появляется в пользовательском
кабинете. Для личных расчётов используйте API или сайт.

## Auth за reverse proxy

При прямом запуске API `TRUSTED_PROXY_CIDRS` оставьте пустым. Для reverse proxy
задавайте только его реальные IP/CIDR через запятую; `true` и число hops не
разрешены. Production-пример уже задаёт адрес Caddy и отдельную Docker-сеть:
подробности и staging-проверки в [инструкции развёртывания](sdd/deployment.md).
Не публикуйте порт API наружу и не доверяйте всей приватной сети.
Auth POST-запросы делят лимит 30 в минуту на IP; ответ 429 содержит `Retry-After`.
Это не замена ingress rate limit и DDoS-защиты.

## Приглашения для регистрации

Оператор с доступом к окружению API выпускает одноразовые ключи. На хосте:

```bash
pnpm --filter litora-api invitations create --expires-hours 168
pnpm --filter litora-api invitations revoke --id UUID_ПРИГЛАШЕНИЯ
```

При Docker-запуске вместо pnpm:

```bash
docker compose --env-file .env.local -f infra/compose.yaml exec -T api node dist/scripts/invitations.js create --expires-hours 168
```

Команда возвращает JSON с `id`, `code`, `expiresAt`. Передайте `code` получателю
по закрытому каналу; не публикуйте вывод и не направляйте его в общие логи.
Исходный ключ нельзя восстановить из БД. Default срок — 7 дней; допустимы 1–720
часов, `--count 1`–`20` для выпуска нескольких ключей. Один ключ создаёт только
один аккаунт; ошибка регистрации не расходует приглашение. Старым пользователям
для входа ключ не нужен. CLI применяет новые миграции до выпуска приглашений.

## Проверки

`pnpm test:bundle` проверяет production-граф web: стартовый JS не более 400 КБ,
Motion и docs не должны загружаться статически с entry. Проверка входит в
`pnpm verify`. Подробный отчёт по маршрутам: `pnpm --filter litora-web analyze:bundle`.
Он собирается в памяти и не заменяет браузерные замеры скорости.

Единый локальный прогон и CI:

```bash
pnpm verify
```

Он проверяет структуру workspace и документации, типы, lint, тесты web/API/Go
и сборку API/web. Отдельные команды:

```bash
pnpm check:workspace
pnpm typecheck
pnpm lint
pnpm build:api
pnpm build:web
pnpm test:web
pnpm test:api
pnpm test:api:db        # нужен TEST_DATABASE_URL отдельной БД litora_test_*
pnpm test:web:e2e       # после playwright install chromium; отдельный Vite на 5189
pnpm test:cli
pnpm test:integration   # дополнительно нужен TEST_INVITATIONS_JSON, см. ниже
```

Браузерный `test:web:e2e` подменяет ответы `/api/**` и не затрагивает рабочую
БД или S3. Установка Chromium и подробности — в [SDD](sdd/development.md).

Локальный `test:api` без `TEST_DATABASE_URL` пропускает три PostgreSQL suites.
`test:api:db` и CI требуют выделенную тестовую БД: проверяются приглашения,
сессии, доступ только владельцу и конкурентная квота заданий. Не используйте
рабочую БД; инструкции — в [SDD](sdd/development.md). Эти тесты не обращаются к
реальному S3.

Интеграционный тест запускает все четыре сценария, проверяет регистрацию, ротацию
сессии, чужие задания, отмену, Swagger, приватность S3 и SHA-256 манифеста. Он
оставляет тестовых пользователей и результаты в локальной БД.
Используйте отдельный тестовый стенд. Выпустите три тестовых приглашения и передайте
JSON через environment, не публикуя его:

```bash
TEST_INVITATIONS_JSON="$(pnpm --silent --filter litora-api invitations create --count 3 --expires-hours 1)" pnpm test:integration
```

Для проверки через web proxy добавьте `TEST_API_URL=http://localhost:5173/api`
к команде выше; `TEST_INVITATIONS_JSON` также обязателен. Каждый прогон требует
новых ключей, поскольку приглашения одноразовые.

## Границы текущей реализации

Это рабочая локальная основа системы. Перед публичным размещением настройте HTTPS,
`COOKIE_SECURE=true`, секреты, резервное копирование и внешний rate limiting.
Восстановление пароля, подтверждение почты, загрузка произвольных данных,
пагинация и политики удаления результатов ещё не реализованы.
