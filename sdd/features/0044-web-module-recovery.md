# 0044 — восстановление навигации при сбое загрузки модуля web

- Статус: реализовано локально; production-проверка после развёртывания открыта.
- Владелец решения: команда Litora.
- Дата: 14.10.2026; исходный SHA: `fbb6b35`.
- Область: web, nginx.

## Проблема и границы

Страницы web загружаются лениво. Старая вкладка после обновления контейнера может
запросить удалённый JS-файл; нестабильная сеть или dev-сервер вызывают тот же класс
ошибки. Раньше nginx отдавал HTML вместо отсутствующего `/assets/*`, а маршрут сразу
показывал экран «Не удалось открыть страницу» и без доказательства называл модуль
«обновлённым». После ручной перезагрузки переход обычно работал.

Исправляем доставку статических файлов и UX восстановления. Не вводим service worker,
хранение прошлых бандлов или внешнюю инфраструктуру. При устойчивом сбое скрывать
ошибку нельзя.

## Требования и приёмка

| ID | Требование | Given / When / Then | Доказательство |
| --- | --- | --- | --- |
| MOD-001 | Однократное восстановление | Первый сбой lazy-модуля при переходе → обновляется текущий URL, раздел открывается без экрана ошибки | E2E с одним отказом модуля |
| MOD-002 | Нет цикла | Модуль не доступен после обновления → показывается ошибка и действие «Обновить страницу» | E2E с постоянным отказом |
| MOD-003 | Честная диагностика | Ошибка импорта без сведений о релизе → UI не утверждает, что причина именно в обновлении | Код и E2E |
| MOD-004 | Правильный HTTP | Отсутствующий `/assets/*.js` → 404, не HTML; `index.html` → revalidation; хешированные assets → immutable | Проверка nginx-конфигурации и HTTP на staging |
| MOD-005 | Прочие ошибки не маскируются | Ошибка рендера/данных → обычный экран ошибки, без автоматической перезагрузки | Код и ручная проверка |

## Контракты и модель данных

API и БД не меняются. Попытка автоматического восстановления хранится в
`sessionStorage` вкладки на 60 секунд. Если хранилище недоступно или браузер явно
offline, перезагрузка не запускается. UI использует существующие токены темы;
промежуточный текст объявляется как `role=status`, ошибка — как `role=alert`.

## Риски и альтернативы

Перезагрузка сбрасывает несохранённое локальное состояние страницы. В данном случае
раздел не успел загрузиться, но состояние общего интерфейса может потеряться.
Хранение старых бандлов позволило бы избежать перезагрузки, однако требует
версионированного статического хранилища и политики очистки; для текущего nginx
выбрана ограниченная самокоррекция. При сетевом сбое возможно одно лишнее обновление.
