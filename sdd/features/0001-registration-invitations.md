# 0001 — регистрация по одноразовым приглашениям

- Статус: реализовано и проверено локально; staging-приёмка отдельно.
- Владелец: владелец Litora. Дата: 26.09.2026.
- Область: contracts / API / web / infra / операторский CLI.

## Границы

Новая регистрация требует одноразовое приглашение. Принято рабочее предположение:
ключ выпускает оператор, default срок 7 дней (настраивается от 1 до 720 часов).
Существующие пользователи входят как раньше. Нет общего ключа, автоматической
рассылки, публичного endpoint выпуска, привязки к email или admin UI.

## Требования и приёмка

| ID | Требование | Проверка |
| --- | --- | --- |
| AUTH-005 | Без invitationCode нельзя зарегистрироваться | Нет/неверный формат → 400; неизвестный, истёкший, отозванный или использованный → общий 403 |
| AUTH-006 | Погашение, user и session атомарны | Два параллельных запроса → один success; ошибка insert user/session откатывает приглашение |
| AUTH-007 | Выпуск/отзыв только оператором | CLI create/revoke; HTTP выпуска отсутствует |
| AUTH-008 | Исходный ключ не сохраняется в БД | 32 случайных байта, префикс litora_, SHA-256 в таблице; код не в URL/storage/log API |

## Контракт и модель

RegisterDto получает обязательный `invitationCode`. LoginDto не меняется.
Миграция `003_registration_invitations.sql` добавляет `registration_invitations`:
UUID, code_hash, created_at, expires_at, used_at, used_by, revoked_at. Claim —
условный UPDATE RETURNING внутри транзакции; конкурентные claim блокируются на
строке. Сессия создаётся до COMMIT. Истёкшие/отозванные записи сохраняются;
retention отдельно. Это bearer-секрет: любой обладатель ключа может его погасить.

## UI и обновление

Только в режиме регистрации: обязательное поле ключа с label, подсказкой и
autocomplete=off. Ошибка доступна через role=alert. Запрос — в submit-handler,
без новых зависимостей или сохранения ключа. Swagger отражает обязательность поля.
Сначала обновить API/миграцию, затем web; старый web больше не может регистрировать
пользователей (400), вход существующих пользователей совместим. Откат API на старую
версию снова откроет регистрацию — недопустим без отдельного решения оператора.

## Проверки и выпуск

Unit, PostgreSQL-тесты atomic claim/rollback/expiry/revoke и HTTP-интеграция.
Применять миграцию к пользовательской БД в этом прогоне не требуется: тесты
проводятся на отдельной БД. Статус released только после фактического развёртывания.
