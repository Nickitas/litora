# 0007 — внедрение дизайн-системы «Чёрное море»

- Статус: implementing, 30.09.2026.
- Источник норм: [дизайн-система](../design-system.md).
- Область: web, без изменения API и научных SVG.

## Цель и границы

Единая светлая/тёмная палитра и переиспользуемые состояния рабочих экранов.
Сначала semantic tokens, form controls, auth/account, статус расчёта и навигация;
затем публичные страницы, справочник, иллюстрации и полный визуальный аудит.
Нельзя смешивать Base UI и Radix варианты shadcn, менять математические цвета Go
или считать смену токенов завершением проверки доступности.

## Приёмка

| ID | Требование | Проверка |
| --- | --- | --- |
| DS-010 | Один источник HEX-токенов для light/dark, chart/status/warning | CSS и сверка с `design-system.md`; текст/primary/input достигают принятых контрастных пар |
| DS-011 | Форма входа и кабинет используют единые контролы, surface и focus | Клавиатура, label, disabled/loading/error, 360 px и 200% zoom |
| DS-012 | Job status понятен без цвета | Общий компонент: подпись + иконка + status tokens; все пять состояний |
| DS-013 | Тема и движение управляемы | system/light/dark, reduced motion, рабочие страницы без постоянной фоновой анимации |
| DS-014 | Публичные страницы и docs не вводят произвольные палитры | Отдельный аудит hardcoded цветов, замена смысловыми токенами или документированное исключение |

## Порядок и риски

1. Сопоставить текущие CSS variables и `components.json` с SDD.
2. Ввести semantic tokens; не менять цвет научных иллюстраций и карты.
3. Привести shadcn Button/Badge и рабочие формы; проверить клавиатуру и темы.
4. Перенести публичные страницы и документацию; проверить реальные экраны и контраст.
5. `pnpm verify`, браузерные тесты, 360 px / 200% zoom / reduced-motion smoke.

## Фактический срез

- Семантическая палитра SDD введена в общий CSS для светлой и тёмной темы;
  статусные/предупреждающие/графические токены доступны через Tailwind.
- Auth и кабинет используют общие стили контролов и Button; статус job
  отображается одним компонентом с иконкой и текстом. Рабочие экраны больше
  не запускают постоянный фон Particles.
- Переключатель темы показывает system/light/dark и сохраняет предпочтение.
  Часть docs и installation переведена на токены.
- Декоративная карточка и карточка релиза используют общие токены вместо
  фиолетово-розовой палитры; предупреждение о скачивании и hero справочника
  также приведены к палитре. Научная цветовая шкала 3D-рельефа остаётся
  осознанным исключением и не зависит от UI-темы.
- Главная и раздел «О проекте» используют те же токены; погодная карточка
  глобуса и блок кода справочника больше не держат отдельную палитру.
  У главной появился настоящий H1 вместо одного лишь анимированного текста.
  Непрерывная морфинг-анимация убрана; глобус и 3D-рельеф не вращаются при
  `prefers-reduced-motion`, декоративные метеоры и индикаторы также замирают.
- CTA главной, установки, релизов, скачивания и входа используют один
  интерактивный элемент — ссылку через shadcn `Button asChild`; вложенных
  `<button>` в `<a>` больше нет. В начале layout добавлена ссылка перехода
  к основному содержимому для клавиатуры; переходы страниц не прокручивают
  экран плавно при `prefers-reduced-motion`.
- Мобильное меню закрывается по Escape с возвратом фокуса на кнопку;
  `aria-expanded` и `aria-controls` связывают кнопку с меню. JS-анимации
  раскрытия выключаются при reduced motion. Меню пользователя на desktop
  получило доступное имя кнопки и такое же закрытие по Escape.
- Chromium E2E проверяет контраст основных, статусных и warning токенов,
  выбор темы, focus, reduced-motion spinner, 360 px, все пять статусов, а
  также открытие справочника и релизов в обеих темах. Это не заменяет ручную
  проверку 200% zoom, screen reader и всех публичных маршрутов.

Открыто: полная визуальная приёмка остальных публичных страниц, настоящий 200% zoom и

перекрашивать вместе с темой. Для DS-014 остаётся ручная проверка реальных
экранов, не только поиск классов цвета.

Глобальная замена токенов влияет на все страницы; rollback — возврат CSS-токенов
и UI-примитивов одним изменением без миграции данных. Дизайн-систему нельзя
считать выполненной, пока DS-014 и реальная визуальная приёмка не закрыты.
