# 0005 — браузерная регрессия критических сценариев web

- Статус: verified locally; CI pending. Дата: 29.09.2026.
- Владелец решения: разработчики Litora; область: web, CI, SDD.
- Связано с P2 «Расширить автоматические тесты» из maintenance.

## Проблема и границы

Статическая проверка маршрутов и ручной smoke не проверяют поведение формы
регистрации, входа, кабинета и ошибок API в браузере. Добавляем небольшую
браузерную регрессию с настоящим React-приложением и подменёнными HTTP-ответами.
Не создаём реальные учётные записи, задания или S3-объекты. Это не проверка
научного расчёта и не замена полного интеграционного сценария.

## Требования и приёмка

| ID | Требование | Проверка |
| --- | --- | --- |
| WEB-TEST-001 | Неавторизованный посетитель кабинета попадает на вход | `/account` при 401 refresh → `/login`; форма доступна с клавиатуры |
| WEB-TEST-002 | Регистрация требует ключ приглашения и передаёт его API | Переключить форму, без ключа submit не происходит; с ключом POST содержит ожидаемые поля, затем кабинет |
| WEB-TEST-003 | Ошибки входа видимы, успешный вход открывает кабинет | 401 → alert без перехода; 200 → `/account` с именем пользователя |
| WEB-TEST-004 | Создание расчёта и ошибки API отражаются в кабинете | Виды сценариев загружаются; POST содержит выбранный тип и параметры; созданное задание появляется; отказ → alert и доступен повтор |
| WEB-TEST-005 | Проверка воспроизводима в CI | Локальный Vite на loopback, перехват только `/api/**`, короткий таймаут, без БД/S3; Chromium устанавливается в CI |

## Контракты и данные

Используем существующие DTO и маршруты. Фикстуры HTTP должны совпадать с
контрактами: refresh возвращает 401 или AuthDto, create возвращает
CalculationJobDto. Не меняем backend, расчётные формулы, миграции и API-клиент.
Тест вводит данные только в браузерный процесс и очищает их вместе с контекстом.

## Риски и альтернативы

Playwright добавляет dev-зависимость и установку Chromium в CI. Сетевой вызов к
настоящему API во время UI-теста недопустим: незнакомый `/api/**` должен
завершать тест ошибкой. Альтернатива — DOM/unit-тест с jsdom — быстрее, но не
поймает проблемы маршрутизации, ленивой загрузки и браузерной валидации формы.
Анимации не должны быть основанием ожиданий; проверяем роли, текст и URL.
