## Проблема и границы

`/account` обозначал одновременно рабочее место для расчётов и будущий личный
профиль. Меню пользователя показывало только часть рабочих сценариев. Разделяем
термины: `/lab` — исследования, `/account` — личные данные и будущие настройки.
Не вводим новые научные сценарии, права, API, сущности БД или работающие настройки
профиля. В меню нет ссылок на ещё не реализованные проекты и хранилище.

## Контракты и совместимость

Новые DTO и endpoint не нужны. Существующие owner-проверки API остаются источником
прав доступа. `/account` теперь **не** перенаправляет в лабораторию: он означает
личный профиль. Старые прямые ссылки `/account/calculations`,
`/account/calculations/:jobId`, `/account/datasets` и `/account/shoreline`
перенаправляют на одноимённые `/lab/*` с query/hash. Устаревший
`/account/calculations/new` ведёт на `/lab`; `/lab/calculations/new` также
ведёт на обзор. После входа открывается `/lab`.

## Риски и альтернативы

- Смена значения корневого `/account` для сохранённой закладки неизбежна при
  создании отдельного аккаунта. Старые вложенные адреса сохраняются; в UI и
  документации рабочая точка входа заменена на `/lab`.
- Меню построено на имеющихся Radix/shadcn-примитивах, без новой зависимости.
  Наличие пункта не означает новый API или готовую настройку.
- Форма запуска получает `new=1` только как UI-сигнал. Параметры расчёта не
  передаются через адресную строку; закрытие очищает сигнал.
