# 0016 — отчёт об отсутствующих S3-артефактах

- Статус: implementing; локальная проверка, staging не подтверждён.
- Область: операторская команда API, PostgreSQL, приватный S3 bucket.

## Проблема и границы

Срез 0015 обнаруживает частичные объекты S3, оставшиеся от ошибочных jobs.
Обратный сбой — metadata в БД указывает на отсутствующий файл — не был виден.
Такой файл нельзя выдавать пользователю как доступный результат. Этот срез
добавляет только диагностику, без автоматического исправления ссылок, смены
статуса job или восстановления файлов.

## Требования и приёмка

| ID | Требование | Проверка |
| --- | --- | --- |
| OPS-ART-016-1 | Изучать записи артефактов текущего bucket под `users/`, не более 10 000 за запуск | Лимит SQL и unit-проверка отбора |
| OPS-ART-016-2 | Считать подозрительной только старую запись завершённого job, отсутствующую в S3 LIST | Unit для статусов, дат, владельца и путей |
| OPS-ART-016-3 | Подтверждать отсутствие через S3 HEAD, не более 100 запросов за запуск | Отчёт `missingS3` / `missingS3Unchecked`; локальный dry-run |
| OPS-ART-016-4 | Не удалять и не исправлять отсутствующие объекты даже с `--apply` | В коде нет операций записи для категории `missingS3` |

## Контракт и модель данных

Используются существующие `calculation_artifacts` и `calculation_jobs`, миграций,
HTTP DTO и UI нет. `missingS3` — число подтверждённых `HEAD 404` в пределах
первых 100 подозрительных записей. `missingS3Unchecked` — число оставшихся
записей, не проверенных через HEAD; оно не равно подтверждённой потере.
`missingS3Sample` содержит максимум 20 ключей для оператора. Учитываются
`succeeded`, `failed`, `cancelled`, если `finished_at` и дата metadata старше
порога (по умолчанию 24 часа). Активные jobs и входные datasets исключены.

## Риски и альтернативы

HEAD может вернуть временную ошибку доступа/сети: такую ошибку не объявляем
пропажей, команда аварийно завершается. Даже подтверждённый 404 не говорит,
почему файл исчез, а versioned S3 может иметь восстанавливаемую версию.
Автоматическое удаление записи БД или перезапуск job может скрыть аварию;
эти действия остаются за отдельным расследованием и восстановлением.
Обход ограничен 10 000 объектов S3 и 10 000 записей БД; при превышении
команда прекращается до `--apply`. Для больших bucket нужна пагинация/батчи.
