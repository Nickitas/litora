# 0017 — пилотная квота малых GeoJSON-наборов

- Статус: implementing; локальные проверки, staging не подтверждён.
- Область: API, PostgreSQL, приватный S3, Swagger.

## Проблема и границы

Один GeoJSON ограничен 64 KiB, но раньше пользователь мог создать неограниченное
число наборов; список кабинета показывает только последние 100. Вводится
пилотный предел **100 сохранённых наборов на пользователя**. Это предел числа
наборов, не срок хранения и не квота на результаты расчётов. Уже существующие
данные не удаляются; при превышении пользователь должен обратиться к оператору,
пока не появится безопасное удаление наборов и связанных jobs.

## Требования и приёмка

| ID | Требование | Проверка |
| --- | --- | --- |
| DATA-QUOTA-017-1 | При 100 сохранённых наборах новый POST `/api/datasets` возвращает 409 до загрузки S3 | PostgreSQL-тест + Swagger |
| DATA-QUOTA-017-2 | Два одновременных запроса при 99 наборах не создают 101-ю запись | PostgreSQL-тест с барьером загрузки |
| DATA-QUOTA-017-3 | Если квота исчерпана между предварительной проверкой и SQL INSERT, загруженный этим запросом объект удаляется | PostgreSQL-тест проверяет S3-мок |
| DATA-QUOTA-017-4 | Другой пользователь не влияет на квоту и чужие наборы не видит | Существующий owner-тест |

## Контракт и модель данных

`CreateDatasetDto` и успешный `DatasetDto` не меняются. Новый ответ — HTTP 409
с русским сообщением. Предел равен 100, что соответствует текущему лимиту списка.
До загрузки выполняется дешёвая проверка; окончательная проверка и INSERT
проходят в транзакции под `FOR UPDATE` строки пользователя. Это сериализует
создание наборов одного владельца без долгой транзакции во время S3-запроса.
Миграции нет: используются существующие `users` и `datasets`.

## Риски и альтернативы

S3 upload происходит до транзакции. При отказе INSERT объект удаляется; при
краше процесса между upload и cleanup возможен orphan dataset. Его отдельная
сверка ещё нужна. Альтернатива — держать транзакцию/строку пользователя во
время S3 upload — отклонена из-за сетевых задержек и блокировки создания jobs.
Для больших входов нужна предварительная reservation-модель и отдельная
байтовая квота. Эта квота не защищает от общего роста результатов jobs.
