# 0061 — Участки всего побережья и строгие форматы научных входов

- Статус: implemented; локальная приёмка 21.10.2026, научная аттестация не выполнялась.
- Дата: 20–21.10.2026; ветка `development`.
- Область: contracts, Go, API/worker, api-client, web, документация.

## Проблема и границы

Встроенный полный контур доступен только целиком, а пользовательские научные
файлы часто проверяются лишь по расширению и префиксу. Добавляем выделение
прямоугольной области на карте любого участка Чёрного моря, сохранение всех
пересекающих её линий с происхождением и использование отдельных линий в
последующих расчётах. Источник — закреплённый полный контур или собственный
GeoJSON. Раздельные линии не соединяются и не замыкаются искусственно.

Открытая береговая линия не является замкнутой морской областью для Gmsh.
Модель дна требует своей совместимой MSH/батиметрии; волны Сочи не переносятся
на другие участки. Новые сетевые загрузки, источники и фоновые HTTP-расчёты
не вводятся. В справочнике даём официальные ресурсы и требования преобразования.

## Требования и приёмка

| ID | Требование | Проверка |
| --- | --- | --- |
| REG-001 | Область выбирается на карте или четырьмя координатами; доступны встроенный и свой контуры | Browser: клавиатура, 360 px, обе темы, ошибка/загрузка |
| REG-002 | Go обрезает каждый исходный путь, сохраняя разрывы, порядок, острова и точные пересечения границ | Численные Go-тесты, несколько частей, пустая область, касание, замкнутое кольцо |
| REG-003 | SVG, GeoJSON линий и JSON-паспорт содержат границы, CRS/единицы и SHA-256 источника; отдельные линии доступны владельцу как вход | CLI manifest, API allowlist, worker/API/S3 |
| REG-004 | До статуса ready файл проходит ограниченную по размеру проверку строго фиксированной структуры; неверные поля/типы/версии/координаты/таблицы отвергаются | API-положительные и отрицательные тесты; Go остаётся источником научной совместимости |
| REG-005 | Пользователь может скачать точную схему и видит источники, форматы и необходимость преобразования | Browser, docs, сверка первичных ресурсов |

## Контракты и архитектура

Новый сценарий `coastline_region`: west/south/east/north в градусах WGS84 и
необязательный UUID собственного контура. Источник и файлы назначает сервер.
Версия входа job повышается до 14 с чтением прежних 1–13; миграций нет.
Геометрическое отсечение и научная проверка находятся в Go, API только
проверяет DTO/структуру файлов и контролирует владение. Геоданные для карты
проходят через API client; web не содержит собственного научного алгоритма.

JSON Schema генерируются из Go-типов, фиксируются в версии форматов и
выдаются пользователю тем же API, который применяет их на upload. Проверка
JSON Schema выполняется стандартным валидатором Ajv; формулы в TS не
переносятся. Табличные и MSH-файлы проверяются поточно по фиксированному
формату. Структурная пригодность отдельного файла не подтверждает совместимость
его с другими файлами, разрешение, точность и научную аттестацию.

Новые JSON/GeoJSON имеют явный предел памяти на upload; существующие ready
файлы и завершённые jobs сохраняются. Source UUID, SHA-256 и зависимости
проверяются существующим механизмом приватных научных артефактов.

## План и риски

- [x] Contracts и runtime-границы, версия input schema, схемы файлов.
- [x] Go: отсечение всех путей, отчёты, manifest и тесты.
- [x] API/worker: новый сценарий, схемы, строгая загрузка и каталог данных.
- [x] Web: область на карте, загрузка, схемы/источники, дальнейшие расчёты.
- [x] Документация, gate, браузерная и изолированная сквозная проверка.

Риски: пустая область, множество отдельных линий, малая детализация источника,
ошибки CRS/порядка осей, слишком большие файлы, несогласованные паспорта.
Не упрощаем точки при выделении и не выдаём рамку области за морской берег.
Откат: скрыть новый сценарий, дождаться jobs v14; старые данные не удалять.

## Доказательства локальной приёмки

`pnpm verify` и `go vet ./...` прошли. Gate включает 10 реальных комплектов
отчётов CLI/worker, в том числе `coastline_region`, проверку манифеста,
SHA-256 и совпадения размерности полного контура с эталоном. API: 113 тестов,
104 passed, 9 SQL-тестов skipped без отдельного TEST_DATABASE_URL для unit-набора.

Изолированный стенд с отдельными PostgreSQL DB и MinIO bucket подтвердил
встроенный и загруженный источники: одинаковая область дала 23 отдельные
линии; источник и результаты проверены по SHA-256. Переход
`coastline_region → dimension_file` использовал собственный артефакт без
повторной загрузки. Проверены отрицательный upload с неизвестным полем,
pending после отказа, приватность preview/артефактов и OpenAPI.
Прошла цепочка `mesh → seabed_build → render/adapt → generate/compare`,
включая рисунки 3–5 и совпадение MSH с отдельным CLI. Тестовые DB/bucket
после проверки удалены; рабочие данные не использовались.

Пять новых браузерных сценариев прошли на полном закреплённом GeoJSON:
две темы, 360 px, выбор углов, числовой ввод с клавиатуры/Tab, свой источник
без скрытой подмены, перенос UUID и скачивание схемы. В полном browser-наборе
83 passed, 1 skipped (live-тест требует тестовых credentials), 1 failed
на счётчике запросов восстановления lazy-модуля после 404; одиночный повтор
этого теста прошёл. Причина нестабильности счётчика не установлена.

CLI дополнительно проверен на западе, севере, юге, востоке и всём море:
29/79/13/10/92 отдельных линий соответственно. SVG отрисованы Chrome,
карта выбора просмотрена в desktop/mobile. Локальные артефакты приёмки:
`apps/lito-cli/output/acceptance/regions-2026-10-21/` (игнорируются Git).
Для всего моря учитываются все пути источника, включая отдельные кольца;
это 11 565 точек по 92 линиям, в отличие от нормализованного внешнего
контура из 9 635 точек для прежнего отчёта размерности.

Архитектурное решение: [ADR-027](../decisions.md#adr-027--фиксированные-схемы-научных-файлов-из-go).
Пользовательская инструкция: `packages/docs/content/black-sea-regions-and-data.md`.
Для локальной работы подняты standard/heavy worker; развёртывание production
и независимая оценка точности исходных данных в эту приёмку не входят.
