## Проблема и границы

До этого инкремента кабинет поддерживал четыре сценария, тогда как CLI строит научные карты,
сетки и отчёты из больших входных файлов. Приоритет — воспроизвести рисунки
`output/article_1/figures` архивного CLI. Рисунки создаются Go; web задаёт
параметры и показывает SVG и прочие артефакты через приватный API/S3.

Первый инкремент открывает загрузку научных входов и сценарии `source_file`,
`map_file`, `dimension_file`,
`mesh`, `seabed_build`, `seabed_render`, `seabed_adapt`,
`seabed_generate_adaptive`, `seabed_validate`, `seabed_compare_adaptive`.
Для цепочки нужны совместимые контур, плоская MSH,
проверенный набор батиметрии и паспорта. Однозначно распознаваемые артефакты
успешных собственных jobs можно выбирать как вход следующего шага без повторной
загрузки. Неизвестные имена и форматы остаются недоступны для автоподстановки.
Полный каталог остальных CLI-команд описан в [плане 0028](0028-full-cli-web-parity.md)
и выполняется следующими инкрементами. Артефакты
архива служат эталоном приёмки, не включаются в Git и не выдаются за результаты
нового расчёта.

## Контракты и данные

`scientific_inputs` — приватные immutable файлы с типом роли, атрибуцией,
размером и SHA-256. HTTP upload потоковый; перед постановкой задания API
проверяет статус `ready` и владельца. Worker повторно сверяет размер и хеш
после скачивания. Ссылки S3 остаются временными. Вход каждого job сохраняет
UUID наборов и численные параметры, но не клиентский путь, URL или shell-флаги.
UUID научного входа может указывать на загруженный файл или на распознанный
артефакт собственного успешного job. Разрешённые пары исходного kind и точного
пути артефакта задаются на сервере. Артефакты не копируются в S3; поэтому их
нельзя удалять, пока есть зависимые задания. Пилотный лимит повторного входа —
2 ГиБ на артефакт и 4 ГиБ суммарно на задание.

`source_file` проверяет и сохраняет снимок загруженного GeoJSON, а
`map_file` строит его обзорную карту. Удалённый URL и обновление кэша
остаются возможностями только CLI. `dimension_file` работает с GeoJSON
береговой линии; `mesh` строит плоскую MSH,
`seabed_build` назначает ей глубины из проверенного JSON/паспорта;
`seabed_render` принимает батиметрический MSH и паспорт EXPORT-02;
`seabed_adapt` — MSH; `seabed_generate_adaptive` и сравнение дополнительно
принимают CSV/JSON поля, полный контур и используют Gmsh. `seabed_validate`
требует отдельную опорную модель и её паспорт неопределённости. Сравнение
может построить два SVG крупного плана Кызылырмакской косы по реальным
ячейкам; это не точное воспроизведение архивного оформления рисунков 6–7.
Атрибуция батиметрии задаётся паспортом источника, не свободной строкой в CLI.

## Риски и альтернативы

Для крупных MSH нужны потоковая передача, multipart S3, проверка лимитов на
HTTP и диске worker. Упавшее задание может оставить часть файлов в S3; текущая
сверка артефактов остаётся обязательной. Высокие лимиты разрешаются лишь
выделенному worker, включая `dimension_file`, не расширяют обычную очередь. Количество одновременных
тяжёлых задач и срок хранения перед публичным запуском требуют отдельного
ресурсного замера. Точная научная эквивалентность архивных SVG зависит от
версии Go, Gmsh и входных SHA-256.

## Проверки и выпуск

Применять новую миграцию без изменения старых. Для rollback старый API
игнорирует новые строки и kinds, но старый worker не должен забирать heavy jobs.
Интеграционные тесты запускать только с отдельной БД и bucket; гигабайтный
эталон не коммитить. Локально проверены typecheck, сборки API/web, lint web,
API-тесты (53 пройдено на временной выделенной PostgreSQL, включая отрицательные
проверки владельца и роли артефакта),
тесты Go, `go vet`, проверки workspace/bundle и синтаксис Compose. Миграции
001–009 применены на временном изолированном PostgreSQL без сети. Тестовая БД
после прогона удалена вместе с контейнером. Из архивных
входов CLI построил dimension, render и adapt с SVG и манифестами; это не
сквозной HTTP/S3-прогон и не доказательство паритета 01–07. Интеграция
загрузки и всего workflow остаётся непроверенной без выделенной тестовой БД,
приватного bucket и ресурсного замера Gmsh. Статус остаётся `implementing`;
полный CLI-каталог ещё не открыт в web.
