# 0011 — идентификация методов расчёта Go

- Статус: локальный срез A3; staging и научная валидация не подтверждены.
- Область: Go CLI, worker, PostgreSQL, contracts, Swagger, кабинет.

## Решение

Go остаётся единственным источником ревизии вычислительного метода. Успешная
команда с `--manifest` создаёт `manifest.json` схемы v2. Для трёх методов,
доступных через HTTP, добавлен объект `method: {id, revision}`:

| Команда CLI | HTTP kind | ID | Начальная ревизия |
| --- | --- | --- | --- |
| `lito dimension` | `dimension`, `dimension_dataset` | `box-counting` | `baseline-1` |
| `lito map` | `map` | `black-sea-overview` | `baseline-1` |
| `lito erosion` | `erosion` | `cerc-one-line` | `baseline-1` |

`baseline-1` — метка существующей реализации на момент введения реестра, а не
утверждение о научной проверке, калибровке или применимости. Для остальных
CLI-команд поле `method` отсутствует: выдуманную версию не присваиваем.
`schemaVersion` манифеста, `inputSchemaVersion`, `resultSchemaVersion`,
`coreVersion` (SHA-256 бинарника) и ревизия метода — разные величины.

Worker проверяет схему, команду, идентификатор и допустимый формат ревизии
перед публикацией артефактов. Успешное задание сохраняет `method_id` и
`method_revision` в PostgreSQL и отдаёт их через API и кабинет. Старые записи
остаются с `NULL`; миграция 006 не подставляет значения задним числом.
Несовместимый манифест завершает job ошибкой; он не превращается в успех.

При изменении формул или значимого алгоритмического поведения Go нужно
повысить ревизию соответствующего метода и обновить научные тесты и описание
методики. Изменение только DTO требует версии схемы, а не искусственного
повышения ревизии. Будущие web-команды добавляются в реестр и контракт
отдельным срезом после проверки входов, лицензий и ресурсов.

## Проверка

- Go unit: manifest v2 и отображение трёх команд, отсутствие метода у
  неразобранных команд.
- API unit: отклонение неверной версии манифеста, команды, ID и ревизии.
- Интеграция: четыре HTTP-kind дают совпадающие поля в Go-манифесте, job DTO
  и summary; старые строки БД не получают ревизию автоматически.
