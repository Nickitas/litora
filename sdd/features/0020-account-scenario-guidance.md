## Проблема и границы

В форме запуска названия и краткие описания приходили из API, но пользователь не
видел источник входных данных и ограничения конкретного сценария. Особенно легко
было принять демонстрационный `erosion` за прогноз. Лимит пяти незавершённых
jobs также обнаруживался только после отказа API.

Этот срез добавляет пояснения для четырёх существующих `kind` и ссылки на
публичный справочник. При проверке перехода обнаружен неверный относительный
путь импорта Markdown в справочник; его исправление входит в срез, чтобы
ссылки открывали реальные материалы. Срез не меняет API, DTO, Go, данные, научную проверку,
квоты или работу очереди. Формулировки в web являются подсказкой; каталог
доступных типов по-прежнему определяется ответом `/api/calculations/kinds`.

## Требования и приёмка

| ID | Требование | Given / When / Then | Доказательство |
| --- | --- | --- | --- |
| ACCOUNT-GUIDE-001 | Показать контекст каждого типа | Given API предлагает один из четырёх типов, When пользователь выбирает его, Then видит описание, источник данных, ограничение и ссылку на соответствующий документ | Playwright с API-фикстурами |
| ACCOUNT-GUIDE-002 | Явно отделить демонстрацию | Given выбран `erosion`, When форма готова к запуску, Then рядом со сценарием видна текстовая метка «Демонстрационный сценарий» и предупреждение о неприменимости как годового прогноза | Playwright |
| ACCOUNT-GUIDE-003 | Пояснить квоту без ложной позиции | Given пользователь на обзоре или в форме, When смотрит условия запуска, Then видит лимит пяти `queued/running` jobs и способ освободить слот, но не выдуманную позицию в очереди | Playwright, ручная проверка текста |
| ACCOUNT-GUIDE-004 | Не отправлять недоступный тип | Given API вернул пустой или неполный каталог, When форма загружается, Then запуск пустого типа недоступен, а при смене каталога текущий выбор приводится к предложенному типу | Playwright / проверка кода |

## Контракты и модель данных

`CalculationKindDto` и `CalculationKind` не меняются. Тексты назначения
берутся из API; локальный `scenarioGuidance` содержит только справочный
источник входов, ограничения и адреса существующих документов для известных
типов. По новым типам обязательна отдельная проверка фактических данных до
добавления записи. Никаких числовых метрик или формул в клиенте нет.

Показаны loading, ошибка, пустой каталог, доступный сценарий и ошибка запуска.
Подсказки используют semantic tokens, текстовые метки и `aria-live`; справка
открывается в новой вкладке с явным доступным предупреждением, чтобы введённые
параметры в модальном окне не терялись. На 360 px блоки переходят в одну колонку.
Ручная приёмка обеих тем, 200% zoom и screen reader остаётся открытой.

## Риски и альтернативы

Тексты источников могут устареть после изменения worker/команд. Поэтому
справочные формулировки привязаны к четырём известным типам и должны
сверяться при изменении каждого из них. Не выводим «осталось N слотов» из
последних 100 jobs: список неполон и мог бы обмануть пользователя. Полная
модель доступности сценариев в API здесь не вводится.
