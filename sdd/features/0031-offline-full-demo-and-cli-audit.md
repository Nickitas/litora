# 0031 — Офлайн-конвейер `all` и аудит паритета CLI/Web

- Статус: реализован локально, сквозная приёмка ожидается.
- Владелец решения: Litora; дата: 11.10.2026; исходный SHA: `c70e5c3`.
- Область: Go CLI, contracts, API/worker, web, документация.
- Архитектура остаётся в рамках [0028](0028-full-cli-web-parity.md): новых сервисов и прав нет; отдельный ADR не требуется.

## Проблема и границы

Веб-каталог не содержал составной команды `lito all`. Сверка всех `--help`
выявила также отдельные отсутствующие команды и частичные параметры; итоговая
[матрица](../cli-web-flag-matrix.md) отделяет их от реализованного.

Этот выпуск добавляет `all_demo`: закреплённые открытые файлы Сочи,
проверка контура, размерность, CERC, баланс наносов, SVG/JSON и управляемые
экспорты CSV/GIF. Существующий `erosion` получает тот же безопасный экспорт GIF.
Это не моделирование дна, калибровка, собственные входы или
воспроизведение архивных фигур полного Чёрного моря.

## Требования и приёмка

| ID | Требование | Доказательство |

## Контракт и совместимость

`kind=all_demo`, `input` основан на `ErosionDemoOptionsDto`: `steps` 1–24,
параметры CERC, `outputCsv`, `csvFormat`, `outputGif`, `gifFps` 1–30,
`gifSkip` 1–24; дополнительно `modelMaxPoints` 0 либо 2–10000,
`noModelSimplify` только при нулевом `modelMaxPoints`. Defaults есть в
`packages/contracts`; API проверяет каждое поле в runtime. Worker формирует
фиксированные относительные имена `all-metrics.csv` и `all-animation.gif`.
CLI получил `all --offline`; он не допускает удалённый URL или `--refresh` в
этом режиме. Входная схема jobs повышена до v4; worker продолжает принимать
v1–v3. Публичный endpoint, БД и роли не меняются, миграции не нужны.
`erosion` использует те же ограничения GIF, кроме `gifSkip` 1–48, и
фиксированное имя `erosion-animation.gif`.

Веб-форма показывает provenance/ограничения, параметры, загрузку и ошибки по
имеющемуся шаблону. Результаты идут через приватное хранилище и owner-filter.
Встроенные `--output`/`--manifest` задаёт worker. Для `all` manifest v2 пока
не содержит единой научной ревизии метода; внутри используются существующие
методы Go. Статус demo нельзя интерпретировать как научную аттестацию.

## Риски, альтернативы и выпуск

Нельзя превращать `all` в произвольный конвейер с URL/путями от клиента:
это обошло бы проверку владельца, могло бы дать SSRF и смешать источники.
Для собственных файлов нужен отдельный контракт ролей и паспортов.
GIF ограничен 24 состояниями; до production нужен ресурсный замер пика памяти,
временного диска и размера файлов, проверка лицензий и сроков хранения.
Worker с поддержкой v4/`--offline` выкатывается до API, создающего v4 jobs;
rollback API не удаляет уже созданные задания. Для отката самого worker
сначала дождаться завершения/отмены v4 jobs.

## Проверки

11.10.2026: `pnpm verify` прошёл; lint выдал прежнее предупреждение
`react-hooks/incompatible-library` для `useReactTable`. `go vet ./...`
прошёл. Браузерный Playwright: 36 тестов прошли, один `@live` пропущен.
Локальный CLI smoke `all --offline` с CSV/GIF создал manifest v2, SVG,
JSON и оба экспорта; запуск с 24 состояниями и GIF дал 32 файла, около
12 МБ на диске. Это не замер пика RAM или диска на целевом worker.
`pnpm test:integration` не выполнялся: нужна отдельная тестовая PostgreSQL/S3;
сквозная приёмка и сравнение архивных SVG остаются открытыми.
