- Дата: 21.10.2026; ветка `development`, исходный SHA `a98097e`.

- Область: подготовка небольших реальных входов, Go, протоколы и документация.

## Границы и задача

Подготовить по одному исходному сегменту для 24 районов: сначала восемь районов
первой очереди, затем шестнадцать второй. Назначение этого среза — исследование
геометрии картографического берега и масштабной зависимости box-counting.
Независимый контроль положения, RMSE, ряды наблюдений и годовой прогноз относятся
к последующим шагам; отсутствие контроля отмечается явно, точность не выдумывается.

Источник — существующий C1, OpenStreetMap `natural=coastline`. Для ограниченных
read-only выгрузок используется публичный Overpass; это разовая подготовка
данных разработчиком, не новая внешняя интеграция web/API. Новые технологии,
учётные данные и платные сервисы не требуются. Данные распространяются отдельно
от лицензии кода под ODbL с атрибуцией и ссылкой на условия OSM.

## Реализация и воспроизведение

Исходные данные: `packages/generated-data/research/`. Это 24 GeoJSON,
24 паспорта, 25 компактных снимков источника, реестр и описание лицензии.
Сохранены все 24 ID и очереди 8/16; поисковые точки и checksum сверяются
с `sdd/evidence/0063-source-catalogue-probes.json`. Время срезов OSM:
21.10.2026, 10:39:21–11:02:36 UTC. Время правки way не подменяет дату съёмки.

Преобразования и выбор выполняет Go `PrepareResearchSegment`: каждый путь
обрезается существующим `SelectRegion / clip-1`, длинные линии делятся на
части до 500 точек с общей граничной точкой. Отбрасываются самопересечения,
повторы, неподходящие координаты, менее 8 точек/200 м, невычислимая оценка и
необходимость нормализации. Выбирается самый длинный принятый основной фрагмент.
Если основных кандидатов нет, проверяются их непрерывные половины и подчасти
до 8 точек; координаты не исправляются. Новый метод подготовки имеет идентичность
`research-coastline-preparation / source-1`. Реализации прежних научных методов
не менялись.

Для Тендровской косы использован подучасток: оба широких фрагмента проходили
строгую геометрию, но `dimension` предлагал перестановку точек. Выбранные номера
координат в обрезанном сегменте записаны в `startPoint`/`endPoint`, уровень деления
— в `subdivisionLevel`. Перестановка не применялась.

Для Каламитского залива окно расширено с 0,16° × 0,12° до 0,24° × 0,12° вокруг
той же исходной точки: первое окно оставляло 2–5 точек в каждом пути и исключало
подробный участок восточнее. Первоначальный непринятый снимок сохранён отдельно;
принятый указан в `source.snapshotFile`. Причина изменения ROI находится в
реестре и паспорте. Получение новых вершин или искусственное уплотнение не выполнялись.

Все 24 входа: 17–500 точек, 446–11 918 байт, принятие строгой Go-проверкой,
успешный реальный CLI `dimension`, неизменные координаты и порядок точек при
загрузке расчётом. 18 исключённых кандидатов отражены в паспортах. Всего срез
занимает около 1,09 МБ; самый большой закреплённый снимок — около 125 КБ.
Крупные SVG и полные HTTP-ответы остаются вне Git в
`/private/tmp/litora-research-0068/`.

Команда подготовки работает без сети по умолчанию. Результаты по умолчанию
пишутся в `apps/lito-cli/output/`; запись поставляемого среза требует явного
`--output`. Из корня репозитория:

```bash
cd apps/lito-cli
go build -o /private/tmp/litora-0068-lito ./cmd/lito
go run ./cmd/prepare-research-data \
  --output ../../packages/generated-data/research \
  --cli /private/tmp/litora-0068-lito \
  --cache /private/tmp/litora-research-0068/raw \
  --reports /private/tmp/litora-research-0068/calculations
```

`--fetch` разрешает только получение отсутствующих снимков. Уже закреплённый
источник с другим запросом не заменяется молча. Получение ограничено последовательными
публичными GET, 4 МиБ на ответ, таймаутом 45 с и тремя попытками с паузами при
временных 5xx/429. Неполный ответ/remark не сохраняется как пригодный источник.
При подготовке встречались 502 и таймауты; все принятые снимки получены полностью.
Проекция исключает персональные поля автора, сохраняя геометрию, ID узлов,
версии ways, время среза и SHA-256 полного ответа.

## Доказательства и ограничения

- Offline-повтор прошёл для всех 24 районов без `--fetch`: содержимое 48 файлов
  геометрии и паспортов осталось побайтно неизменным.
- `go test ./...`, `go vet ./...` пройдены, включая воспроизведение всех 24
  контуров из исходников, деление без упрощения/соединения, отказ исходного
  Каламитского окна, выбор подучастка вместо нормализации и отмену Context.
- `pnpm test:api`: 121 пройден, 9 DB-тестов пропущены без `TEST_DATABASE_URL`.
  Новый тест пропускает все 24 GeoJSON через настоящий валидатор API и проверяет
  `canonicalGeometrySha256`; `pnpm --filter litora-api typecheck` пройден.
- `pnpm test:reports` пройден. Расчётные SVG всех районов просмотрены через
  Chromium; обзорные снимки: `/private/tmp/litora-research-0068-queue-1.png`
  и `/private/tmp/litora-research-0068-queue-2.png`.
- `pnpm test:web`, `node scripts/check-cli-capabilities.mjs` и `git diff --check`
  пройдены. Новые локальные ссылки проверены, секретов и крупных артефактов нет.

`pnpm verify` **не пройден**: `check:workspace` по-прежнему останавливается на
ссылке в `sdd/features/0018-account-workspace-navigation.md` на удалённый
`todo/account-roadmap.md`. Несвязанная ссылка не исправлялась; перечисленные
проверки запускались отдельно. Это не объявление полного gate зелёным.

Независимый RMSE, датированные наблюдения и пригодность для прогноза не приняты.
Картографическая геометрия может включать сооружения и портовые границы. Цель
RMSE ≤10 м не объявляется достигнутой; ряды CoastSat/контроль остаются шагами
22–26. Успех расчёта, устойчивость по масштабам и высокий R² не заменяют эти проверки.

Интеграция PostgreSQL/S3, UI E2E и race в этом изменении повторно не запускались:
контракты, доступ, хранение, конкурентность и UI не менялись. Сквозной расчёт
входов проверен реальным CLI, совместимость малого набора — валидатором API.

## Совместимость и риски

Изменения шагов 05–06 уже находятся в рабочем дереве и сохраняются. На этом
шаге не меняются контракты HTTP, права, БД и UI каталога: подключение подготовленных
данных к `/lab/datasets` — следующий шаг 08. Крупные исходники и расчётные рисунки
остаются вне Git; в репозитории только ограниченные контуры и паспорта.
Проверки выполняются offline по закреплённым данным; обновление источника —
отдельное явное действие. Коммит и публикацию выполняет пользователь.
