# 0042 — интерактивная динамика береговой линии в кабинете

- Статус: implementing, 13.10.2026. Локальный сквозной срез реализован;
  интеграционная и научная приёмка на тестовой инфраструктуре открыта.
- Владелец решения: команда Litora.
- Исходный SHA: `0098c4e` (ветка `development`).
- Область: Go CLI, worker, API, contracts, api-client, web, приватные S3-артефакты.
- Архитектурное решение: [ADR-018](../decisions.md).

## Проблема и границы

До этого среза кабинет показывал готовые SVG и ссылки на файлы. Пользователь не мог
перейти к конкретному состоянию берега, увидеть, где изменился контур, и связать
участок карты с временным графиком и качеством входных данных.

Фактическая основа: `erosion`, `erosion_file`, `all_demo` и `all_file` сохраняют
`erosion/longshore-cerc.json`. В нём `snapshots[0]` — исходная линия,
`snapshots[i + 1]` — положение после `steps[i]`; каждый шаг содержит
`condition.time`, `duration_hours`, ячейки с `shoreline_change_m`, объёмы и
невязку баланса. Координаты снимков — `{lat, lon}` в градусах. При собственном
ряде до 10 000 состояний/200 точек полный JSON может быть большим. Текущий API
выдаёт временные ссылки на приватные артефакты, но не JSON для интерактивного
просмотра. Добавленный в этом срезе owner-scoped API читает ограниченные JSON;
браузерный `fetch` signed URL потребовал бы отдельной CORS-политики S3.

`map`/`map_file` дают один GeoJSON-контур и годятся для статического обзора, а
`dimension` — для графика масштабов. Батиметрические сценарии дают глубины и
сетки, но их нельзя выдавать за временную динамику берега. У демо CERC могут
отсутствовать календарные метки. Даже ряд с датами — **расчёт модели по
волновым условиям**, а не повторные измерения линии берега и не поток данных в
реальном времени. Анимация лишь быстро переключает сохранённые состояния.

Первый выпуск охватывает один завершённый CERC-расчёт. Сопоставление нескольких
запусков и слой наблюдавшихся контуров требуют отдельной проверки совместимости
источника, CRS, геометрии, времени, метода и неопределённости. Загрузка
спутниковых снимков и автоматическое выделение берега сюда не входят.

## Пользовательский сценарий

Маршрут `/account/shoreline` сейчас показывает последние **собственные** CERC
расчёты, включая незавершённые и старые результаты без индекса. Для них есть
отдельное сообщение о статусе или отсутствии интерактивной карты. В деталях
подходящего job есть переход «Открыть динамику берега». Выбор job показывает:

1. Паспорт: модель/демо, источник волнового ряда и батиметрии, период,
   `scenario_status`, ограничения, метод и ревизия, CRS и единицы.
2. Карту D3 с исходной и выбранной линиями, фиксированным географическим
   экстентом, легендой, масштабом, zoom/pan и выбором узла или ячейки.
3. Общую шкалу состояния: календарные годы, месяцы, недели и дни — **масштаб
   видимого окна**, а не усреднённые вымышленные контуры. Курсор привязывается
   только к существующим кадрам. Кнопки предыдущего/следующего кадра и
   воспроизведение работают также с клавиатуры; скорость влияет лишь на UI.
4. Синхронные графики: временной ряд уже рассчитанного Go смещения выбранной
   ячейки (м), высота волны `hs_m` (м), эродированный/отложенный объём шага
   (м³) и невязка баланса (м³). Название величины, знак, единица, время шага и
   источник видны в подписи/tooltip. Таблица значений — альтернатива графикам.

Карта показывает два контура разным цветом и типом штриха. Для выбранного
кадра указывается точное время его получения и номер шага. Интерполяция
геометрии между кадрами, оценка скорости м/год в web и пересчёт CERC в D3
запрещены. Любые итоговые или периодные научные метрики рассчитывает Go и
версионирует отдельно от кадра.

### Семантика времени

- Если `input_quality.wave_climate.has_complete_times=true`, кадр 0 имеет
  время начала первого состояния волн, кадр `i + 1` — конец соответствующего
  интервала `condition.time + duration_hours`. Все даты нормализуются к UTC;
  интерфейс явно показывает UTC и может форматировать его для пользователя.
- Переключатель год/месяц/неделя/день меняет диапазон шкалы и доступные кадры.
  Неделя начинается в понедельник. При выборе периода курсор переходит к
  последнему **имеющемуся** кадру внутри него. Если кадров нет, показывается
  «В этом периоде нет состояния» и границы ближайших доступных кадров; старый
  контур не подписывается новой датой. Пропуски между интервалами отмечаются.
- Если меток нет, календарные переключатели скрыты, доступна шкала
  «Исходная линия → шаг N» с длительностью шага. Не выводить условный год
  запуска job и не превращать часы моделирования в календарные даты.
- Состояния `queued/running/failed/cancelled` имеют отдельные объяснения;
  недостроенный результат не появляется как готовая карта.

## Контракты и данные

Go после успешного CERC записывает **визуализационный контракт v1** вместе с
обычными результатами до manifest. Индекс содержит `schemaVersion`,
`scenarioStatus`, ограничения, CRS `EPSG:4326`, единицы, источники, число
узлов и кадров, режим `calendar`/`steps` и для каждого кадра chunk ID,
фактическое время или `null`, длительность и метрики шага. Метод и ревизия остаются
метаданными job в API; разрывы видны из фактических меток. Chunk содержит
индекс кадра, координаты линии и смещение ячеек, уже вычисленные Go. Суммы по календарным
периодам, если потребуются, создаёт Go по отдельному версионированному правилу;
web не агрегирует научные величины.

Индекс и кадры лежат в приватном S3 как артефакты результата. Chunk ограничен
64 кадрами и 4 МиБ; индекс — 4 МиБ. Эти пределы требуют проверки
на реальном годовом ряду в тестовом окружении. Go проверяет соответствие числа кадров
`len(steps)+1`, порядка времён, конечных координат и индексов; worker сверяет
manifest/SHA-256 и бюджет выхода. API не читает весь научный JSON ради кадра.

Реализованные локально owner-scoped read-only endpoints:

- `GET /api/calculations/:id/visualization` — метаданные и индекс;
- `GET /api/calculations/:id/visualization/chunks/:chunkId` — один известный
  ограниченный JSON chunk через API после проверки владельца, статуса job,
  версии схемы и принадлежности chunk этому job.

API не принимает S3 path/URL от клиента, не создаёт расчёт в HTTP-запросе и
возвращает `Cache-Control: private, no-store`. Точный DTO фиксируется в
`packages/contracts`, валидируется на границе чтения артефакта, затем
используется `api-client` и web. Неизвестная версия или старый job без индекса
получает состояние «Интерактивный просмотр для этого результата недоступен»
и сохраняет доступ к исходному SVG/JSON; автоматического пересчёта нет.
Дополнительной БД-миграции в первом срезе нет: артефакты уже имеют реестр.

## Дизайн и производительность

D3 применяется только для картографической проекции, шкал, осей, геометрии
линий и навигации; React управляет состояниями запроса и выбора. Загружать
модули D3 вместе с маршрутом динамики, не с первым экраном кабинета.
Экстент и проекция должны оставаться фиксированными при перемещении курсора,
чтобы визуальное «смещение» не возникало от автоподгонки кадра. Карта не
подменяет геодезическое измерение: при необходимости расстояния/площадь
готовит Go в метрах с указанной системой координат.

Мини-карта или обзор всего Чёрного моря берётся из `map`/`map_file` только
после явной проверки CRS и пространственного охвата; в первом срезе допустим
чистый локальный фон координат без сторонних тайлов. Нет нового платного
сервиса, ключей, публичного bucket и второго UI-kit. Цвета и focus — из
semantic tokens дизайн-системы, пары линий различаются также штрихом и
подписью. Неподвижный скриншот без легенды не считается приёмкой.

## Риски и альтернативы

- Прямой `fetch` signed S3 URL потребовал бы CORS bucket и отдал бы весь файл;
  выбран ограниченный owner-scoped JSON через API. Если нагрузка API окажется
  высокой, отдельно измерить вариант временных URL для chunk с узким CORS.
- Парсинг полного `longshore-cerc.json` в браузере даёт большой пик памяти и
  зависимость от 15-минутной ссылки; оставлен как скачиваемый научный отчёт.
- SVG по выбранным кадрам покрывает только 2–128 состояний большого ряда и
  не позволяет честную ежедневную навигацию; остаётся статичным превью.
- Дневные/недельные графики могут выглядеть непрерывными при пропусках.
  Соединять линией только соседние временные состояния без разрыва; интервалы
  и отсутствие данных показывать явно. Годовая/месячная кнопка не обещает
  фактические наблюдения каждой даты.
- Кадры больших пользовательских рядов увеличат объём S3 и время CLI.
  Нужны измерение, лимиты, контроль бюджета worker и процедура отката.

## Текущий срез реализации

Go создаёт `erosion/visualization/index.json` и кадры по 64 состояния или до
4 МиБ. Индекс также ограничен 4 МиБ. В кадрах есть исходные/рассчитанные
координаты и смещение ячеек; индекс содержит высоту волны, объёмы шага и
невязку из результата Go. Worker включает файлы в manifest и S3, но не
дублирует их в `result_summary`. API читает ограниченный JSON после проверки
`user_id`, успешного статуса и принадлежности артефакта job. Web показывает
последние собственные CERC-jobs и принимает точный UUID из страницы результата.

На экране есть D3-карта с двумя линиями, pan/zoom, выбор узла, точечный график
высоты волны, пространственный профиль смещения, таблица чисел и календарные
периоды или шаги. График высоты волн намеренно состоит из отдельных точек:
разрыв между состояниями не выглядит непрерывной линией. Дневной/недельный
период без кадров не показывает прежний контур. Темы, узкий экран, клавиатурная
шкала и reduced motion покрыты реализацией и выборочным E2E; полный ручной
аудит доступности остаётся открытым.

Пока не реализованы временной график выбранной ячейки за весь ряд и
периодные научные агрегаты. Для большого ряда проверены синтетические
10 000 шагов/200 точек и ограничения файлов, но не реальная сквозная
производительность worker → S3 → API → браузер. Нельзя называть это
проверенным воспроизведением годового исследования.

## Проверки и выпуск

Локальный код не означает развёртывание или научную аттестацию. D3 добавлен
как зависимость только lazy-маршрута. Старые jobs без индекса сохраняют SVG и
полный JSON. Откат UI/API не удаляет научный JSON; новые chunks остаются
приватными артефактами до согласованной политики хранения. Команды и результаты
проверок фиксируются в рабочем отчёте после общего gate.
