## Проблема и границы

Полная страница сейчас показывает статус, файлы и общий JSON, но вход,
происхождение данных, результат и версии трудно прочитать по отдельности.
Сведения уже возвращаются существующим owner-scoped `GET /api/calculations/:id`;
новый endpoint, научные вычисления и изменение схемы не нужны. Страница не
утверждает научную валидацию источника или точную воспроизводимость запуска.

## Требования и приёмка

| ID | Требование | Given / When / Then | Доказательство |
| --- | --- | --- | --- |
| PASSPORT-001 | Читаемый паспорт | Given завершённый job, When открыта полная страница, Then отдельно видны статус, даты, вход, метрики, provenance, версии и файлы с полным SHA-256 | E2E |
| PASSPORT-002 | Честная неполнота | Given активный или старый job без части полей, When страница открыта, Then отсутствующие данные не подменяются вымышленными, а демонстрационный сценарий помечен до завершения | E2E |
| PASSPORT-003 | Изоляция переходов | Given открыта страница A, When пользователь переходит на B до окончания запроса, Then UI не показывает данные A как данные B и старый ответ не перезаписывает B | E2E |
| PASSPORT-004 | Доступность | Given узкий экран и клавиатура, When пользователь читает паспорт, Then длинные UUID/хеши не ломают ширину, разделы имеют заголовки, ссылки и действия доступны с клавиатуры | E2E и ручная проверка |

## Контракты и модель данных

Используются существующие `CalculationJobDto` и `CalculationArtifactDto` без
изменений. Worker записывает `resultSummary.provenance` для успешных запусков:
список входных файлов с размером и SHA-256; у пользовательского набора также
заявленные источник, версия, лицензия, CRS и единицы; у демо — заявленные
источники из манифеста. Это сведения о происхождении, не внешняя проверка
достоверности. `resultSummary.metrics` содержит прочитанные небольшие JSON-файлы,
а не типизированный научный результат; показываем их без вывода новых метрик
и единиц.

Signed URL остаётся только в ссылках на файлы и не выводится в JSON паспорта.
`commandLine` не отображается: он содержит технические пути worker. У старых
job отсутствующие поля явно помечаются. Успешный job может иметь иной формат
summary: полный исходный JSON остаётся доступным в раскрываемом блоке.

## Риски и альтернативы

- Типизированные карточки научных метрик потребуют отдельной версии schema и
  методической проверки; пока не выводим значения из произвольного JSON.
- Формат provenance может расширяться: известные поля показаны явно, весь
  исходный `resultSummary` доступен для проверки без интерпретации.
- Signed URL истекает через 15 минут. В этом срезе не внедряется обработка
  ошибок загрузки и обновление ссылки: это отдельный пункт этапа 1.
- Ключ запроса и cleanup эффекта исключают смешивание jobs при навигации.
