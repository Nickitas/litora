# 0032 — каталог малых наборов береговой линии в кабинете

- Статус: implementing, 10.10.2026.
- Владелец решения: команда Litora.
- Область: web UI, E2E и документация; без изменения API, contracts, S3 и научной логики.
- Связано с [планом кабинета](../../todo/account-roadmap.md) и
  [лимитом малых наборов](0017-small-dataset-quota.md).

## Проблема и границы

Свои GeoJSON-наборы сейчас видны только в форме нового расчёта. Пользователь не
может отдельно просмотреть их паспорта, найти нужный источник и понять, что уже
сохранено. API уже возвращает последние 100 собственных наборов; это текущая
квота, а не серверная пагинация или произвольный каталог.

Добавляем раздел `/account/datasets` со списком паспортов и созданием через
существующую форму. Не добавляем редактирование, удаление, скачивание исходного
GeoJSON, научную оценку пригодности или новые права. Создание нового набора не
изменяет байты и паспорт предыдущего.

## Контракты и модель данных

Используются существующие `GET/POST /api/datasets`, `DatasetDto` и
`CreateDatasetDto`. Отдельного endpoint для одного набора и выдачи S3-файла
сейчас нет. API проверяет владельца, квоту 100, структуру и размер входа;
научная проверка геометрии остаётся в Go при запуске. Поиск в UI работает
только по полученному полному списку в пределах текущей квоты.

## Риски и альтернативы

- `source`, `sourceRevision` и `license` — заявления пользователя, не
  независимая аттестация. UI явно это поясняет.
- При сбое обновления после успешного `POST` сохранение уже произошло. UI
  показывает возвращённый паспорт локально и не повторяет запись автоматически.
- Отдельная серверная пагинация/поиск потребуются при изменении квоты, но
  сейчас создали бы лишний контракт. Список до 100 достаточен для этого среза.
- Удаление/версии связаны с retention и зависимыми jobs; эти действия остаются
  закрытыми до отдельного решения.

## Дополнение: повторы и учебные контуры, 16.10.2026

Причина одинаковых карточек: форма нового расчёта создавала новый dataset для
одного и того же встроенного контура Сочи при каждом открытии. Исправление
работает в границах web и `packages/generated-data`, без изменения API, прав,
миграций и научной логики.

| ID | Требование | Приёмка |
| --- | --- | --- |
| DATA-CATALOG-006 | Не плодить стартовый набор | При наличии сохранённого примера Сочи с совпадающими паспортом и SHA-256 новый расчёт использует его UUID и не вызывает `POST /datasets`; при отсутствии создаёт один набор. |
| DATA-CATALOG-007 | Честно показывать старые повторы | Совпадающие паспорт и SHA-256 сворачиваются в одну карточку; отдельные UUID можно снова показать. Число записей и расход квоты остаются видимыми. Никакие записи/S3-объекты не удаляются. |
| DATA-CATALOG-008 | Дать выбор разных примеров | Каталог показывает Сочи, Геленджик и Анапу как разные проверяемые OSM LineString с атрибуцией, версией, числом точек и предупреждением об учебном назначении. Сохранение каждого происходит только по нажатию пользователя. |

Дублями считаются только записи с одинаковыми названием, источником, версией,
лицензией, CRS, единицами, числом точек, размером, SHA-256 и версией схемы.
Сходный контур с иным паспортом остаётся отдельной карточкой. Повторный
автоматический выбор Сочи проверяется на клиенте по списку последних 100
записей; одновременные вкладки всё ещё могут создать две записи. Для строгой
межвкладочной идемпотентности понадобится отдельное серверное решение.
Отдельное удаление записей возможно только после проверки зависимых jobs,
политики retention и безопасного удаления S3.

## Дополнение: очистка локальных повторов, 17.10.2026

Предыдущее требование DATA-CATALOG-007 о визуальном сворачивании повторов
заменено: каталог показывает каждую фактически сохранённую запись и общий
расход квоты, но не выводит счётчик/предупреждение о повторах. Удаление из
пользовательского API по-прежнему не предоставляется.

| ID | Требование | Приёмка |
| --- | --- | --- |
| DATA-CATALOG-009 | Безопасно очистить старые локальные повторы | Для точно указанного владельца, паспорта и количества записей локальный служебный сценарий сохраняет самый ранний набор, сверяет содержимое всех S3-объектов с SHA-256, проверяет отсутствие ссылок из расчётов на удаляемые UUID, создаёт резервную копию пяти повторов и удаляет только их записи и объекты. План подтверждается его SHA-256; при изменении данных операция прекращается. |
| DATA-CATALOG-010 | Чистый каталог | В каталоге нет баннера «Повторов» и скрывающего записи переключателя. Количество отражает реальные записи. Поиск, пустое состояние, мобильная ширина и обе темы остаются доступными. |

Сценарий `apps/lito-api/src/scripts/cleanup-local-datasets.ts` работает только
с локальными PostgreSQL и S3, отклоняет production и требует точные
`--owner`, `--name`, `--sha256`, `--count`; режим `--apply` требует hash
предварительного плана. Он не меняет схему, DTO, права или научную логику.
Перед удалением повторно блокируется строка владельца и проверяются исходный
план и связи с расчётами. Резервная копия в игнорируемом `.litora/backups/`
содержит паспорта и байты удаляемых GeoJSON. При сбое удаления S3 после
транзакции могут остаться сиротские объекты; их сверяют с манифестом, не
очищают широким префиксом. Миграция пользовательских или production-данных
не выполняется. Выбор самого раннего UUID сохраняет образец для будущих
расчётов; зависимые UUID никогда не удаляются.

Локальная приёмка 17.10.2026: предварительный план обнаружил шесть одинаковых
записей и ноль зависимых расчётов; пять копий удалены из PostgreSQL и MinIO,
самая ранняя запись и её S3-объект остались. Резервная копия содержит пять
GeoJSON, их SHA-256 повторно проверены. Целевые E2E каталога: 6/6. Это не
означает очистку других окружений и не заменяет интеграционную проверку
публичного API на отдельном тестовом окружении. `pnpm verify` прошёл; lint
оставил одно предупреждение React Compiler, сборка — предупреждение о размере
чанка. Ручная проверка экрана в обеих темах и с экранным диктором остаётся
открытой.
