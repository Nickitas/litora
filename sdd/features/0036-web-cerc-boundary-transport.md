# 0036 — Граничный перенос наносов в web-сценариях CERC

- Статус: реализовано локально; сквозная научная приёмка открыта.
- Владелец: Litora; дата: 11.10.2026; основа: ветка `development`.
- Область: contracts, API/worker, web, Swagger, документация. Математика Go не меняется.

## Проблема и границы

CLI принимает `--left-boundary-transport` и `--right-boundary-transport` для
`erosion` и `all`, но web всегда передавал ноль. Ненулевой измеренный баланс
нельзя было воспроизвести в кабинете. Добавляются два явных числовых поля для
`erosion`, `erosion_file`, `all_demo` и `all_file`, включая повтор и паспорт
расчёта. Знаки и единицы совпадают с Go: м³/с, положительный левый поток входит
в сегмент, положительный правый выходит.

Файлы внешних источников/стоков по ячейкам и сооружений не входят в этот проход:
их индексы должны быть сопоставлены с фактически моделируемым контуром, который
`all` может упрощать. Передача таких JSON без проверки могла бы дать формально
успешный, но неверно привязанный результат.

## Контракт и совместимость

`CercOptionsDto` дополнен `leftBoundaryTransport` и
`rightBoundaryTransport`. Runtime-валидация остаётся на API, а worker получает
только фиксированные флаги после повторной проверки job. Отсутствующие значения
старых jobs интерпретируются как ноль. Схема входа новых jobs — v7;
worker сохраняет чтение v1–v7. БД и роли научных файлов не меняются.

## Риски и альтернативы

Ненулевые граничные потоки требуют измерений или обоснования; технически
допустимое число не делает сценарий научно пригодным. Вместо свободной строки
CLI API принимает только конечные числа с ограниченным диапазоном. Вместо
скрытого нуля форма показывает оба значения и смысл знака. На релизе сначала
обновлять worker, затем API и web; при откате завершить или отменить jobs v7.
