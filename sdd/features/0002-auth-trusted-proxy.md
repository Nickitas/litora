# 0002 — доверенный proxy и лимит auth-запросов

- Статус: verified локально; staging-приёмка не выполнена.
- Владелец: владелец Litora; продолжение P1 auth из maintenance.
- Дата: 26.09.2026. Область: API, production Compose/Caddy, тесты.

## Проблема и границы

Существующий лимит PostgreSQL — 30 POST-запросов auth в минуту на IP,
общий для register/login/refresh/logout. Без trust proxy весь трафик nginx
попадал в один счётчик. Не вводим Redis, ORM или новый лимит по аккаунту.
Предел сохраняется; это fixed window (возможен burst на границе минут),
пользователи за NAT делят квоту. DDoS и ingress rate limit остаются отдельной задачей.

## Требования и проверки

| ID | Требование | Проверка |
| --- | --- | --- |
| AUTH-009 | По умолчанию proxy не доверяем | Поддельный X-Forwarded-For не меняет req.ip |
| AUTH-010 | Доверие только списку IP/CIDR | Некорректная конфигурация останавливает запуск; true/hops/*/CIDR /0 запрещены |
| AUTH-011 | Правильная цепочка IP | Доверенный hop учитывает ближайшего недоверенного клиента; левый forged IP игнорируется |
| AUTH-012 | Блокировка предсказуема | 31-й POST → 429 + Retry-After 1–60; два IP имеют разные квоты; смена окна сбрасывает счётчик |

## Реализация и совместимость

TRUSTED_PROXY_CIDRS пуст по умолчанию. Express обрабатывает цепочку справа налево
по списку доверенных адресов: [официальная документация](https://expressjs.com/en/guide/behind-proxies/).
Не читаем X-Forwarded-For вручную. Production: Caddy → API напрямую для /api/*;
web остаётся отдельным upstream. Только API и Caddy подключены к edge-сети,
upstream `api-edge` разрешается только в этой сети (не плавающий адрес default-сети).
доверие к статическому адресу Caddy /32, порты API наружу не публикуются.
Сеть по умолчанию 172.30.10.0/24, proxy 172.30.10.2; при конфликте оператор меняет
LITORA_EDGE_SUBNET и LITORA_PROXY_IP согласованно. Caddy принимает прямых клиентов,
CDN/LB не поддерживается без пересмотра доверенной цепочки и allowlist.

DTO и клиент не меняются; Swagger описывает 429. SQL-миграция не нужна:
существующая auth_rate_limits сохраняется, счётчик насыщается на 31.
IP-счётчики пока сохраняются без автоматической уборки; retention в P1 data policy.
Локальный nginx/Vite по умолчанию не доверенный: общая квота proxy допустима
для dev, production-пример использует прямой Caddy hop.

## Проверки и выпуск

Unit/HTTP-тесты доверия заголовкам и PostgreSQL-тест 429/разделения/сброса окна.
Staging smoke через настоящий Caddy и проверка сетевой недоступности API отдельно.
Откат Caddy/Compose согласован с API: старый API игнорирует адрес proxy и снова
объединяет пользователей в одну квоту. Не ослаблять trust до true ради обхода.

26.09.2026: `pnpm verify` с отдельной временной PostgreSQL БД прошёл, 8 тестов API
без пропусков. Проверены AUTH-009–012, включая HTTP 429/Retry-After, разные IP,
подставленный левый адрес и сброс окна. `docker compose ... config --quiet` и
`caddy validate` закреплённого образа прошли. Рабочие БД/S3 не изменялись.
Настоящая цепочка Caddy/Docker, TLS, ingress и сетевые запреты на staging ещё
не проверялись. Предупреждение web о чанке 528,45 КБ остаётся отдельной задачей.
