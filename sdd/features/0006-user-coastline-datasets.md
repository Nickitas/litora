# 0006 — пользовательская береговая линия для dimension

- Статус: первый срез реализован локально, P1 продолжается. Дата: 29.09.2026.
- Владелец решения: команда Litora. Область: contracts, API, worker, S3, web, PostgreSQL.
- Связано с P1 «Пользовательские входные данные и новые расчёты».

## Границы

Первый безопасный вертикальный срез: один GeoJSON `LineString` береговой линии
Чёрного моря для `dimension_dataset`. `dimension`, `map`, `erosion` на поставляемых
данных сохраняют поведение. Не принимаем путь, URL, shell-аргументы и произвольный
формат. Пользовательский CERC, батиметрия, mesh, большие файлы и удаление данных
требуют отдельных контрактов и приёмки. Загрузка JSON через API годится только
для малых линий; прямой multipart/S3 upload будет отдельным решением.

## Требования

| ID | Наблюдаемое поведение | Проверка |
| --- | --- | --- |
| DATA-010 | Только авторизованный владелец создаёт и перечисляет свои наборы | POST/GET `/api/datasets`, чужой набор не выдаётся |
| DATA-011 | Вход ограничен и декларация координат однозначна | Только `LineString`, `EPSG:4326`, `degrees`, `[longitude,latitude]`, 2–500 точек, JSON ≤ 65536 байт; остальные значения → 400/413 |
| DATA-012 | Происхождение фиксируется до расчёта | Название, источник, лицензия, SHA-256, размер, CRS и единицы хранятся в БД; байты — приватный S3 object |
| CALC-010 | Выбор пользовательского набора запускает Go dimension | job содержит только `datasetId`; API сверяет владельца, worker скачивает по серверному ключу, сверяет размер/SHA-256 и передаёт локальный путь CLI |
| CALC-011 | Неуспешная научная проверка не скрывается | Go валидирует геометрию/границы; ошибка → failed с журналом, не `succeeded` |
| CALC-012 | Worker остаётся ограниченным | Один job на worker, timeout 300 s, лимит 256 файлов/100 MiB перед публикацией; Compose CPU/memory limits сохраняются |
| UI-010 | В кабинете можно загрузить, выбрать и запустить набор | Файл, источник/лицензия, ошибки/loading/empty, список своих наборов и результат job; keyboard/узкий экран |
| UI-011 | Без своего файла доступен явный стартовый GeoJSON | Пример Сочи имеет фиксированный источник и лицензию; создаётся приватный dataset только при выборе примера или первом запуске `dimension_dataset` без выбранного набора, повторный запуск на странице использует тот же UUID |

## Контракт и модель

`CreateDatasetDto`: `name`, `source`, `license`, `crs`, `coordinateUnit`,
`geometry` (GeoJSON LineString). Клиент не передаёт S3 key. `DatasetDto` возвращает
UUID, метаданные, checksum, размер, дату, без подписанного URL. Новый
`CalculationKind=dimension_dataset`, `input={datasetId: UUID}`. В jobs отдельный
`dataset_id` FK к неизменяемой записи; `input` для совместимости содержит ID.
Миграция добавляет таблицу datasets и индекс owner/date, существующие записи jobs
не трогает. Удаления/изменения datasets пока нет, поэтому job сохраняет
воспроизводимую ссылку. `resultSummary.provenance` содержит паспорт и digest;
`coreVersion` — digest бинарника. Ссылка на S3 остаётся приватной.

Метаданные `source`/`license` — заявление пользователя, не редакционная проверка.
API проверяет форму, лимит и декларацию CRS/единиц; научную пригодность
координат и геометрии определяет только Go. Успешная загрузка не означает
научной валидности. Размер HTTP body дополнительно ограничен Nest/Express. Лимит
100 MiB результата проверяется после завершения CLI, перед публикацией; он не
ограничивает рост временных файлов во время расчёта. Для production нужны
измерение пикового потребления диска и квота временного каталога.

## Риски, альтернативы и откат

S3 и PostgreSQL не имеют общей транзакции; при сбое INSERT после upload API
пытается удалить объект, а остаточный orphan требует будущей уборки. Не
показывать пути/ключи в публичном DTO. Не запускать CLI из controller.
Альтернатива — presigned multipart/upload и отдельная очередь валидации — нужна
для больших файлов, но добавляет состояние и не требуется для 64 KiB.
Откат: остановить создание новых datasets/нового kind, оставить миграцию и
старые записи/объекты до согласованной политики удаления; старые три сценария
продолжают работать.
