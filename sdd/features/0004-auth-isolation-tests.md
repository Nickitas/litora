# 0004 — регрессионные тесты сессий и изоляции расчётов

- Статус: verified locally; CI/staging pending. Дата: 26.09.2026.
- Область: API tests; P1 auth и P2 maintenance/testing.

## Границы

Проверяем существующее поведение, не расширяем права admin и не меняем DTO.
Реальные AuthService/Guard/Controllers/Repository и PostgreSQL. Только выдача
signed URL заменена наблюдаемым mock: тест не создаёт объекты и не обращается к S3.
Нет нового фреймворка, новых миграций и отправки писем.

## Окружение и изоляция

Только TEST_DATABASE_URL с именем БД `litora_test_*`; без переменной suite явно
пропускается. Каждый сценарий создаёт уникальных пользователей, cleanup удаляет
только их UUID и собственный auth-rate key, без TRUNCATE и глобального сброса.
CI уже поднимает отдельный PostgreSQL. Нет ожидания истечения таймера: даты fixture
изменяются только в тестовой БД. Не подменяем методы сервиса или SQL-ответы.

`pnpm test:api:db` требует TEST_DATABASE_URL. `pnpm test:api` локально допускает
явный skip двух PostgreSQL suites; при CI=true отсутствие тестовой БД — ошибка.
Runner проверяет protocol/host/имя перед запуском тестов. Значение URL не выводится.

Это не полный E2E с браузером, Go worker и S3; их интеграционная приёмка остаётся
отдельной. Любой найденный дефект сначала воспроизводится тестом и фиксируется
в этой спецификации, а не скрывается ослабленным assertion.

## Результаты проверки

26.09.2026: `pnpm verify` с отдельной PostgreSQL БД прошёл: 15 API-тестов,
без ошибок и пропусков, а также проверки workspace, типов, lint, Go, web smoke,
сборки API/web и budget bundle. Отдельно подтверждено, что runner до запуска
тестов отклоняет отсутствие TEST_DATABASE_URL в CI/обязательном режиме и
имя рабочей БД. Существующее поведение прошло регрессию без изменения
production-логики, DTO и схемы БД.

Это локальные результаты, не подтверждение запуска GitHub Actions или staging,
полного браузерного E2E либо аудита безопасности.
