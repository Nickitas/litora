# 0057 — видимый расход квоты научных файлов

- Статус: локальная приёмка пройдена; staging-проверка пилота отдельно.
- Дата: 19.10.2026; ветка `development`, поверх текущего незакоммиченного diff.
- Область: contracts, API, api-client, форма лаборатории.

## Проблема и границы

API ограничивает владельца 20 записями и 2 ГиБ заявленного объёма, включая
незавершённые загрузки. До попытки резервирования пользователь не видит расход.
Показываем серверные счётчики в форме, где загружаются научные файлы. Правила
резервирования, сроки и удаление готовых файлов этим срезом не меняются.

## Требования и приёмка

| ID | Требование | Проверка |
| --- | --- | --- |
| QUOTA-01 | Авторизованный пользователь получает только свои count/bytes и действующие пределы. Pending, uploading и ready учитываются одинаково. | Запрос для двух пользователей и после резервирования. |
| QUOTA-02 | Форма показывает занятые записи и заявленный объём, обновляет данные после резервирования и удаления pending. Ошибка запроса квоты не подменяется нулём. | UI и интеграционный тест API. |
| QUOTA-03 | Достигнутый предел по-прежнему защищает API; ответ 409 и приватность не меняются. | DB-тест двадцатой записи и попытки следующего резервирования. |

## Контракт и совместимость

`GET /api/scientific-inputs/quota` возвращает `usedCount`, `limitCount`,
`usedBytes`, `limitBytes` как целые числа. Доступ требует действующий access token.
Объём является суммой **заявленных при резервировании** размеров, а не измерением
S3. Ответ не содержит чужих записей. Маршрут аддитивный; миграция не нужна.

## Риски и откат

Одновременное резервирование в другой вкладке может сделать показанный счётчик
устаревшим; серверная транзакционная проверка остаётся решающей. При ошибке
обновления UI сообщает, что расход недоступен. Откат — удалить маршрут и
индикатор; данные и схема БД не меняются.
