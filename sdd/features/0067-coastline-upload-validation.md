## Проблема и границы

Малый GeoJSON сохраняется после проверки формы, а замечания Go появляются только
в расчёте. Отдельный сценарий `source_file` инспектирует метаданные большого
контура и не является полной проверкой геометрии. Переносим запуск проверки
в загрузку, сохраняем паспорт и показываем очередь/результат рядом с набором.

Проверяются малые наборы и загружаемые научные файлы роли `coastline_geojson`.
Наблюдения ряда береговой линии и другие роли сохраняют собственные форматы.
Геометрическая проверка не аттестует источник, точность съёмки и пригодность
для прогноза. Исходные координаты не исправляются и не переупорядочиваются.

## Контракты и модель

Общее представление проверки содержит UUID задания, статус очереди, версию
метода, время и ограниченный список замечаний из отчёта Go. Отсутствующая
проверка — самостоятельное состояние, не `succeeded`. Старые записи совместимы
и могут быть проверены отдельно. Результат привязан к неизменяемому источнику
и его checksum; jobs и чтение отчётов ограничены владельцем.

Для малого набора используется `dataset_validation` с `datasetId`; для большого
контура — `coastline_validation` с `coastlineInputId`. Оба вызывают один новый
Go-метод проверки. `source_file` сохраняет прежний API и снимок для совместимости
зависимых расчётов, но скрыт в обычной форме. HTTP-контроллер
не запускает CLI. Служебные виды проверки исключаются из обычного каталога
сценариев, но не из allowlist worker и чтения исторических заданий.

Загрузка и постановка задания — разные операции: если очередь временно не приняла
задание, API возвращает сохранённую запись с явным отсутствием проверки и
возможностью повтора, не предлагает повторно загружать файл и не теряет паспорт.

## Научные и ресурсные границы

Правила геометрии реализуются в Go с повторным использованием существующих
проверок координат, области Чёрного моря, совпадений и пересечения сегментов.
Предлагаемые нормализатором исправления не применяются автоматически. Новый
метод имеет отдельную идентичность/ревизию в `internal/domain/methods`.

Для составного GeoJSON проверяются все линии/кольца по отдельности; разрывы и
острова не соединяются. Ограничиваются объём отчёта и ресурсы проверки;
достижение лимита сообщается как непройденная проверка, а не принятие остатка
без анализа. Обработка поддерживает Context. Больше деталей фиксируется вместе
с реализацией и измерением на полном поставляемом контуре.

## Риски и альтернативы

- Научные формулы в TS запрещены: общий валидатор contracts проверяет только
  структуру и лимиты; результат геометрического анализа приходит из Go.
- Нельзя подменять пользовательский файл исправленным контуром без явного
  выбора. Проверка возвращает замечания и сохраняет исходный checksum.
- Повторный клик не должен создавать несколько активных проверок одного входа;
  постановка сериализуется в БД с существующим ограничением очереди пользователя.
- Полный общий gate отдельно блокирует прежняя ссылка 0018 на удалённый
  `todo/account-roadmap.md`; восстановление удалённого документа сюда не входит.

## Реализованные ограничения и совместимость

Поддерживаются двумерные LineString, MultiLineString, Polygon, MultiPolygon
и оболочки Feature/FeatureCollection. Кольца имеют минимум четыре координаты
и точно замыкаются. Явный CRS допускается только EPSG:4326 или его URN из
закреплённого MarineRegions. Пределы: 16 МиБ, 20 000 координат на путь,
50 000 суммарно и 200 замечаний. Превышение лимитов даёт отказ; предел точек
или отчёта дополнительно отмечается `truncated`, а остаток не считается проверенным.

Совпадения определяются существующим округлением до шести знаков координат;
пересечения несмежных сегментов — существующей функцией ядра. Между отдельными
путями пересечения/вложенность не проверяются. Это проверка линий, не полная
топологическая аттестация полигона. Исходник не нормализуется.

Полный закреплённый снимок проверен без упрощения: 92 пути, 11 565 координат,
0 замечаний, принят. Запуск `go run` вместе со сборкой занял 1,83 с локально;
это не нагрузочная аттестация worker. Отчёт и manifest:
`/private/tmp/litora-coast-check-measure-ytWExf`. Новый метод:
`coastline-validation / geometry-1`.

Научный контур использует существующий heavy-профиль. При его отключении
загрузка сохраняется с `not_requested` и сообщением о недоступности проверки.
Малый набор проверяется стандартным worker. Форма блокирует расчёт до принятия
входа; API расчётов сохраняет совместимость старых клиентов. Проверка в форме
не заменяет обязательную валидацию входных данных Go при каждом расчёте.

Версия входов jobs повышена до 15, прежние 1–14 поддерживаются. Миграция
`018_coastline_validation_jobs.sql` добавляет только два частичных индекса
по владельцу/источнику/дате. Повтор активного задания идемпотентен благодаря
существующей блокировке пользователя. Завершённую проверку можно повторить.
Геометрический отказ также проходит проверку manifest, размеров и checksum
до публикации; метод и ревизия сохраняются и у отказа.

Индексы можно оставить; исходные файлы и исторические задания сохраняются.
