## Проблема и границы

В кабинете и общих страницах смешаны shadcn-кнопки и диалог запуска с
браузерными `select`, полями, чекбоксами и нативными диалогами. Это даёт разные
размеры, focus-состояния и поведение. Приводим интерактивные элементы web к
существующему shadcn `radix-nova` и семантическим токенам темы. Структурные
HTML-элементы (`main`, `section`, `h1`, `dl`, `form`) и настоящие ссылки остаются:
заменять их UI-компонентами означало бы потерять семантику. `type=file`
продолжает использовать системный механизм браузера внутри shadcn `Input`.
Для дат истории используется локальный shadcn-совместимый `Calendar` в
`Popover`, без внешнего календарного сервиса.

## Контракты и модель данных

API/DTO/БД не меняются. Компоненты находятся в
`apps/lito-web/src/shared/shadcn/components/ui`; используется установленный
`radix-ui`, Tailwind 4 и текущие theme tokens. Контролируемые `Select`
передают строковое значение через `onValueChange`, а не DOM `change`.
Пустое значение Radix Select представляется отдельным sentinel только внутри
UI, без передачи его в API/URL. Метки связываются с trigger/input через `id`.
Тема использует одну shadcn-кнопку с текущей иконкой и циклической сменой
режима. Сохраняется прежний ключ `litora-theme`. Для дат используется
`react-day-picker` (зависимость shadcn Calendar) с русской локалью; выбранная
локальная календарная дата преобразуется в YYYY-MM-DD без UTC-сдвига.
Компоненты `Calendar` и `Popover` добавлены в существующий слой после просмотра
шаблонов shadcn CLI; preset не менялся. Ранее добавленные совместимые
примитивы следует сопоставить с актуальными шаблонами без перезаписи
кастомизации.

## Риски и альтернативы

- Native `select` проще, но отличается между браузерами и не соответствует
  текущему UI. Radix Select требует изменения E2E с `.selectOption` на
  взаимодействие с combobox/options.
- Дублировать Radix-логику в каждом экране нельзя; primitives общие.
- Подменять `button` произвольным `div` нельзя. Кнопки shadcn продолжают
  выводить семантический HTML `button`.
- Примитив Dialog должен управлять scroll lock, focus trap, Escape и возвратом
  focus. Не вводим второй UI-kit или новую библиотеку.

## Проверки и выпуск

Миграция UI совместима с API и не требует migration/rollback данных. При
проблеме можно вернуть только React-компоненты. Фактические проверки и
ограничения: `pnpm verify` — успешно, включая лимит статического JS-графа
entry; `pnpm --filter litora-web test:e2e` — 26
пройдено, один live-сценарий пропущен, поскольку требует отдельного окружения;
`git diff --check` — без ошибок. Автоматические E2E покрывают 360 px, темы,
ловушку и возврат фокуса, а также reflow при CSS-области 640×400 — эквиваленте
200% масштаба для окна 1280×800. Снимки модального запуска в обеих темах и
сравнения в тёмной теме просмотрены. Настоящий browser zoom и screen reader
ещё требуют ручной приёмки.
