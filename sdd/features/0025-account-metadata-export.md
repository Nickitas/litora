# 0025 — скачиваемый паспорт метаданных расчёта

- Статус: implementing, 04.10.2026.
- Владелец решения: команда Litora.
- Область: contracts, web, E2E и документация; без нового HTTP endpoint,
  миграции, прав, S3-доступа и научных вычислений.
- Связано с [планом кабинета](../../todo/account-roadmap.md) и
  [полным паспортом](0022-account-calculation-passport.md).

## Проблема и границы

Полный паспорт расчёта виден на странице, но его нельзя сохранить как небольшой
машинно-читаемый документ. Прямое сохранение `CalculationJobDto` раскрыло бы
временные `downloadUrl`, а также техническую `commandLine` с путями worker.
Нужна отдельная версия формата и явный список полей. Экспорт строится локально
из уже полученных через owner-scoped API деталей job; он не подписывает файлы,
не включает их байты, не даёт доступа другим пользователям и не обещает точное
воспроизведение исторического ядра.

## Контракты и модель данных

`CalculationMetadataExportV1` — контракт скачиваемого файла в
`packages/contracts`, не ответ нового endpoint. Верхний уровень: `format`,
`schemaVersion`, `calculation`, `provenance`, `artifacts`. В `calculation` только
UUID, kind/status, известные поля input (`steps`/`datasetId`), версии, метод и
время. В `provenance` — известные сведения о наборе, заявленные источники и
размеры/SHA-256 входных файлов без локальных путей. В `artifacts` — ID,
категория, имя, MIME, размер и SHA-256 без URL и object key. Произвольный
`resultSummary.metrics`, `commandLine`, ошибка worker, access/refresh token и
байты файлов не экспортируются. Если формат входа неизвестен, его проекция
равна `null`, а не пустому объекту, похожему на достоверный вход.

Пользовательские поля источника и лицензии остаются заявлениями владельца, не
подтверждением достоверности. Перед передачей файла третьему лицу пользователь
должен проверить эти сведения. Схема v1 не является CLI manifest и не
доказывает, что файлы всё ещё доступны в S3.

## Риски и альтернативы

- Экспорт всего DTO проще, но выдаёт signed URL; явная проекция ограничивает
  данные и делает изменение формата осознанным.
- Серверный endpoint мог бы формировать экспорт, но повторил бы уже выданные
  owner-scoped метаданные и расширил бы HTTP-поверхность без необходимости.
- Поля provenance старых jobs неполны; не подставляем придуманные значения и
  не включаем абсолютные пути входных файлов.
- Заявленные пользователем строки источника/лицензии входят в паспорт как есть:
  приложение не добавляет туда свои токены, но пользователь должен проверить
  собственный текст перед передачей экспорта.
- JSON сам по себе не подписан криптографически; SHA-256 в нём — сведения из
  сохранённого паспорта, а не новая независимая проверка файла.
