Этот протокол относится к одноразовому локальному стенду, а не к digest
релизного образа. PostgreSQL `postgres:17-alpine` (image ID
`sha256:742f40ea20b9ff2ff31db5458d127452988a2164df9e17441e191f3b72252193`)
и `litora-minio-dev:2025-10-15-9e49d5e` (image ID
`sha256:2469201a35c2fd61bb90e557c7e8172c376ce6b127fb2df83e4af2a5e7ba7e08`)
запущены с данными только в tmpfs и портами на `127.0.0.1`.
API и standard worker запущены из дерева исходного прогона через
`tsx`; Go CLI собран `go1.25.4 darwin/arm64`. Node.js `v22.12.0`, pnpm
`10.15.0`. Heavy worker и Gmsh в исходном прогоне не участвовали.

## Команды и ограничения результата

- `pnpm verify` с `TEST_DATABASE_URL=.../litora_test_acceptance` — пройден
  после всех изменений этого локального среза. Для кандидата выпуска повторить
  на его точном SHA.
- `pnpm test:api:db` — 106/106 без пропусков. `pnpm --filter litora-api
  test:migrations` — 17 миграций на чистой временной БД, повтор без изменений.
- `pnpm --filter litora-web typecheck`, `lint`, `build` — успешно; lint оставил
  одно существующее предупреждение TanStack Table, Vite — предупреждение о
  крупных чанках.
- Общий mock Playwright-прогон после исправления устаревшего текста:
  69 прошли, 1 live-сценарий пропущен по настройке. Live-сценарий отдельно
  прошёл 1/1 с настоящим API/worker/S3 и одноразовым приглашением.
- Прямой локальный `node dist/main.js` с Node.js 22.12 завершился на TS-export
  пакета contracts; API через `tsx` работал. Готовый runtime-образ с другой
  версией Node.js здесь не проверялся; это обязательная проверка [0049](0049-prebuilt-vps-delivery.md).
- 19.10.2026 дополнительный прогон использовал те же локальные image ID
  PostgreSQL и MinIO, новые tmpfs-контейнеры и тестовую БД, API, standard и
  heavy worker из HEAD `efc34f6` с diff теста. Вход `black-sea.json` имеет
  указанный выше SHA-256. Прогон завершился успешно дважды, второй раз с
  проверкой причины 409. Gmsh и seabed не запускались. Контейнеры с `--rm`
  остановлены и удалены после каждого прогона.
- На трёх следующих одноразовых стендах того же дня успешно повторены
  интеграционный сценарий с удалением всей зависимой цепочки и отдельный тест
  подмены S3. Для последнего использован малый dataset, созданный кодом теста;
  исходный SHA-256 сверен с паспортом до замены, размер сохранён, SHA изменён.
  Это локальная проверка поведения worker, не проверка внешнего S3 и IAM.
- Отдельный тест timeout/crash использовал исполняемый тестовый CLI, который
  только ожидает; научные расчёты им не подменялись. После `SIGKILL` worker
  тест вручную завершил оставшийся дочерний процесс и сдвинул
  `heartbeat_at` на 61 секунду назад только в одноразовой БД. Так проверена
  ветка восстановления без ожидания минуты. Новый job выполнен собранным Go
  CLI. Это не проверка естественного истечения 60 секунд, OOM или фактического
  перезапуска runtime-образа на staging.
- Проверка URL использовала отдельный MinIO bucket и двухсекундную подпись;
  обычный срок API в 900 секунд подтверждён параметром выданного URL. Полные
  900 секунд не выжидались. Браузерный тест модуля выполнялся на dev-сборке с
  mock API и искусственным 404, а не с двумя опубликованными web-образами.

## Открытые проверки до закрытого пилота

- На выделенном staging повторить этот путь для точных image digest, реального
  TLS и приватного bucket, включая обзор с реальным API после более 100 jobs.
- На staging проверить смену двух реальных web-релизов с сохранённой сессией,
  срок ссылки от настоящего S3, timeout и crash/restart на точных образах с
  естественным ожиданием stale heartbeat; отдельно проверить судьбу scratch.
  Для массового удаления ещё проверить реальный S3,
  частичный отказ и повтор; локальный DB-тест покрывает этот алгоритм с fake S3.
- Пройти клавиатуру, 360 px, 200% zoom и обе темы вручную на маршрутах пилота.
- Измерить ресурсы heavy отдельно и выполнить совместный restore PostgreSQL+S3
  на чистом стенде. Этот локальный протокол не подтверждает RPO/RTO или выпуск.

В тестовом окружении использовались только одноразовые приглашения и учётные
записи; коды, токены и подписанные URL в протокол не внесены. После проверки
тестовые процессы и контейнеры останавливаются; данные tmpfs уничтожаются
вместе с конкретными контейнерами.
