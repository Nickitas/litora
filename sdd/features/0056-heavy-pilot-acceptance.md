# 0056 — приёмка heavy-пути закрытого пилота

- Статус: частично проверено локально; ресурсные лимиты и научная приёмка открыты.
- Дата: 19.10.2026; HEAD `efc34f631b48c1cce63cac4f50a6140334fdca3e` плюс незакоммиченный diff.
- Владелец решения: команда Litora.
- Область: Go CLI, Gmsh, heavy worker, API, PostgreSQL, приватный S3.
- Решение владельца от 19.10.2026: heavy обязателен в ближайшем закрытом
  пилоте. Отсутствие готовых входов откладывает приёмку пилота, а не исключает
  heavy из его состава. Точный список открываемых пользователю heavy-kind
  будет закреплён отдельно.

## Проблема и границы

Каталог предлагает `mesh` и сценарии seabed только при включённом heavy-профиле.
Наличие команд и Gmsh не доказывает, что полный расчёт дна помещается в ресурсы
стенда или что исходные данные пригодны для научного вывода. Этот протокол
отделяет технический smoke малого входа от приёмки цепочки на лицензированных
научных данных. Права доступа, DTO и алгоритмы этим срезом не меняются.

## Требования и приёмка

| ID | Требование | Доказательство и текущий статус |
| --- | --- | --- |
| HEAVY-01 | Одинаковый вход и параметры дают одинаковую MSH в CLI и heavy worker; результат имеет manifest v2, SHA-256 и приватную выдачу. | Локально пройдено для малого OSM-сегмента Сочи; SHA-256 MSH совпал. |
| HEAVY-02 | Малая эталонная цепочка `mesh → seabed build → render/adapt → generate/compare/validate` проходит на входах с закреплёнными версиями, CRS, датумами, nodata, лицензиями и численными допусками. | Открыто: поставляемый паспорт `black-sea-bathymetry-source.metadata.json` описывает источник, но не производный набор точек; попытка `seabed build` с ним закономерно отвергнута из-за `point_count=0`. |
| HEAVY-03 | На выделенном стенде измерены wall time, peak RSS всего дерева процессов, CPU и пик scratch для каждого шага; лимиты выставлены по результатам. | Открыто. Локальный замер одного малого `mesh` не характеризует полный контур. |
| HEAVY-04 | Проверены отмена, timeout, crash/restart, выходной и временный лимиты, dry-run очистки scratch на том же heavy-стенде. | Открыто. Для standard есть отдельный [протокол 0055](0055-standard-pilot-acceptance.md). |

## Локальный технический прогон HEAVY-01

- Вход: `apps/lito-cli/data/examples/sochi-local-segment.geojson`, SHA-256
  `5fc2e8625fc57021fb760cccc63cb6ff20848edd70e159453f34402faa99129a`;
  OpenStreetMap way 59530506, выгрузка 17.08.2026, ODbL. Это стартовый
  сегмент, не полный контур Чёрного моря и не инженерная съёмка.
- Параметры: `cellSizes=2000`, `boundaryDetails=2000`,
  `generators=frontal-quad`, `maxCells=1000`, timeout Gmsh 1 минута.
  Go `1.25.4 darwin/arm64`, Gmsh `4.15.2-git`, Node `22.12.0`.
- Standalone CLI: `go build -trimpath`, затем `lito mesh` с `--manifest` и
  указанными параметрами. MSH содержит 15 четырёхугольных ячеек;
  SHA-256 `d438b6e929cf5717b13d9e8638181149e99e320e4f395c7ad86521be564b5bdb`.
  Повтор дал тот же SHA. Локальное `/usr/bin/time -l`: 0,30 с real,
  maximum resident set size 29 458 432 байта **для процесса CLI**; пик
  дочернего Gmsh отдельно не измерен. Каталог результата: 7 файлов, 28 КиБ
  выделенного места на APFS. Это не оценка peak scratch для полного задания.
- HTTP: `TEST_HEAVY_ENABLED=true TEST_MESH_ENABLED=true
  TEST_MESH_CLI_BINARY=/private/tmp/litora-heavy-acceptance-cli pnpm test:integration`
  на отдельной PostgreSQL 17 и локальном MinIO с tmpfs, портами только
  `127.0.0.1`. API, standard и heavy worker запущены из исходников через
  `tsx`, Go CLI собран локально. Job `succeeded`, профиль `heavy`, 0,454 с
  между `started_at` и `finished_at`, 8 опубликованных файлов. MSH имеет тот
  же SHA-256 и размер 2557 байт. Тест проверил SHA-256 скачанных MSH,
  отчёта и manifest v2, подпись 900 с, отказ для URL без подписи и 404
  для чужого UUID. Тест дополнительно запустил тот же CLI на том же файле и
  сравнил SHA-256 MSH с worker. Общий integration-прогон завершился успешно; его
  standard- и dependent-сценарии также прошли.
- Изолированные контейнеры остановлены с `--rm`; одноразовые БД и объекты
  были в tmpfs. Файл приглашений и журнал теста удалены из `/private/tmp`.
  Данные и подписи не включены в протокол.

Дополнительно standalone `mesh` на встроенном грубом `data/black-sea.json`
с ребром 200 км и детализацией 20 км создал 48 ячеек за 0,28 с. Вход
схематичен, разрешение предельно грубое, поэтому этот запуск не задаёт
лимиты production и не считается приёмкой полного контура.

## Следующий проверяемый шаг

Подготовить малую **реальную** производную батиметрию и её паспорт из
разрешённого источника: SHA-256, точное происхождение и лицензия, EPSG:4326,
вертикальный датум, nodata, число точек и совместимость с выбранным полигоном.
Закрепить независимую опорную модель для `validate` и численные допуски до
запуска. Затем выполнить HEAVY-02–04 на выделенном стенде с измерением
всего дерева процессов и scratch. До этого пилот с heavy не объявлять принятым
и не открывать непроверенные сценарии пилотной аудитории.

Проверки этого среза: `node --check scripts/integration-test.mjs`,
изолированный `pnpm test:integration` с двумя opt-in флагами,
`pnpm check:workspace`, `git diff HEAD --check`. Точный runtime-образ,
staging, реальные S3/IAM, backup/restore и браузер здесь не проверялись.
