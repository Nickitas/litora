# 0012 — паспорт источника малой береговой линии

- Статус: локальный срез A3; staging не подтверждён.
- Область: contracts, API, PostgreSQL, worker, кабинет и документация сайта.

## Граница

Этот срез относится только к малому пользовательскому GeoJSON `LineString`
для `dimension_dataset`. Поддерживаются WGS84/EPSG:4326, порядок
`[долгота, широта]` и угловые градусы. API отклоняет координаты вне
глобальных диапазонов долготы −180…180 и широты −90…90. Это синтаксическая
проверка CRS, не доказательство, что измерения действительно сделаны в WGS84
или относятся к Чёрному морю. Научную пригодность продолжает проверять Go.

Новое необязательное поле `sourceRevision` — заявленная пользователем версия,
дата снимка или ID выгрузки источника (до 120 символов). Оно сохраняется
в паспорте dataset, возвращается через API и копируется в provenance job.
Если версия не известна, `source_revision=NULL`; миграция 007 не заполняет
исторические наборы и не изменяет их GeoJSON или SHA-256. Файл примера Сочи
пока не имеет проверенного upstream version ID, поэтому поле у него также
пустое, хотя дата выгрузки указана в текстовом названии источника.

Значение поля не сверяется с исходным провайдером и не подтверждает лицензию.
Версия схемы dataset остаётся 1: форма геометрии не изменилась, а новое
метаполе является необязательным. Для волн, батиметрии и других больших
входов понадобятся отдельные контракты с датумами, единицами, nodata,
временем, проверкой лицензий и точной версией исходного набора.

## Приёмка

- API отвергает неверные глобальные координаты, пустую и слишком длинную
  ревизию, но принимает старый запрос без нового поля.
- PostgreSQL и API сохраняют переданную ревизию; старые строки остаются с
  `NULL`. Worker переносит её в provenance результата без домыслов.
- Сквозной тест проверяет значение в dataset DTO и в успешном job.
