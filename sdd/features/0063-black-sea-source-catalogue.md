## Проблема и границы

Для 24 районов описаны исследовательские задачи, но не было общей матрицы
источников с подтверждёнными продуктами, версиями, условиями и переходом к форматам
Litora. Общая ссылка на портал не подтверждала наличие сцен конкретного района.

В этом изменении проверяются первичные карточки источников и доступность метаданных
Sentinel-2 за 2016 и 2025 годы в каждой поисковой точке. Пользовательский каталог
живет в `packages/docs/content/black-sea-source-catalogue.md`; существующее
руководство по участкам ссылается на него. Методики и описание источников не
дублируются в SDD, инженерный протокол не включается в пакет сайта.

Это поиск источников и фиксация пробелов. Здесь не загружаются снимки/крупные
сетки, не создаются пользовательские datasets, не извлекаются наблюдения,
не добавляются адаптеры NetCDF/SAFE/Shapefile и автоматические внешние интеграции.
Страница `/lab/datasets` этим изменением не получает новые готовые наборы:
её композиция — шаг 03, подготовка и подключение наборов — шаги 07–09/25.

## Протокол проверки источников

Сохранены [результаты поиска](../evidence/0063-source-catalogue-probes.json).
У протокола версия 1, дата проверки и исходный SHA; это исследовательское
доказательство, не DTO публичного API и не научный набор наблюдений.

Для каждого ID выбрана поисковая точка EPSG:4326. Выполнены отдельные запросы
`GET https://catalogue.dataspace.copernicus.eu/odata/v1/Products`:

- коллекция `SENTINEL-2`, атрибут `productType=S2MSI1C`;
- `Intersects` с `POINT(longitude latitude)`;
- интервалы `[2016-01-01, 2017-01-01)` и `[2025-01-01, 2026-01-01)` UTC;
- `$top=1`, `$select=Id,Name,ContentDate`;
- 2016: сортировка времени по возрастанию, 2025: по убыванию;
- не более четырёх одновременных read-only запросов; без учётных данных.

Точный шаблон `$filter` и параметры есть в JSON. Наличие результата проверено
по HTTP 200, непустым ID/имени и попаданию времени в запрошенный год.
Для соседних районов одна сцена может повторяться; уникальность сцен между
районами не является критерием.

Не проверялись пиксели, облачность, реальный берег внутри сцены, полнота
промежуточных лет и научная точность. Поисковые точки не являются окончательными
ROI; их поля не заменяют геометрию принятого набора.

Дополнительно сверены первичные описания OSM Coastlines, MarineRegions,
Sentinel-2, USGS Landsat, GEBCO_2026, EMODnet DTM 2024 и Copernicus Marine W1.
Для W1 подтверждены почасовой dataset и соответствия переменных по PUM 4.1;
получение локального NetCDF и выполнение конвертации не заявляются проверенными.

## Обнаруженные пробелы

- Для всех 24 районов O1 ещё не подготовлен, независимый контроль R0 не подобран.
  Это отсутствие принятого комплекта, не утверждение, что съёмок нигде не существует.
- Для всех районов нужны точные ROI, локальные морские выборки и проверка nodata.
  Географический охват продукта не доказывает наличие валидной ячейки у каждого берега.
- Файл `apps/lito-cli/data/coastline/black-sea.geojson` существует: 299 701 байт,
  SHA-256 `116dcbc076ff0086e8bb3d72a34fc1df5353dc3c93c5cad91a99c336e039d246`,
  соответствует паспорту. Это исходная обзорная граница C0, не принятая локальная съёмка.
- Пути GEBCO raw/TID/regular и EMODnet control, указанные в
  `apps/lito-cli/data/black-sea-bathymetry-source.json`, в этой копии отсутствуют.
  Значение `download_status` старого паспорта не менялось и не считается текущим
  доказательством наличия данных. Файлы необходимо восстановить и сверить checksum.
- Страница текущего Marine Licence Agreement вернула HTTP 403. Официальные
  карточки продукта и Help Center доступны; название соглашения, бесплатный доступ
  и требование атрибуции подтверждены, полный текст редакции не проверен.
  Перед распространением W1/производных нужно получить актуальную редакцию.
- Для OSM подтверждена официальная ссылка на архив, сам большой ZIP не скачивался.
  Конкретная версия выгрузки, checksum и локальная точность ещё не определены.

## Контракты, риски и совместимость

DTO, HTTP, роли, БД, лимиты и семантика `ready` не меняются. Применяется порядок
contracts → runtime-валидация → потребители только в будущих изменениях поведения.
В приложении не появляется новая библиотека, Python-процесс или сетевой адаптер.

Риски: изменяемые каталоги и processing baseline, разные CRS/вертикальные системы,
зависимость продуктов друг от друга, недоступная лицензия, отсутствие контроля.
Меры — закреплённые ID и даты, сохранённый протокол, явные пробелы и отдельная
приёмка подготовленных входов. Альтернатива общей ссылке на портал отклонена:
она не даёт проверяемой связи с районами и конкретными сценами.
