# 0009 — снимок встроенных входов каждого расчёта

- Статус: локальный срез A3, сквозная проверка пройдена; staging не подтверждён.
- Область: Go CLI остаётся вычислительным ядром; меняются worker, паспорт результата и тесты.

## Проблема и граница

`coreVersion` идентифицирует бинарник, но не байты входных наборов. До этого
worker делал символическую ссылку на общий каталог `data`; демо `erosion`
может обновлять его кэш. Два задания могли получить общий изменяемый вход.

Worker теперь копирует поставляемый каталог `data` в частный каталог job до
запуска Go. После успешного Go он снимает SHA-256 и размер файлов, которые
привязаны к открытым HTTP-kind. Для `dimension_dataset` уже проверенный
приватный GeoJSON включается в тот же список. Путь в паспорте — логическое имя
внутри job, не абсолютный путь сервера или S3 key.

| Kind | Файлы снимка |
| --- | --- |
| `dimension` | `data/black-sea.json` |
| `map` | `data/black-sea.json`, `data/examples/sochi-local-segment.geojson` |
| `erosion` | Сегмент Сочи, волны, батиметрия, манифест кэша; инвентарь сооружений, если он присутствует и является JSON-массивом |
| `dimension_dataset` | `input.geojson` после сверки размера и SHA-256 с паспортом dataset |

`resultSummary.provenance.files` содержит `path`, `sizeBytes`, `sha256`.
Для `erosion` дополнительно `declaredSources` переносит заявления из
манифеста кэша: дата подготовки и названия источников. Это **не** редакционная
проверка лицензии, датума или научной пригодности. Хеш — точная версия
байтов снимка, но не версия метода и не гарантия независимого аудита upstream.
Обязательный файл/поле отсутствует или паспорт неверен — job не помечается
успешным. Публичные URL и произвольные пути пользователя не принимаются.

## Проверки и ограничения

- Unit-тест сверяет перечень и хеши с файлами, ловит неизвестный kind,
  отсутствующий вход и неполный манифест.
- Требуется сквозной прогон worker → Go → PostgreSQL/S3 на чистом стенде и
  проверка private copy при двух одновременно работающих worker.
- `erosion` по-прежнему может обновить **свою** копию кэша через внешние
  сервисы при её непригодности. Для воспроизводимости без сети нужно отдельно
  закрепить и лицензировать проверенный набор, запретить fallback и ввести
  версию upstream данных. Не объявлять этот срез полным решением provenance.
- Размер копии сейчас ограничен составом поставляемого репозитория, но не
  отдельной runtime-квотой. Квота и пики временного диска остаются в A5.

Локально 01.10.2026: `pnpm verify` прошёл. В изолированном Compose-проекте
HTTP → PostgreSQL → worker → Go → S3 прошли все четыре kind; тест проверил
версии схем, перечень и хеши входов, приватность файлов, отказ на плохой
геометрии, отмену и Swagger. Контейнеры остановлены и удалены. Тестовые
PostgreSQL/MinIO volumes сохранены: их удаление требует отдельного согласия.
