# 0046 — реплей датированных спутниковых контуров

- Статус: implementing, 15.10.2026; локальная интеграционная приёмка открыта.
- Владелец решения: команда Litora.
- Область: contracts, API, PostgreSQL, S3, api-client, web.
- Архитектурное решение: [ADR-021](../decisions.md).

## Проблема и границы

Текущий `/lab/shoreline` показывает кадры модели CERC. Пользователь ожидает
наблюдавшуюся динамику за годы, но готовых датированных контуров в Litora нет.
CoastSat вне платформы извлекает их из спутниковых снимков и экспортирует
GeoJSON. Этот срез принимает **подготовленные** LineString-контуры CoastSat,
не запускает Python, Google Earth Engine или научные расчёты в TypeScript.

Поддерживается только GeoJSON в EPSG:4326 после явного преобразования из
проектного CRS CoastSat. Это ограничение исключает ошибочное размещение UTM
координат на карте. Отсутствующие даты не интерполируются. Контур песок/вода
не является линией долговременной эрозии без поправок на уровень моря и контроля
качества. Отдельный план нужен для автоматического извлечения снимков, приливных
поправок и сравнения смещений в метрах в Go.

## Контракты и модель данных

Роль `shoreline_timeseries_geojson` добавлена к `scientific_inputs` миграцией
`016_observed_shoreline_series.sql`. Загрузка использует существующий
owner-scoped `POST /scientific-inputs` и `PUT /scientific-inputs/:id/content`.
`GET /scientific-inputs/:id/shoreline-series` возвращает ограниченный DTO v1:
границы [west,south,east,north] и кадры с временем ISO UTC, координатами
[longitude,latitude], спутником и качественными полями. Входной CoastSat
`date` без суффикса трактуется как UTC согласно его экспорту.

Лимит: 2–2500 кадров, до 120 000 координат суммарно, до 16 МиБ. Обновление
SQL CHECK совместимо с существующими ролями. Старые файлы и расчёты не меняются.
Откат приложения оставляет новую роль в БД; перед откатом схемы надо убрать
файлы этой роли с сохранением приватных объектов по операторской процедуре.

## Риски и альтернативы

GeoJSON без CRS может содержать неверно объявленные, но численно допустимые
координаты: загрузчик проверяет паспорт EPSG:4326 и диапазон, научную
достоверность источника подтверждает пользователь. Большой файл читается в
память API в пределах 16 МиБ; на staging нужен ресурсный тест. Отдельный
Python worker отклонён для первого среза из-за новой внешней зависимости,
учётных данных Google Earth Engine и границы научной логики Go. Локальный
импорт в браузере без приватного хранения отклонён: набор пропал бы после
перезагрузки и не имел owner-проверки.

По согласованию для географического фона используется MapLibre GL JS со стилем
OpenFreeMap Liberty. D3 рисует датированные линии в проекции текущего вида карты;
контуры остаются в браузере и не отправляются сервису тайлов. Сервис получает
запросы к области просмотра, поэтому факт просмотра участка доступен внешнему
провайдеру. OpenFreeMap не даёт SLA; при отказе остаётся координатная сетка D3.
Фон показывает современную картографию, а не исторический спутниковый снимок.
Для собственного сервера стиль задаётся `VITE_MAP_STYLE_URL` при сборке web.
