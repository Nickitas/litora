# 0033 — CERC по собственным входам в личном кабинете

- Статус: реализовано локально; сквозная научная и UI-приёмка открыта.
- Владелец: Litora; дата: 11.10.2026; основа: ветка `development` до изменения.
- Область: contracts, API/worker, PostgreSQL, web, документация. Go-математика не меняется.
- Решение использует существующие ADR-001/003/004/010; новых сервисов и прав нет.

## Проблема и границы

Ранее личный кабинет запускал `erosion` только на закреплённом демо Сочи.
Теперь отдельный `erosion_file` запускает ту же команду Go с приватными
GeoJSON-контуром, волновым рядом CSV/JSON, батиметрией JSON и паспортом.
Произвольные локальные пути и URL из клиента не принимаются.

Не покрываются `steps=0` (весь волновой ряд), дополнительные источники наносов,
сооружения и граничные потоки, `all` по своим данным и `calibrate-cerc`.
Загрузка не означает научную аттестацию или права на публикацию.

## Контракт и совместимость

`kind=erosion_file`: обязательны `coastlineInputId`, `waveInputId`,
`bathymetryInputId`, `bathymetryMetadataInputId`. Все значения — UUID,
владелец и роль перепроверяются worker при получении S3-объекта. Остальные
поля и пределы CERC совпадают с демо, кроме исходного `maxBathymetryGap=1500` м.
`steps` ограничен 1–48. Источник волнового ряда взят из сохранённого паспорта
загрузки и передан `--wave-source`; это заявленный пользователем источник.
`wave_climate` — новая роль с максимумом 16 МиБ, `.csv`/`.json`, без CRS и
координатных единиц. Миграция `010_wave_climate_input.sql` только расширяет
CHECK роли, не меняет записи. Входная схема jobs v5; worker принимает v1–v5.

Worker загружает объекты по owner-filter и сверяет размер/SHA-256. Для CERC
он переносит батиметрию в свой подкаталог под безопасным исходным ASCII-именем,
паспорт — в соседний `*.metadata.json`; содержимое паспорта не переписывается.
Go выполняет существующие проверки связки и научные расчёты. CLI-манифест v2
и ревизия метода не меняются. Строка аудита скрывает значение `--wave-source`;
сам источник остаётся в приватном provenance. Все выходы сохраняются в приватном S3.

## Риски и альтернативы

Отклонено прямое указание путей/URL в API: это ломает изоляцию и создаёт SSRF.
Отклонено переписывание `dataset_file` паспорта в worker: это скрывало бы
несовпадение происхождения. Альтернатива нового флага Go для явного пути
паспорта пока не нужна: существующий Go-контракт совместим с безопасной
подготовкой соседних файлов. Малый лимит ряда и предел 48 состояний
ограничивают память/размер GIF, но не доказывают пригодность для production.

Выкатка: сначала миграция и worker с v5, затем API и web. Откат API не
удаляет queued/running v5 jobs; старый worker их не понимает. До отката
worker их нужно завершить или отменить штатно. Квоты, хранение и роли
пользователей не расширяются.
