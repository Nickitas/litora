# 0028 — Полное функциональное покрытие CLI через web

- Статус: draft; выполнение после первого инкремента [0027](0027-web-cli-scientific-workflows.md).
- Дата: 06.10.2026; ветка `development`.
- Область: Go, contracts, API, worker, web, эксплуатация и научная приёмка.

## Цель и граница

Пользователь должен получить через кабинет ту же научную операцию, параметры,
проверки и файлы, что при соответствующем локальном запуске CLI на тех же
байтах входа и версиях Go/Gmsh. Это функциональный паритет, а не передача
произвольной командной строки в HTTP. Транспортные флаги (`--output`,
`--manifest`, `--gmsh`) назначает worker; shell `completion` остаётся только
для локальной оболочки. Удалённый `--source-url` нельзя открывать как
произвольный URL без отдельной политики источников и защиты от SSRF.

Текущее покрытие и оставшиеся команды сверяются с [реестром](../cli-capabilities.md).
Реализованный код не означает подтверждённую научную эквивалентность: полный
сквозной прогон на приватных PostgreSQL/S3 и сравнение рисунков 01–07 открыты.

## Приоритеты реализации

| Этап | Сценарии / улучшение | Зависимости и проверяемый результат |
| --- | --- | --- |
| P0 | Цепочка фигур 01–07 без ручной передачи файлов | Переиспользование собственных MSH, паспортов и поля; эталонный manifest, SHA-256 и сравнение SVG/метрик по фиксированному набору. Не выдавать похожее оформление за точное совпадение. |
| P1 | Собственные входы `erosion`, `calibrate-cerc`, составной `all` | Отдельные роли и паспорта для локального берега, волн, батиметрии, наблюдений, сооружений/источников наносов; только конечные проверенные DTO флагов, без сетевых загрузок worker. Годовое покрытие волн проверяет Go. |
| P2 | `seabed check-full`, `expert-set`, `assess-ml` | Нормализовать пакет связанных артефактов: JSON-отчёты CLI сейчас содержат локальные пути к MSH/паспорту и не переносимы одиночным upload. Go-адаптер получает доверенное соответствие артефактов, проверяет SHA-256; отдельный приватный процесс экспертных оценок и ключа организатора. |
| P3 | Источники и эксплуатация | Для удалённого `source` — согласованный allowlist доменов, DNS/IP/redirect-защита, ограничение bytes/time и лицензий. Для всех тяжёлых сценариев — прогресс, лимиты суммарного временного диска, отмена, срок хранения и запрет удаления входного результата с зависимыми jobs. |

## Общие требования приёмки

| ID | Требование | Доказательство |
| --- | --- | --- |
| PAR-001 | Каждый научный флаг CLI, доступный пользователю, имеет эквивалентный параметр сценария или явно обоснованное серверное значение | Матрица команда/флаг → DTO/default/ограничение, контрактные тесты и Swagger |
| PAR-002 | На одинаковых входных SHA-256 и версиях ядра/Gmsh CLI и web-job дают одинаковый набор manifest-артефактов и численные метрики в указанном допуске | Сквозные тесты worker → API → web на отдельной БД/S3, эталонные fixtures без гигабайтных файлов в Git |
| PAR-003 | Параметры и файлы другого пользователя, неуспешного job или неподходящей роли нельзя подставить в расчёт | Негативные API/DB/worker-тесты, owner-filter и отказ без утечки S3-key |
| PAR-004 | Для фигур 01–07 известны источник, версия, CRS, единицы, nodata и допуск визуального сравнения | Протокол эталона и научная проверка изображений, не только факт создания SVG |
| PAR-005 | Каждая форма имеет loading/empty/error/cancel/access состояния, клавиатуру, мобильную ширину и обе темы | UI/E2E-протокол на тестовом стенде |
| PAR-006 | Пользователь видит все научные значения по умолчанию до запуска, может повторить расчёт с теми же входами и сохранить конфигурацию сценария | Контрактная матрица каждого флага CLI → поле DTO/серверное значение/причина исключения; повторный запуск по сохранённым UUID, SHA-256 и версиям |
| PAR-007 | Цепочка не теряет входы, пока от них зависят другие jobs, и укладывается в лимиты диска/времени | Тест графа зависимостей, квот, отмены и политики хранения, включая ошибку на границе лимита |

Матрица PAR-001 должна перечислять **все** флаги `--help`, а не только ключевые
флаги реестра. Для каждого сценария она разделяет научный параметр, выбор
источника и транспортный флаг worker (`--output`, `--manifest`, `--gmsh`).
Одинаковое название команды без этой сверки не считается паритетом. Для
PAR-002 эталон хранит команды CLI, SHA-256 входов, версии Go/Gmsh, параметры,
список файлов, численные допуски и протокол сравнения SVG с архивными
`fig_01`–`fig_07`; наличие изображения в галерее само по себе недостаточно.
Часть PAR-006 реализована как «Создать на основе»: форма переносит известные
параметры и доступные собственные UUID, но не сохраняет отдельную библиотеку
конфигураций и не запускает старую версию Go. Недоступный набор нельзя молча
подменить примером; это проверяется браузерным тестом.
Для демонстрационного `erosion` доступны основные параметры CERC и CSV
([0029](0029-web-erosion-demo-controls.md)); они сохраняются в job и
экспортируемом паспорте. Собственные научные входы и полный набор флагов
`erosion` этим не закрыты.

## Риски и решение о выпуске

Пользовательский JSON/CSV может быть синтаксически допустимым и научно
несовместимым; Go остаётся единственным источником проверок модели. Гигантские
артефакты не копируются ради передачи между шагами, поэтому retention зависит
от графа jobs. `expert-set` содержит закрытый ключ организатора: его нельзя
показывать участникам или смешивать с общими SVG карточек без отдельной модели
доступа. Публичный запуск P1–P3 требует ресурсного замера, проверки лицензий,
плана миграции/отката и прогонов на выделенном тестовом окружении. До этого
статус «полный паритет CLI» не объявлять.
