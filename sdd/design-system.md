# Дизайн-система «Чёрное море»

Статус: конвенция; [внедрение 0007](features/0007-design-system-adoption.md)
идёт по этапам. Токены и рабочие экраны приведены к палитре, но полный аудит
публичных страниц и визуальная приёмка ещё открыты.

## 1. Характер интерфейса

Спокойный научный инструмент: точность, читаемые параметры, ясное состояние расчёта,
акцент на карте и результатах. Глубокий синий напоминает глубину, бирюзовый — воду,
светлые нейтральные поверхности — рабочий лист. Цвет не заменяет смысл.

Маркетинговые страницы, документация, вход и кабинет используют одни токены,
типографику и состояния компонентов. На лендинге допустим один сдержанный морской
градиент; в рабочих формах нет стеклянных панелей, постоянного свечения, разноцветных
CTA и декоративной анимации каждой карточки.

## 2. Какой shadcn

Сохраняем текущий **shadcn/ui `radix-nova`**, Radix primitives, Tailwind CSS 4,
`baseColor: neutral`, `cssVariables: true`, Lucide, `rsc: false`, TypeScript.
Новый preset не создаём: Nova уже выбран в `apps/lito-web/components.json`.
Не смешиваем Radix и Base UI варианты одного компонента, не запускаем повторно
`shadcn init` с перезаписью кастомизаций. Это Vite SPA, не React Server Components.

shadcn предоставляет исходники компонентов, которыми владеет проект; тему задаём
semantic CSS variables и парными foreground-токенами, а не заменой классов в каждой
кнопке. Основание: [официальная система тем](https://ui.shadcn.com/docs/theming) и
[выбор стилей/базовых библиотек](https://ui.shadcn.com/docs/changelog/2025-12-shadcn-create).

Расположение примитивов: `src/shared/shadcn/components/ui`. Доменный компонент
`CalculationStatus` живёт в слое entity/feature, не в библиотеке универсальных кнопок.
Общий UI-package не создаём, пока потребитель один. `@magicui` и animated icons
уже настроены, но не становятся обязательной зависимостью каждой рабочей страницы.

Путь CSS в `components.json` настроен на действующий файл
`src/shared/styles/index.css`; перед добавлением новых компонентов проверяйте
его вместе с алиасами и диффом сгенерированного кода.
Версию CLI shadcn фиксировать при установке; просматривать diff исходников/зависимостей.

## 3. Семантическая палитра

Цвета ниже — нормативные sRGB HEX. Допустима механическая конвертация в OKLCH
без визуального изменения; не держать два независимо редактируемых набора.
Реализация: один `:root`, один `.dark`, существующий `@theme inline` Tailwind.
В компонентах только `bg-background`, `text-foreground`, `border-border`,
`bg-primary`, `text-primary-foreground` и аналогичные токены, без случайных HEX.

на белый текст из старого класса компонента в обеих темах.

### Статусы и графики

| Статус | Светлая: текст / фон | Тёмная: текст / фон | Подпись и иконка |
| --- | --- | --- | --- |
| queued | `#526874` / `#E9F0F4` | `#A3BAC6` / `#1A3442` | «В очереди», Clock |
| running | `#1D4ED8` / `#DBEAFE` | `#93C5FD` / `#142B46` | «Выполняется», LoaderCircle |
| succeeded | `#166534` / `#DCFCE7` | `#86EFAC` / `#123226` | «Завершён», CircleCheck |
| failed | `#B42318` / `#FEE4E2` | `#FFB4AB` / `#40120E` | «Ошибка», CircleAlert |
| cancelled | Как queued | Как queued | «Отменён», CircleSlash |
| warning (не job status) | `#854D0E` / `#FEF3C7` | `#FDE68A` / `#382B14` | Предупреждение о качестве |

Ввести `--status-*-foreground/background` при реализации; не размазывать значения
по Badge. Один компонент отображает статусы из `CalculationStatus` контракта.

Для категорий: chart-1 teal `#087D8A` / `#40C9CC`, chart-2 blue `#2563EB` / `#93C5FD`,
chart-3 amber `#A16207` / `#FACC15`, chart-4 violet `#7C3AED` / `#C4B5FD`,
chart-5 green `#15803D` / `#86EFAC` (light / dark). Каждая серия также имеет имя,
маркер/тип линии; наложенные серии не должны отличаться только цветом.

Батиметрия — последовательная шкала «мелко → глубоко» с легендой, единицами и
явным nodata; не использовать статус success для обозначения глубины. Значения
и цветовая шкала научного SVG принадлежат Go renderer; web-тема не перекрашивает
их произвольно. Процент/точность не показывать, если модель их не возвращает.

## 4. Контраст и доступность

Цель — WCAG 2.2 AA. Обычный текст не ниже 4.5:1, крупный 3:1; видимые значимые
границы/focus проверять отдельно на 3:1. Основание:
[WCAG — контраст текста](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
и [контраст нетекстовых элементов](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

Расчёт относительной яркости sRGB для сплошных цветов дал:

| Пара | Light | Dark |
| --- | --- | --- |
| foreground / background | 13.53:1 | 15.54:1 |
| muted-foreground / background | 5.53:1 | 8.91:1 |
| primary-foreground / primary | 4.87:1 | 7.97:1 |
| primary / background (ссылка) | 4.61:1 | 8.95:1 |
| input / card | 3.85:1 | 3.88:1 |

Это проверка токенов, не сертификат всех экранов. Opacity/hover/картинки меняют
контраст. `border` намеренно мягкий и не подходит как единственный контур ввода.
Текст кнопки на hover сохраняет проверенную пару, иначе нужен повторный расчёт.

- Tab/Shift+Tab проходят логично; focus видим: кольцо 2 px с отступом 2 px.
- Label связан с input; ошибка через `aria-describedby`, неверное поле `aria-invalid`.
  Placeholder не заменяет label; required обозначается словами/легендой формы.
- Dialog возвращает focus инициатору, закрывается Escape; есть заголовок и описание.
- Иконка без текста имеет доступное имя. Минимальная touch-цель — 44×44 px.
- `aria-live=polite` для изменения состояния job, не для каждого tick polling.
  Ошибка отправки сообщается доступно; не полагаться только на toast.
- Карта/график имеют текстовое описание, подписи осей/единиц и альтернативу данными.
- Рабочие страницы проверяются при 200% zoom и ширине 360 px, без потери действий.
- `prefers-reduced-motion`: убрать необязательную анимацию; текст «Выполняется»
  сохраняется, даже если spinner перестал вращаться.

## 5. Типографика, размеры и композиция

Geist Variable уже подключён. Основной текст 16/24 px, подписи 14/20 px,
служебные пометки не мельче 12/16 px. H1 32/40 semibold (на mobile 28/36),
H2 24/32, H3 20/28; не перескакивать уровни заголовков ради размера.
Числа/метрики — tabular-nums, код/UUID — системный monospace; единицы рядом со значением.
Форматирование `Intl` с `ru-RU`; `0`, отсутствие значения и ошибка — разные состояния.

Spacing: 4, 8, 12, 16, 24, 32, 48, 64 px. Радиус основы `--radius: 10px`;
сохранять существующие производные shadcn, не добавлять десятки уникальных радиусов.
Тонкая тень только у плавающих поверхностей и важных карточек, в dark в основном border.
Иконки Lucide 16/20/24 px, stroke 1.75–2; emoji не заменяет системную иконографику.

Контент кабинета max-width 1440 px; справочник/текст около 72–80 символов строки.
Desktop: навигация 240 px, контент гибкий. Mobile: Sheet навигации, форма в один
столбец, таблица с осмысленным horizontal scroll либо карточками, без скрытия статуса.
В списке расчётов важны тип, статус, время и действие; UUID — в деталях/копировании.

## 6. Состав UI-kit и правила сценариев

Набор ниже — целевой каталог, не заявление об установленных компонентах.
Добавлять по мере задач, переиспользовать уже существующие Button/Card/Badge.

| Группа | Компоненты | Правила |
| --- | --- | --- |
| Действия | Button, DropdownMenu, Tooltip | Один primary на смысловую область; Tooltip не единственное имя |
| Ввод | Label, Input, Textarea, Select, Checkbox, Switch | Label, helper, единицы, ограничение, inline error |
| Структура | Card, Separator, Tabs, Sidebar, Breadcrumb | Не помещать всё в дополнительные карточки |
| Обратная связь | Alert, Skeleton, Progress, toast | Progress только с реальной метрикой; ошибки не исчезают сами |
| Данные | Table, Badge, ScrollArea | Сортировка/пагинация только при поддержке API |
| Оверлеи | Dialog, AlertDialog, Sheet | Опасное действие с понятным подтверждением |

Вход: два понятных режима регистрации/авторизации, пароль допускает вставку и
password manager, правильный autocomplete. Нельзя прятать политику пароля в toast.

Создание расчёта: описание метода, источник/ограничения, поля с единицами, оценка
только при реальных замерах, submit pending защищает от повторного клика. Для
erosion рядом с запуском явная метка «Демонстрационный сценарий».

История: skeleton при первом запросе; empty с объяснением и CTA; reconnect при
сбое сети. Карточка результата: статус → параметры → метрики → изображения → файлы
с форматом/размером/SHA-256 → технические детали. Отмена отличается от удаления.
Скачивание идёт по URL от API; не строить адрес S3 вручную.

## 7. Порядок внедрения и приёмка

1. Инвентаризировать текущие hardcoded цвета и компоненты; CSS-path shadcn исправлен.
2. Ввести tokens и переключение system/light/dark; persist только предпочтение темы.
3. Привести примитивы, включая dark destructive/focus/input; затем auth и кабинет.
4. Унифицировать статусы, состояния формы, историю и просмотр результатов.
5. Перенести публичные страницы и docs без изменения научных иллюстраций.
6. Проверить contrast, клавиатуру, responsive, reduced motion, empty/error/offline;
   выполнить typecheck/build/lint. Скриншоты фиксируют изменения, но не заменяют проверки.

Этот план не добавляет новую библиотеку состояния, не меняет HTTP-контракт и не
обещает новые продуктовые функции. Любая новая функция проходит обычный SDD.
