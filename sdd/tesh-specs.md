# Технические конвенции

Статус: конвенции нового кода и проверенный срез реализации на 25.09.2026.
Изменение архитектурного решения сопровождается записью в [ADR](decisions.md).

## 1. Границы системы

```text
Пользователь → React → @litora/api-client → NestJS → PostgreSQL
                                              ↑         ↓ очередь
                                              └─ отдельный Node worker
                                                        ↓ spawn без shell
                                                  Go CLI / Go-пакеты
                                                        ↓
                                              приватные объекты в S3
```

API и worker сейчас запускаются из одного Docker-образа, но это разные процессы
и контейнеры. **Go worker — целевой следующий адаптер, не текущая реализация.**
Замена транспорта не должна менять API или переносить математику из Go в TS.
API выдаёт signed URL; браузер может скачивать файл по этой ссылке, но никогда
не получает S3-ключи и не управляет bucket напрямую.

| Область | Ответственность | Запрещённая зависимость |
| --- | --- | --- |
| `apps/lito-cli` | Геометрия, модели, валидация научных данных, отчёты и manifest | HTTP/auth/БД в научных пакетах |
| `apps/lito-api` | Пользователь, сессии, DTO, очередь, владение, хранение | Расчёт в controller, научные формулы |
| `apps/lito-api/src/worker` | Захват задания, CLI, heartbeat, отмена, публикация файлов | Произвольный shell или команда из запроса |
| `apps/lito-web` | Состояния экрана, ввод, отображение, навигация | Прямой SQL, S3 SDK, копии серверных DTO |
| `packages/contracts` | Публичные типы/контракты | Nest/React/драйвер БД и секреты |
| `packages/api-client` | HTTP, типизированные ответы и ошибки | UI-компоненты и научная логика |
| `packages/config` | Общие безопасные настройки | Секреты и production-учётные данные |
| `packages/docs/content` | Научные и инженерные документы | Локальные копии в приложениях |
| `packages/generated-data` | Небольшие примеры с происхождением | Полные GEBCO/результаты сотен МБ |

Общие пакеты не импортируют приложения. API не импортирует web; web не импортирует
исходники API. Домен Go не зависит от Cobra: Cobra читает флаги и вызывает use case.
Новый модуль создаётся по реальной ответственности, а не ради абстракции «на будущее».

## 2. Принятый стек и исключения

| Используем сейчас | Конвенция / что не добавляем автоматически |
| --- | --- |
| Go 1.25.4+, Cobra | Не переписываем модели в Node/Python |
| Node 22.12+, pnpm 10.15.0, workspaces | Один корневой `pnpm-lock.yaml`; не npm/yarn lockfiles |
| NestJS 11, TypeScript, REST/OpenAPI | Не GraphQL, gRPC и отдельные микросервисы без ADR |
| `pg`, SQL-миграции | Не вводим Prisma/TypeORM параллельно с текущим доступом |
| PostgreSQL 17, очередь `SKIP LOCKED` | Redis/RabbitMQ/Kafka только после измерений |
| AWS SDK v3, S3 API | Файлы не в BYTEA/JSONB и не в Git |
| React 19, Vite 7, React Router 7 | Не Next.js и не TanStack Router без миграционного решения |
| Tailwind 4, shadcn `radix-nova`, Lucide, Geist | Не второй UI-kit MUI/AntD и не новый style поверх старого |
| Context и polling в текущем web | TanStack Query возможен отдельной миграцией, не установлен по умолчанию |
| Docker Compose, PostgreSQL, локальный MinIO | Kubernetes и HA не нужны для первого односерверного пилота |

Точные зависимости определяют manifests/lockfile/Dockerfile. Версии выше описывают
исходный срез, а не запрет безопасных обновлений. Обновление major — отдельное
изменение с migration notes и тестами. Для release образы фиксируются digest,
`latest` запрещён. Локальный `minio:latest` — существующий технический долг;
production-вариант объяснён в [deployment](deployment.md).

## 3. Общий код-стайл

- Русский: UI, собственные ошибки CLI/API, документация, комментарии к публичному коду.
  Английский: идентификаторы, HTTP-поля, SQL, имена файлов и технические ключи.
- UTF-8, LF, завершающий перевод строки; не коммитить массовую смену переносов строк.
- Называть по смыслу: `createCalculation`, `jobId`, `artifact`; не `data2`, `manager`
  без ответственности. Константы ограничений имеют понятное имя и единицу измерения.
- Функция решает одну задачу; ранние возвраты вместо глубокой вложенности. Общую
  абстракцию выделять при повторяемом поведении, не при случайно похожих строках.
- Комментарий объясняет ограничение/причину/источник, а не пересказывает выражение.
  TODO содержит ссылку на задачу и условие завершения.
- Не оставлять закомментированные реализации, отладочные console.log и неиспользуемые
  зависимости. Логирование события — осознанное, без секретов и пользовательских файлов.

### TypeScript / NestJS

- `strict`; не ослаблять tsconfig ради прохождения сборки. `unknown` на внешней
  границе, затем runtime-проверка. Тип TS сам по себе вход не валидирует.
- `any`, двойные `as`, non-null assertions и `@ts-ignore` требуют конкретного
  обоснования и узкой границы; не маскировать ими несовпадающие контракты.
- Prettier: 2 пробела, `semi: true`, двойные кавычки, `trailingComma: es5`,
  `printWidth: 80`. Это существующая настройка web; единый root formatter пока не заведён.
- `import type` для типов; сохранять `.js` в ESM-импортах API. Не менять модульный
  режим и алиасы в рамках случайной функции. Импорты: внешние → общие пакеты → локальные.
- Controller: auth + разобрать/проверить DTO + вызвать service/repository + вернуть DTO.
  Повторяемые бизнес-правила выделять в service; SQL живёт в repository, параметры `$1`.
- Не логировать и не возвращать пароль, токены, `DATABASE_URL`, stacktrace драйвера.
  Пользовательская ошибка по-русски; техническая причина — безопасно в серверном логе.
- `await` для обязательных операций. Fire-and-forget только с владением жизненным циклом,
  обработкой ошибки и graceful shutdown; тяжёлые задачи — в очереди.
- Числа проверять на finite, диапазон, целочисленность. Не принимать неизвестные поля.
  Новые endpoint должны иметь точные Swagger schemas, включая ошибки и nullable поля.

### Go

- `gofmt`, затем `go vet`; экспортируемый тип/функция имеют godoc-комментарий на русском,
  начинающийся с имени сущности. Имена пакетов короткие, lowercase; файлы `snake_case.go`.
- Ошибки возвращаются явно, оборачиваются `fmt.Errorf("контекст: %w", err)`;
  `panic` не применяется к пользовательскому вводу. Не подавлять ошибки записи/закрытия.
- `context.Context` передаётся первым параметром для долгих операций; отмена и таймаут
  проверяются в циклах. Не создавать неограниченные goroutine; при параллельности
  задавать лимит, владение каналами и тест с `-race`.
- Научный вход: CRS, порядок координат, единицы, nodata, диапазон и происхождение.
  Не смешивать географические градусы с метрами; не выдумывать отсутствующие данные.
- Детерминированные примеры, фиксированный seed при случайности, golden/числовые тесты
  с обоснованным допуском. Смена формулы требует ссылки на методику и сравнения результатов.
- CLI: таблицы через `text/tabwriter`, разделитель `\t`, русские заголовки. Результаты
  в `output/` относительно CLI или явном `--output`; не в корне монорепозитория.
- Для машинного потребителя — версия manifest/schema и данные, а не парсинг человекочитаемой
  таблицы. `--manifest` остаётся необязательным для самостоятельного пользователя CLI.

### React

- Функциональные компоненты и hooks верхнего уровня. `PascalCase` для компонента,
  `useSomething` для hook, `kebab-case.tsx` для файла. Сохранять текущие слои
  `app/pages/widgets/features/entities/shared`; не мигрировать дерево ради одной формы.
- Страница собирает сценарий; feature владеет действием, entity — представлением
  сущности, shared — универсальными примитивами. Нижний слой не импортирует верхний.
- Данные API получать через `@litora/api-client`. Не создавать локальные копии
  `CalculationJobDto`; UI-only модели допускаются как явное преобразование DTO.
- Производное состояние вычислять при рендере, не синхронизировать цепочкой effects.
  Effects для внешних систем; подписки, запросы и polling имеют cleanup, старый ответ
  не перезаписывает новое состояние после смены пользователя/задания.
- Access token только в памяти. При logout очищаются пользовательские данные и таймеры.
  Не хранить токены в localStorage/sessionStorage и URL. Тема интерфейса там допустима.
- Loading/empty/error/forbidden/success — отдельные состояния; ошибка не равна пустой
  истории. Не показывать выдуманный процент готовности расчёта.
- Семантические HTML-элементы, label, видимый focus, клавиатура; правила в
  [дизайн-системе](design-system.md). Не вставлять внешний SVG/HTML через
  `dangerouslySetInnerHTML`; отчёты отображать безопасным способом.
- Мемоизация и code splitting после измерения. Крупные карты/3D загружать по требованию,
  не импортировать сотни МБ в главный bundle.

## 4. Контракты, HTTP и данные

Порядок изменения: contracts → API/worker → api-client → web → OpenAPI → документация.
Runtime-валидация находится на границе API; Swagger-классы могут оформлять схемы,
но не становиться независимым источником бизнес-типов. Сегодня OpenAPI описывается
явно; автоматический codegen клиента пока не настроен.

- Базовый путь `/api`, camelCase JSON, UUID идентификаторы, UTC ISO 8601 даты.
  В UI даты форматируются по локали, исходные значения не меняются.
- Известные HTTP-статусы: 400 неверный ввод, 401 нет сессии, 404 отсутствующий/чужой
  ресурс, 409 конфликт, 429 лимит, 503 зависимость недоступна. Не выдавать чужое
  существование через 403. Точный ответ сверять с endpoint, не менять статусы случайно.
- `POST /calculations` сейчас возвращает 201 и job, не результат и не 202.
  `POST /:id/cancel` также использует текущий 201; унификацию делать контрактным изменением.
- Авторизация владельца обязательна в SQL (`id` и `user_id`), включая файлы и отмену.
  Наличие `role=admin` в БД само по себе не даёт новых HTTP-прав.
- SQL: snake_case, параметризация, короткие транзакции; сеть/S3/CLI не держат транзакцию.
  JSONB только для структурированных входов/малых сводок, не бинарного содержимого.
- Новая миграция `NNN_name.sql` в `infra/postgres/init`, опубликованные не править.
  Номер согласовать с веткой; изменения по expand→migrate→contract, destructive шаг отдельно.
  Текущий runner транзакционный: `CREATE INDEX CONCURRENTLY` в нём не использовать.
- PostgreSQL и S3 не имеют общей транзакции. Частичный upload учитывается как возможный
  исход; нельзя объявить success до сохранения реестра результатов. План уборки сирот
  и политики удаления требует отдельной спецификации.
- Новые входные файлы: лимит размера/распаковки, SHA-256, MIME и фактический формат,
  безопасное имя/путь, владелец, provenance. Upload API пока не реализован.

## 5. Секреты, конфигурация и эксплуатация

Только environment на сервере; локально `.env.local`, пример без секретов. Не
добавлять credentials в пакеты, Docker build args, клиентский `VITE_*` или Git.
Новая переменная документируется: назначение, default, обязательность, секретность,
перезапуск. В конфигурации нет самовольного fallback на production-пароль.

Не выполнять CLI из HTTP controller, не давать запросу выбрать binary/flags/path/URL,
не пользоваться `exec` со строкой. Разрешённые сценарии — `calculations/commands.ts`.
Очередь обязана сохранять atomic claim, heartbeat, лимиты и условные переходы статусов.
Не считать `health=200` доказательством живого worker: нужен успешный контрольный job.

## 6. Проверки и Git

| Изменение | Минимальная проверка |
| --- | --- |
| Только Markdown | Ссылки, отсутствие дублей/секретов, `git diff --check` |
| Compose/Caddy-пример | `docker compose ... config --quiet`, Caddy validate, секреты не печатать |
| Contracts/API/client | `pnpm typecheck`, `pnpm build:api`, `pnpm test:api` |
| Web | `pnpm typecheck`, `pnpm build:web`, lint web; клавиатура и обе темы |
| Go | `gofmt` затронутых файлов, `go vet ./...`, `go test ./...` внутри CLI |
| Конкурентный Go | Дополнительно `go test -race ./...` |
| Auth/jobs/S3/миграции | Полный интеграционный сценарий на отдельной тестовой БД/bucket |

Основные команды из корня: `pnpm typecheck`, `pnpm build:api`, `pnpm build:web`,
`pnpm test:api`, `pnpm test:cli`. Единый gate — `pnpm verify`; он также включает
`pnpm check:workspace`, web lint и проверку документации/релизных бинарников.
`pnpm test:integration` — только на тестовом стенде, создаёт аккаунты и объекты.

Работа ведётся от монорепозиторной `development`; `main` — выпуск после приёмки.
Не подмешивать старую source-ветку web под тем же именем. Не переписывать импортированную
историю и LFS ради текущей функции. Ветки агента при необходимости — `codex/<topic>`.
Изменения пользователя сохранять; коммиты, push, merge и релиз — только по поручению.

Когда коммит поручен: `type(scope): краткое действие` (`feat`, `fix`, `docs`,
`refactor`, `test`, `chore`; scope `cli/api/web/contracts/infra/docs`). Заголовок
может быть на русском, type/scope — технические идентификаторы. Один логический
результат на коммит; breaking change явно описать в сообщении и миграционных заметках.
PR связывает spec/требования, перечисляет проверки и риск для данных. SemVer ядра,
версия manifest и версия HTTP-контракта — разные сущности: не считать hash binary
заменой версии публичной схемы.
