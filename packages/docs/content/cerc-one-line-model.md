# Инженерная одномерная модель CERC

Команды `lito erosion` и `lito all` используют инженерную модель одной линии
берега. Она предназначена для вдольбереговой перестройки песчаного берега на
масштабе, для которого профиль можно считать сохраняющим форму. Это не 2D
морфодинамическая модель и не заменяет полевые измерения.

## Необходимые данные

Расчёт не начинается без двух явно загруженных входов:

- батиметрии в JSON-формате Lito;
- временного ряда состояний волн через `--wave-input`.

Команды `lito erosion` и `lito all` требуют явно указать контур, волновой ряд
и батиметрию. Пустой и неполный запуск завершается ошибкой до загрузки данных.
Автоматического сценария Сочи, его загрузчика и флагов `--black-sea-sochi`/
`--offline` больше нет. Для локальных файлов сеть не нужна; удалённый контур
можно импортировать только явным `--source-url`. Наличие реальных файлов
само по себе не подтверждает пригодность для исследования или прогноза.

API не принимает новые демонстрационные виды `erosion`/`all_demo`. Ранее
поставленные в очередь демо завершаются с понятной ошибкой; старые результаты
остаются доступны владельцу с исходным статусом интерпретации.

В личном кабинете отдельный сценарий «Эрозия по своим данным» принимает
приватный GeoJSON незамкнутого локального сегмента, волновой ряд JSON/CSV
до 16 МиБ и JSON батиметрии с паспортом. Источник волн, указанный при загрузке,
передаётся Go как `--wave-source`, в том числе для JSON. Через форму можно
рассчитать первые 1–48 состояний либо выбрать 0 для всего загруженного ряда,
настроить CERC и сохранить CSV. В режиме первых 1–48 состояний доступен GIF.
Граничные потоки на обоих концах сегмента задаются в форме явно. Пустое поле
не заменяется нулём: 0 означает выбранное условие отсутствия потока, которое
требует обоснования. Необязательные JSON-профили источников наносов и сооружений теперь
можно загрузить для сценариев `erosion_file`, `all_file` и `calibrate_cerc`.
Для полного ряда допустимы до 10 000 состояний и 200 точек берега. Go сохраняет
полный численный `longshore-cerc.json`, а SVG эрозии — не более выбранных 2–128 кадров,
включая первый и последний. GIF и широкий CSV в этом режиме недоступны;
длинный CSV можно включить отдельно. Расчёт может завершиться по лимиту времени
или объёма результата worker. Загрузка файлов сама по себе не делает результат
прогнозом.

В новом расчёте web/API индекс разрушения, высота бермы, глубина замыкания,
пористость, K, расстояние отбора глубины и радиус её поиска заполняются по данным
участка. Автоматических физических значений нет. Калибровка также требует явно
заданных кандидатов K, дистанции сопоставления наблюдений и фактического шага
батиметрии из паспорта (технический предел 0.1°). Начальные настройки экспорта
и ресурсных ограничений показаны с пояснениями; допустимый диапазон не
подтверждает научную пригодность. Сохранённые полные параметры можно повторить,
но повтор не заменяет независимую проверку.

Линия берега должна быть незамкнутым, последовательно оцифрованным **локальным
сегментом**. Полный `data/coastline/black-sea.geojson` описывает границу морского района
и не является допустимым входом one-line модели: сначала извлеките
участок исследования с непрерывной береговой линией и подготовьте для него
прибрежную батиметрию.

Для Чёрного моря рекомендуемый источник волнового ряда — реанализ
[Copernicus Marine BLKSEA_MULTIYEAR_WAV_007_006](https://data.marine.copernicus.eu/product/BLKSEA_MULTIYEAR_WAV_007_006/description).
Он публикует значительную высоту, период и направление волн. Для батиметрии
следует использовать [GEBCO Grid](https://www.gebco.net/data_and_products/gridded_bathymetry_data/): это открытая глобальная сетка с шагом 15 угловых секунд. Метаданные набора, период, дата выгрузки и способ пространственной выборки должны быть указаны в поле `source` волнового ряда и в журнале эксперимента.

Пример JSON:

```json
{
  "source": "Copernicus Marine BLKSEA_MULTIYEAR_WAV_007_006, выборка 41.80N 41.70E, 2020-01-01..2020-01-02",
  "conditions": [
    {
      "time": "2020-01-01T00:00:00Z",
      "duration_hours": 3,
      "hs_m": 1.2,
      "tp_s": 5.8,
      "direction_from_deg": 110
    }
  ]
}
```

Эквивалентный CSV обязан иметь заголовок:

```text
time,duration_hours,hs_m,tp_s,direction_from_deg
2020-01-01T00:00:00Z,3,1.2,5.8,110
```

Для CSV происхождение обязательно передаётся отдельным флагом `--wave-source`.
Направление — метеорологическое: оно указывает, **откуда** пришла волна, по
часовой стрелке от севера.

Дополнительно `LoadWaveClimate` принимает исходный JSON-ответ
[Open-Meteo Marine](https://open-meteo.com/en/docs/marine-weather-api) с
почасовыми полями `wave_height`, `wave_period`, `wave_direction`. Для него
обязательно передайте `--wave-source`, поскольку ответ API не содержит
достаточных метаданных для воспроизводимого научного отчёта. Сам факт
успешной загрузки такого ответа и завершения CERC не меняет класс сценария.

`time` либо должен присутствовать у каждого состояния, либо отсутствовать у
всех. При наличии временных меток Lito отвергает перекрывающиеся и
неупорядоченные интервалы, а в итоговом JSON показывает длительность и самый
длинный пропуск ряда.

## Расчёт

В глубокой воде спектральное состояние представлено его интегральными
параметрами `Hs` и `Tp`. Для каждого узла линии берега модель:

1. решает дисперсионное соотношение `ω² = gk tanh(kh)` и получает фазовую и
   групповую скорости;
2. преобразует угол по закону Снеллиуса;
3. получает высоту при подходе к берегу из сохранения потока энергии;
4. находит глубину разрушения из критерия `Hb = γ hb`;
5. вычисляет поток наносов CERC:

   `Q = K · (E Cg sin(αb) cos(αb)) / ((ρs − ρ) g (1 − p))`;

6. применяет дискретное уравнение неразрывности `ΔV = (Qleft − Qright) Δt`;
7. переводит объём ячейки в смещение линии через активную высоту профиля
   `B + Dc`.

`longshore-cerc.json` в `output/erosion/` содержит `scenario_status`,
`usage_limitations`, происхождение волнового ряда и батиметрии, каждую ячейку,
`Q` в `м³/с`, объём в `м³`, смещение в
метрах, дистанцию до батиметрической точки и невязку массы. Если для
билинейной интерполяции у берега не хватает ячеек, допускается только ближайшее
реальное измерение в радиусе `--max-bathymetry-gap`; превышение радиуса
останавливает расчёт. В web радиус выбирается явно по покрытию и неопределённости
источника; самостоятельный CLI сохраняет начальные 1500 м. Если явно заданы
непроницаемые границы (`Q = 0`), суммарная невязка должна быть близка к машинному нулю.

В личном кабинете новые результаты CERC можно открыть в разделе «Динамика
берега». Карта сопоставляет исходную линию с выбранным сохранённым состоянием,
а графики показывают высоту волн и смещение по ячейкам из расчёта Go.
На широком экране карта и графики расположены рядом: выбор кадра на шкале под
картой обновляет выделенное состояние на графиках, а выбор узла меняет его
временной график. Над графиками показаны точное смещение выбранного узла за
шаг и высота волны для показанного кадра. На узком экране графики идут сразу
после карты. Паспорт и остальные числовые значения находятся ниже рабочей
области.
Если у всех волновых состояний есть временные метки, шкалу можно рассматривать
по годам, месяцам, неделям и дням. Пустой период обозначает отсутствие кадра,
а не неизменность берега. Без дат доступна только навигация по шагам. Это
просмотр результатов модели, не наблюдение линии берега в реальном времени.
Старые расчёты без индекса карты по-прежнему доступны как SVG и полный JSON.

## Качество входов и границы сегмента

Укажите фактический шаг регулярной сетки через `--bathymetry-resolution`
либо предоставьте проверяемый соседний паспорт `*.metadata.json` с
`target_resolution_degrees`, `dataset_file` и SHA-256 набора.
Этот параметр нельзя заменять произвольным значением: от него зависит ключ
ячейки, интерполяция глубин и допустимость ближайшей точки. Для пользовательского
набора Чёрного моря шаг обязателен: в кабинете он берётся только из паспорта,
в CLI его можно указать явно. Значение не подставляется из удалённого демо.

В `input_quality` файла `longshore-cerc.json` фиксируются временное покрытие
волн, число точек и шаг батиметрии, доля интерполированных выборок и максимум
дистанции до ближайшего измерения. Если последняя величина велика относительно
размеров береговой формы, результат пригоден только для предварительной
оценки.

`scenario_status` описывает допустимую интерпретацию отдельно от технического
успеха расчёта. Старые демонстрационные результаты сохраняют `demo`; новый
набор без отдельной процедуры аттестации получает `unclassified`. Lito не
присваивает исследовательский статус автоматически.

Самостоятельный CLI сохраняет нулевой граничный поток по умолчанию. В web/API
потоки обязательны и не подставляются. Для участка с
известным внешним балансом используйте:

```bash
--left-boundary-transport 0.03 \
--right-boundary-transport 0.01
```

Единица — `м³/с`; положительный поток на левой границе входит в сегмент, а на
правой — выходит из него. В отчёте сохраняются внешний чистый объём и невязка
замыкания баланса. Не задавайте эти значения без измерений или обоснованной
оценки: ноль остаётся более честным условием при отсутствии информации.
В кабинете оба поля доступны для демо и собственных сценариев `erosion`/`all`;
при повторе расчёта введённые значения сохраняются.

Внешние источники и стоки внутри сегмента передаются отдельным JSON-файлом:

```json
[
  {
    "point_index": 12,
    "source_rate_m3_s": 0.005,
    "description": "питание пляжа",
    "data_source": "проектный журнал работ, август 2026"
  }
]
```

Передайте его через `--sediment-sources источники.json`. Положительное значение
добавляет наносы, отрицательное моделирует их изъятие. Индекс относится к
вершине сегмента после нормализации контура в Go; один индекс может иметь только один
источник. Данные о происхождении обязательны. В поле `sediment_sources` и в
каждом шаге JSON-отчёта сохраняются исходные параметры и фактический внешний
объём. Профиль активного слоя и исчерпание местного запаса пока не моделируются,
поэтому не используйте этот механизм как замену инженерной оценки запасов.

Сооружения задаются отдельно на грани между `left_point_index` и следующим
узлом сегмента:

```json
[
  {
    "left_point_index": 8,
    "transmission_coefficient": 0.25,
    "kind": "буна",
    "description": "железобетонная буна",
    "data_source": "обследование сооружений, август 2026"
  }
]
```

Передайте профиль через `--structures сооружения.json`. Коэффициент `0`
означает полное перекрытие переноса, `1` — отсутствие влияния, промежуточное
значение — долю пропуска. Допускается только одно сооружение на грани, а
`kind` и `data_source` обязательны. Это one-line представление перехвата
вдольберегового транспорта: оно не рассчитывает дифракцию, отражение или
обтекание волн вокруг сооружения.

В кабинете каждый такой профиль — отдельный приватный файл JSON до 1 МиБ
с указанными источником и лицензией. Выберите файлы в форме расчёта; API
проверит владельца и роль, worker передаст их Go без переинтерпретации чисел.
Для `all_file` с индексными профилями необходимо отключить упрощение базовой
линии и оставить максимум точек равным нулю: иначе номера ячеек потеряют
смысл. Go может удалить повторяющиеся вершины при нормализации, поэтому
проверьте индексы именно по загруженному и нормализованному контуру. Проверка
диапазона индексов не доказывает, что сооружение привязано к нужному месту.

Сооружения задавайте явным файлом `--structures` с обоснованной привязкой к
индексам выбранного контура. Автоматического скачивания и назначения полного
перехвата по OSM-тегу больше нет. Отсутствие файла означает отсутствие заданных
сооружений, а не подтверждение их отсутствия на участке.

## Калибровка коэффициента CERC

Команда `calibrate-cerc` сопоставляет результаты физической one-line модели с
независимыми скоростями изменения линии берега и ранжирует кандидаты `K` по
RMSE. Она не использует историческую эвристику `erosion-strength`.

```bash
./lito calibrate-cerc \
  --input участок.geojson \
  --bathymetry глубины.json \
  --bathymetry-resolution 0.000139 \
  --wave-input волны-за-год.json \
  --observations наблюдения-берега.json \
  --cerc-coefficients 0.20,0.30,0.39,0.50 \
  --output output/калибровка
```

Файл наблюдений — массив JSON-объектов:

```json
[
  {
    "lat": 43.6123,
    "lon": 39.7012,
    "shoreline_change_rate_m_per_year": 0.8,
    "uncertainty_m_per_year": 0.2
  }
]
```

Положительная скорость наблюдения означает размыв, отрицательная — аккумуляцию.
Внутреннее положительное смещение CERC направлено в море и поэтому означает
аккумуляцию; при сравнении с наблюдениями программа меняет знак явно. Ряд волн
должен покрывать не меньше 8766 часов по умолчанию; семидневный прогноз Сочи
для калибровки сознательно отклоняется. Результат сохраняется в
`output/erosion/cerc-calibration.json` вместе с источниками берега и волн.

В личном кабинете сценарий «Калибровка CERC по наблюдениям» принимает пять
приватных файлов: локальный GeoJSON-сегмент, годовой ряд волн JSON/CSV,
батиметрию JSON, её проверяемый паспорт и независимые наблюдения JSON в
EPSG:4326. Для наблюдений укажите источник и лицензию при загрузке;
сервер сохраняет SHA-256. Фактический шаг батиметрии в градусах задаётся в
форме и сверяется Go с паспортом. Минимальное покрытие ряда в кабинете нельзя
задать меньше 8766 ч. Отчёт, манифест и журнал доступны только владельцу
через временные ссылки. Если отчёт помещается в краткую сводку, кабинет
показывает рейтинг и метрики таблицей без повторного расчёта; крупный отчёт
остаётся доступен как файл JSON. Это подбор коэффициента для указанных данных,
а не независимая аттестация или гарантия будущего прогноза. Необязательные
источники наносов и сооружения задаются теми же приватными профилями, что и
для расчёта эрозии.

## Подготовка длинного ряда для прогноза

Локальная команда проверяет фактическое временное покрытие GeoJSON
наблюдений и, по желанию, волнового ряда до построения модели:

```bash
./lito shoreline-data-audit \
  --observations снимки-берега.geojson \
  --wave-input архив-волн.json \
  --validation-start 2022-01-01 \
  --output output/аудит
```

Для CSV волн дополнительно задайте `--wave-source`. Отчёт
`shoreline-data-audit.json` содержит годы с числом контуров, включая пустые,
максимальный промежуток между наблюдениями, часы покрытия волнами, число линий
без `uncertainty_m` и сведения о поправке уровня воды, если исходный GeoJSON
содержит булево поле `tide_corrected` у каждой Feature. Для контура с заявленной
поправкой можно передать паспорт в `properties`:

```json
{
  "tide_corrected": true,
  "water_level_correction": {
    "method": "название и версия метода приведения линии к опорному уровню",
    "source": "источник измерений уровня воды и его временной охват",
    "vertical_datum": "название вертикального датума"
  },
  "uncertainty_m": 5.0
}
```

Все три строки паспорта обязательны и должны описывать именно выбранный
контур. Паспорт при `tide_corrected=false` отклоняется. Старый GeoJSON без
паспорта остаётся доступен, но значение `true` без метода, источника уровня и
датума не доказывает сопоставимость дат. Отчёт схемы 4 считает такие контуры,
перечисляет заявленные методы и датумы и предупреждает о смешанных датумах.
В кабинете сведения показаны у выбранной даты. Они являются заявлением
источника; Lito не вычисляет и не проверяет величину поправки.

SHA-256 исходных файлов сохраняется в отчёте. `geoaccuracy` не подменяет неопределённость
положения линии. Команда не рассчитывает прогноз и не решает автоматически,
пригоден ли набор: это требует согласованного определения берега, батиметрии,
профиля, проверки на поздних независимых датах и оценки ошибки.
`--validation-start` необязателен: Go относит более ранние контуры к части
для будущей настройки модели, а контуры с указанной даты — к отложенной
проверке. Дата должна оставлять наблюдения с обеих сторон. JSON схемы 4
сохраняет числа, границы и промежуток между частями, но не рассчитывает модель.
В `pilotCoverage` отдельно указано число линий, которые геометрически
пересекают стартовую рамку Сочи, и число таких линий по годам. Контуры вне
рамки не засчитываются в покрытие пилота. Это проверка местоположения,
а не точности наблюдения или готовности к прогнозу.

Для пилота у Сочи начальный охват совпадает с существующим техническим
OSM-сегментом: 39.6679270–39.7129247° E и 43.5854760–43.6442458° N
(EPSG:4326). Этот контур не является историческим рядом или линией после
поправки уровня воды. Чтобы сравнивать спутниковые даты, нужны датированные
линии для того же участка, способ поправки, вертикальный датум и оценка
неопределённости. Пока эти сведения не получены, новые трансекты и прогноз
на год или два в кабинете не доступны.

В личном кабинете на странице реплея наблюдений можно выбрать загруженный ряд
GeoJSON и при необходимости волновой файл, затем запустить тот же Go-аудит через
очередь worker. Результат показывается рядом с картой и сохраняется как
приватный JSON-артефакт задания. Доступ ограничен владельцем файлов и расчёта.

CoastSat полезен для получения исторических контуров и рядов на трансектах,
но сам не прогнозирует двухмерную линию. Для исторических волн Чёрного моря
кандидат — почасовой [Black Sea Waves Reanalysis](https://data.marine.copernicus.eu/product/BLKSEA_MULTIYEAR_WAV_007_006/services)
Copernicus Marine. Его NetCDF нельзя передать CLI без подготовки: нужны выбор
точки/области и переменных, перевод единиц, направление «откуда», временные
метки UTC и проверка разрешения 0,025° у конкретного берега, а также прав на
использование. Автоматическая
загрузка архива и прогноз на два года в Litora пока не реализованы.

## Запуск

```bash
./lito erosion \
  --input /путь/к/локальному-сегменту.geojson \
  --bathymetry output/source/black-sea-bathymetry-gebco2026-0.01deg-derived.json \
  --wave-input /путь/к/black-sea-wave-climate.json \
  --breaking-index 0.78 \
  --berm-height 2 \
  --closure-depth 8 \
  --porosity 0.40 \
  --cerc-coefficient 0.39
```

Для исследовательского набора рядом с батиметрическим JSON обязателен паспорт
`.metadata.json`. Формат, проверка SHA-256 и отличие целевого шага 0,01° от
официальной сетки GEBCO 15 угловых секунд описаны в
[`docs/data-provenance.md`](data-provenance.md).

Модель поддерживает только участки Чёрного моря. Координаты другого бассейна
отклоняются загрузчиками береговой линии и батиметрии; переключателя акватории
в CLI нет.

`--steps 0` использует весь ряд; положительное значение является явным
ограничением первыми состояниями ряда. Временной масштаб задаётся только
`duration_hours`, поэтому эвристические флаги штормов, сезонности и подъёма
уровня моря для этой команды не применяются.

## Границы применимости

Следующее описание относится к модели при наличии подходящих входов и
проверенных параметров участка.

Модель пригодна для скринингового инженерного прогноза и калибровки участка,
если есть достоверные `Hs`, `Tp`, направление, прибрежная батиметрия и
сведения об активном профиле. Перед принятием проектного решения нужно
калибровать `K`, глубину замыкания и берму по наблюдениям конкретного участка.

Она пока не моделирует дифракцию за сооружениями, отражение, нерегулярный
полный спектр, кросс-береговой перенос, изменение дна, исчерпание местного
запаса наносов и 2D-гидродинамику. Эти процессы потребуют отдельной
2D-морфодинамической ветви с регулярной сеткой, граничными условиями и
калибровочными наблюдениями.
