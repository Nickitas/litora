# Единая платформа Litora: реализация и план

## Как получить рисунки 3–5 в Лаборатории

В окне «Новый расчёт» откройте блок «Карты и сетки дна · рисунки 3–5»:

- «Обзор глубин» и «Фактическая сетка» запускают один сценарий визуализации
  готовой модели. Он сохраняет `seabed/svg/bathymetry-overview.svg` и
  `seabed/svg/mesh-details.svg`, а также 3D-вид и профили. В контрольных окнах
  показаны все ячейки MSH без прореживания. Повторный запуск Gmsh не требуется.
- «Поле размера ячеек» рассчитывает `seabed/svg/size-field.svg`, CSV и JSON
  поля h(x,y). Вариант примера использует минимум 200 м, берег 300 м,
  шельф 500 м и глубоководье 1000 м; значения видны и редактируются до запуска.
  Цвет обозначает целевую длину ребра. Новую сетку по этому полю создаёт
  отдельный сценарий «Построить адаптивную сетку».

Нужны принятая батиметрическая MSH, паспорт экспорта (для карт) и паспорт
источника. Если модели пока нет, сначала постройте плоскую full-quad MSH
по полному GeoJSON-контуру, затем назначьте глубины из производного JSON
GEBCO с проверяемым паспортом. В готовом результате доступны кнопки
следующего этапа: форма подставляет совместимые собственные файлы без
скачивания и повторной загрузки. При нескольких подходящих сетках выбор
остаётся явным. Новые сборки сохраняют также `seabed/bathymetry-source.json`;
для старых результатов недостающий паспорт нужно выбрать вручную.

При отключённых расчётах дна варианты видны, но кнопки недоступны:
администратор должен включить вычислительное окружение с отдельным heavy
worker. Форма не запускает задания автоматически. Полнота контуров, качество
батиметрии и разрешение MSH определяют детализацию рисунков; одинаковое
оформление не подтверждает совпадения результатов при разных исходных данных.

Форма нового расчёта выстроена одинаково для всех сценариев: тип расчёта,
исходные данные, параметры, результат. Выберите сохранённые входы или загрузите
недостающие файлы в разделе данных. Перед запуском форма перечисляет, чего
не хватает, и ожидает успешной проверки геометрии. Если исходный файл повтора
удалён, его нужно явно заменить или исключить, когда он необязательный.
Выключенные сервером сценарии помечены в селекторе; рядом показана причина.
Кнопка с вопросом возле типа расчёта открывает справку выбранного сценария:
входные данные, ограничения и ссылку на методику в новой вкладке. Escape или
кнопка закрытия возвращают к форме и сохраняют введённые значения. Причины,
мешающие запуску, и подсказки к полям видны в самой форме без открытия справки.
После запуска открывается страница задания со статусом, отчётами и файлами.

## Реализованный путь пользователя

Для работы с любым участком побережья доступен сценарий «Выбрать участок
побережья»: область на карте, полный встроенный или свой контур, отдельные
GeoJSON-линии и переход к следующим расчётам. Требования к собственным
наборам и официальные источники собраны в [справочнике данных](black-sea-regions-and-data.md).

1. Пользователь получает у оператора одноразовый ключ и регистрируется на `/login`;
   пароль хешируется Argon2id. Приглашение имеет срок действия и не может быть
   использовано повторно. Пользователь, сессия и погашение ключа сохраняются вместе:
   ошибка регистрации не расходует ключ. Для входа в существующий аккаунт ключ не нужен.
2. API создаёт сессию: случайный access token на 15 минут хранится только в памяти
   web, refresh token — в HttpOnly/SameSite cookie. В PostgreSQL лежат только хеши.
   При обновлении refresh token ротируется, logout отзывает оба токена.
3. В лаборатории пользователь открывает `/lab` для обзора активных и
   недавних расчётов, а форму запуска или загрузки контура — в модальном окне
   из обзора либо истории. `/lab/calculations` показывает историю,
   `/lab/calculations/:jobId` — полный результат, а `/lab/datasets` —
   паспорта своих малых GeoJSON-наборов. Устаревший
   `/lab/calculations/new` возвращает к обзору. Web обращается только к
   `@litora/api-client`; DTO находятся в `@litora/contracts`.
   `/account` показывает имя и email пользователя и служит заготовкой будущих
   настроек профиля. Старые вложенные ссылки `/account/calculations`,
   `/account/datasets` и `/account/shoreline` перенаправляют в лабораторию.
4. `POST /api/calculations` проверяет параметры и создаёт собственное задание
   со статусом `queued`. На пользователя допускается пять незавершённых заданий.
5. Отдельный Node worker из `apps/lito-api/src/worker` атомарно забирает задание
   через PostgreSQL `FOR UPDATE SKIP LOCKED` и запускает собранный Go CLI.
   Это начальный транспортный адаптер; научная логика остаётся в Go.
6. Каждый запуск получает собственный каталог и копию встроенных данных.
   Разрешены только заранее заданные
   команды и параметры; shell отключён, пользовательские пути и URL запрещены.
   Для своего контура API принимает UUID принадлежащего пользователю набора;
   worker получает приватный объект и сверяет размер и SHA-256 перед Go.
   Для малого GeoJSON API принимает только WGS84/EPSG:4326, пары
   `[долгота, широта]` в градусах и проверяет глобальные диапазоны координат.
   Пользователь может указать версию или дату снимка источника; это его
   заявление, которое сервис не подтверждает по внешнему реестру. Если версия
   не указана, в паспорте остаётся `null`.
   Для научных сценариев пользователь загружает приватные файлы до 512 МиБ каждый:
   API фиксирует роль, источник, лицензию и SHA-256, а worker повторно сверяет
   размер и хеш. Сам факт загрузки не подтверждает совместимость CRS, вертикальной
   системы и научную пригодность; их проверяют Go-команды при выполнении.
   Для волнового ряда `erosion_file`, `all_file` и `calibrate_cerc` действует более строгий предел 16 МиБ;
   принимаются только JSON и CSV. Источник волнового ряда указывается владельцем
   при загрузке и передаётся Go как `--wave-source`.
   Необязательные индексные профили CERC принимаются как JSON до 1 МиБ каждый;
   для `all_file` с ними упрощение контура запрещено.
7. CLI создаёт SVG/JSON/GeoJSON/MSH и `manifest.json` версии 2. Манифест содержит
   имя команды, а для `dimension`, `map`, `erosion` — идентификатор и ревизию метода,
   размеры и SHA-256 файлов. Worker проверяет соответствие метода сценарию
   до публикации результата и сохраняет файлы в приватный MinIO,
   а статусы, SHA-256 исполняемого ядра, вход и небольшие метрики — в PostgreSQL.
   Идентификатор и ревизия метода видны в кабинете; `baseline-1` обозначает
   текущую реализацию, но не научную валидацию. Для старых результатов поля
   могут быть пустыми. Для новых результатов сохраняется версия схемы, а в provenance — размер и
   SHA-256 входных файлов частной копии. Для демо Сочи также записываются
   заявленные источники из манифеста; это не проверка их лицензии. Web-демо
   `erosion` сверяет digest поставляемого набора до и после Go и не обновляет
   данные через сеть: при непригодном наборе расчёт завершается ошибкой.
8. Кабинет обновляет историю и список активных заданий каждые четыре секунды,
   а открытую страницу активного результата — каждые две. Пользователь видит
   только свои задания. Файлы доступны по signed URL на 15 минут.

История в `/lab/calculations` использует отдельный
`GET /api/calculations/page`: страницы по 20 записей, максимум 50, устойчивый
порядок по дате создания и UUID. Фильтры включают статус, сценарий, даты UTC
и точный UUID расчёта; свободного поиска по названию нет, поскольку названия
пока не сохраняются. Ответ содержит число совпадений и курсор следующей
страницы. Курсор относится к выбранным фильтрам и не даёт доступа к чужим
заданиям. В таблице истории следующая страница подгружается при прокрутке;
при ошибке остаются уже показанные строки и кнопка повторной загрузки.
На узком экране таблицу можно прокручивать по горизонтали. Старый
`GET /api/calculations` остаётся списком последних 100 для недавних расчётов
в обзоре и старых клиентов. Активные `queued` и `running` обзор запрашивает
отдельно через фильтрованные страницы истории, поэтому старое ожидающее
задание не исчезает за сотней завершённых. Если обновление не удалось, обзор
сохраняет последние полученные данные и явно сообщает об ошибке.

Раздел `/lab/datasets` показывает до 100 собственных наборов береговой
линии, их название, заявленные источник/версию/лицензию, CRS, число точек,
размер, дату и SHA-256. Поиск по названию и источнику работает только в
полученном списке. Здесь можно сохранить новый GeoJSON LineString отдельно
от запуска расчёта; он затем появится в форме сценария `dimension_dataset`.
После сохранения Go worker отдельным заданием проверяет геометрию. Карточка
показывает очередь, выполнение, результат и конкретные замечания, позволяет
повторить проверку. До успешного результата форма не запускает расчёт по этому
входу. Успех не подтверждает точность съёмки или пригодность для прогноза.
Карточка открывает `/lab/datasets/:datasetId`: карту линии и
её охвата, полный паспорт, скачивание сохранённого GeoJSON и форму размерности
с выбранным UUID. Открытие страницы, скачивание и переход к форме не запускают
расчёт. Редактирование и удаление сохранённых наборов пока недоступны.

`GET /api/datasets/:id` возвращает паспорт с геометрией, а
`GET /api/datasets/:id/content` — сохранённые байты. Оба запроса доступны только
владельцу: API проверяет размер, SHA-256 и структуру файла, затем выдаёт ответ
без S3-ключей и подписанных URL, с запретом кеширования. Чужой и отсутствующий
набор дают одинаковый 404. Повреждение или недоступность сохранённого объекта
дают безопасную ошибку 503.

`GET /api/datasets/:id/validation` читает состояние, а `POST` по тому же адресу
ставит проверку в очередь; для загруженного научного контура используются
`/api/scientific-inputs/:id/validation`. Запросы ограничены владельцем. Повторный
запрос во время активной проверки возвращает то же задание. Если очередь занята,
успешно сохранённый файл и паспорт остаются доступны, `validation` сообщает,
что проверка ещё не запрошена, и объясняет причину. Старые наборы проверяются
явным запуском. Для научных контуров нужен включённый heavy-профиль и его worker.

Служебные виды `dataset_validation` и `coastline_validation` вызывают
`lito coastline-check`. Вид `source_file` сохраняет прежний API и снимок
источника для совместимости; эти три вида скрыты в обычном выборе нового
расчёта. Прежние задания остаются доступны. API расчётов сохраняет совместимость
старых клиентов: проверка в форме не заменяет собственную валидацию входов Go
при выполнении каждого расчёта.

Полная страница расчёта показывает отдельные блоки результата, входных
параметров, происхождения файлов, метода и версий, времени выполнения и
артефактов. SHA-256 входных и выходных файлов виден целиком. Для старых или
незавершённых jobs отсутствующие поля отмечены явно; JSON-сводка ядра доступна
без пересчёта научных метрик в браузере. Сведения об источнике пользовательского
набора заявлены владельцем и не проверены внешним реестром. Ссылки на приватные
файлы временные; кнопка «Обновить ссылки» повторно запрашивает детали job.
Кнопка «Создать на основе» открывает новую форму с сохранёнными параметрами
своего расчёта; до нажатия «Запустить расчёт» новое задание не создаётся.
Форма повторно проверяет доступность входных файлов и не подменяет пропавший
набор данных встроенным примером без явного выбора пользователя. Новый запуск
использует текущую версию Go, поэтому это удобное повторное заполнение, а не
воспроизведение исторического ядра или гарантия одинаковых численных результатов.
SVG, PNG, JPEG, WebP и GIF из результатов показываются как изображения, без
вставки SVG-кода в страницу. Если предпросмотр не загрузился, полная страница
показывает ошибку и действие «Обновить ссылки и повторить»; файлы и остальной
паспорт остаются доступными. При отсутствии объекта в хранилище обновление
ссылки не восстановит сам файл. В окне сравнения предлагается открыть полный
отчёт для обновления. HTML и журналы не показываются как изображения.
Изображения больше 8 МиБ кабинет не загружает автоматически: пользователь
может явно открыть предпросмотр или скачать исходный SVG.
Кнопка «Скачать паспорт JSON» на полной странице сохраняет небольшой
машинно-читаемый документ `litora.calculation-metadata` версии 1. В нём есть
UUID, статус, известные параметры входа, даты, версии схем и метода, сведения
о происхождении, имена/форматы/размеры и SHA-256 файлов. Временных ссылок,
токенов приложения, командной строки worker, содержимого файлов и произвольных
JSON-метрик в нём нет. Если вход старого или неизвестного сценария нельзя
безопасно представить в этом формате, поле `input` равно `null`. Такой паспорт
не является CLI-манифестом или гарантией доступности файлов и не позволяет
запустить историческую версию ядра. Заявленные пользователем сведения об
источнике следует проверить перед передачей файла другим людям.

## Доступные сценарии

| Тип | Вход | Результат |
| --- | --- | --- |
| `source_file` | Свой приватный GeoJSON-контур с паспортом источника; совместимый API, скрыт в форме | Проверка источника, снимок GeoJSON и манифест |
| `dataset_validation` / `coastline_validation` | Автоматически после загрузки или явного повтора | Проверка исходной геометрии Go, состояние и замечания, отчёт и manifest |
| `dimension` | Полный закреплённый `data/coastline/black-sea.geojson` с паспортом MarineRegions | Box-counting по 9 635 точкам, SVG контура, отдельная регрессия и JSON |
| `dimension_dataset` | Свой GeoJSON `LineString` или пример участка Сочи по умолчанию: `EPSG:4326`, градусы, 2–500 точек, до 64 KiB; паспорт источника, лицензии и необязательной версии | Box-counting, SVG и JSON; Go проверяет научную пригодность при запуске |
| `dimension_file` | Свой полный GeoJSON-контур с паспортом источника | Box-counting, SVG и JSON |
| `map` | Поставляемая схема Чёрного моря и локальный участок Сочи | Обзорный SVG и GeoJSON |
| `map_file` | Свой приватный GeoJSON-контур Чёрного моря | Обзорный SVG и GeoJSON |
| `erosion` | Исторический тип, новые запуски удалены | Чтение прежних результатов владельца с отметкой демонстрации |
| `erosion_file` | Свой GeoJSON-контур, волновой ряд CSV/JSON (до 16 МиБ), JSON батиметрии и паспорт этого набора; необязательные индексные JSON-профили наносов и сооружений; 1–48 первых состояний или весь ряд с ресурсными лимитами | Те же CERC-отчёты, SVG, JSON и необязательные CSV/GIF; для всего ряда — полный численный JSON и ограниченное число SVG без GIF |
| `all_demo` | Исторический тип, новые запуски удалены | Чтение прежних результатов владельца с отметкой демонстрации |
| `all_file` | Свой GeoJSON-контур, волны CSV/JSON, JSON батиметрии с паспортом, 1–48 первых состояний или весь ряд с ресурсными лимитами; настройки CERC/упрощения и экспорт CSV/GIF; необязательные индексные профили только без упрощения | Тот же составной конвейер Go по собственным входам без переключения на демо Сочи; весь ряд сохраняет полный численный JSON и ограниченное число SVG без GIF |
| `calibrate_cerc` | Свои локальный контур, фактический волновой ряд, JSON батиметрии с паспортом и независимые наблюдения годовой скорости берега; явный шаг батиметрии, коэффициенты и необязательные индексные профили | JSON-рейтинг коэффициентов CERC по ошибкам наблюдений, manifest и приватный журнал |
| `mesh` | Свой полный GeoJSON-контур, размеры рёбер, детализация берега и генераторы | Плоские MSH, SVG и отчёт сравнения Gmsh |
| `seabed_build` | Плоская MSH, проверенный JSON батиметрии, его паспорт и тот же контур | Модель дна MSH/VTU/CSV/JSON |
| `seabed_render` | Модель дна, паспорт экспорта, паспорт источника, изобаты и масштаб 3D | Обзор глубин (рисунок 3), фактические фрагменты без прореживания (рисунок 5), 3D и профили SVG |
| `seabed_adapt` | Модель дна, паспорт источника и настройки поля размера | CSV/JSON/SVG поля размера |
| `seabed_generate_adaptive` | Модель дна, паспорт, CSV/JSON поля размера и полный контур | Фактическая full-quad MSH и отчёт проверки |
| `seabed_validate` | Проверяемая и независимая опорная модели, паспорта и поле размера | Ошибки глубин, изобат, уклона и размера |
| `seabed_compare_adaptive` | Модель дна, паспорт, CSV/JSON поля, контур, уровни и генераторы; необязательные уровни и seed AI-01, уровень и генератор рисунка 5 | MSH, SVG-превью сеток, рейтинг и отчёты Gmsh; по выбору — приватные экспертные карточки AI-01 и компоновка рисунка 5 |
| `seabed_assess_ml` | Заполненный TSV оценок, закрытый ключ AI-01, отчёт ADAPT-03, исходные MSH, паспорт EXPORT-02 и контур; пять настраиваемых порогов | Отчёт AI-02 JSON/TSV, файл оценки модели и краткая сводка решения |
| `seabed_check_full` | Плоская MSH полного моря, отчёт того же запуска `mesh` с SHA-256, полный контур, проверенная батиметрия и паспорт | QA-03, модель MSH/VTU/CSV, карты SVG и отчёт полного контура |

В `seabed_compare_adaptive` можно выбрать подробное окно Кызылырмакской косы.
Для каждого успешного генератора Go создаёт обзор и два SVG крупного плана
из фактических ячеек MSH. Публикационный вариант в кабинете не является
побайтовой копией архивных рисунков 6–7: перед использованием в статье
сверьте входные SHA-256, версии ядра/Gmsh, численные метрики и оформление.
В этой же форме можно включить экспертный набор AI-01: после принятого
сравнения Go создаст слепые SVG-карточки, лист оценивания, инструкции и
`organizer-key.json` в результатах владельца. Для каждого выбранного уровня
нужны минимум два успешных генератора. Закрытый ключ нельзя передавать
экспертам. Заполненные оценки можно загрузить в отдельном сценарии AI-02;
Go проверяет связь ключа, отчёта и трёх исходных файлов по SHA-256. Сбор оценок
экспертами и отдельный запуск AI-01 по старому заданию пока отсутствуют.
В том же сценарии пресет «Компоновка AI-01: три фрагмента 125–250 м»
включает AI-01 и сборку одного SVG из карточек Кызылырмакской косы,
Батумского залива и Анатолийского склона. Уровень и генератор можно изменить
до запуска. Файл остаётся приватным артефактом владельца и не предназначен
для слепой экспертной разметки.
Эта компоновка архивных карточек отличается от контрольных окон фактической
сетки `mesh-details.svg` из сценария визуализации модели.
Для работы по параметрам архивной статьи выберите «Отчёты по модели дна» →
«Поле размера ячеек» и нажмите «Архив статьи: поле 50–250 м», затем выберите свою совместимую
модель дна и паспорт источника. После успешного расчёта её CSV/JSON можно
выбрать в `seabed_compare_adaptive`; кнопка «Заполнить как рисунки 6–7:
сетки 125–250 м» задаёт уровень, оба генератора и окно Кызылырмакской косы.
Пресеты только заполняют редактируемые поля: входы остаются приватными и
выбираются отдельно, запуск требует подтверждения. Плотная сетка может
потребовать значительной памяти, диска и времени Gmsh; отметку о большом
расчёте пресет не включает. Одинаковые параметры без одинаковых исходных
файлов и версий инструментов не гарантируют совпадения рисунков.
Для рисунков 1–2 встроенный `dimension` уже использует полный архивный контур;
для другого собственного источника используйте `dimension_file`,
для рисунка 3 — `seabed_render` с принятой моделью дна и паспортами.
Для трёх контрольных окон «сложный берег → шельф → склон» выберите подтип
«Фрагменты фактической сетки»: `seabed_render` создаёт
`seabed/svg/mesh-details.svg`. Другой архивный рисунок 5 — компоновка AI-01:
`seabed_compare_adaptive` с AI-01 и пресетом статьи создаёт
`seabed/expert-set/fig_05_actual_mesh_fragments.svg` из трёх карточек
того же задания (Кызылырмак, Батуми, Анатолийский склон).
Ни один пресет не обещает побайтового совпадения с
архивом: нужны те же входные SHA-256, параметры, версии ядра/Gmsh и проверка
научных метрик. SVG сравнения сеток также можно изучить и скачать отдельно.

В форме «Отчёты по модели дна» один селектор задаёт основной SVG: обзор
глубин, поле h или фактические фрагменты. Подтип определяет необходимые
файлы и параметры; выбор сохраняется при повторе и выделяется на странице
задания. Остальные артефакты Go остаются доступны. API принимает необязательный
`input.reportType`: `bathymetry_overview` или `mesh_details` для
`seabed_render`, `size_field` для `seabed_adapt`; несовместимые значения
отклоняются. Старые задания без подтипа показывают прежнюю галерею.
Если модели нет, раскройте «Подготовить модель дна»: доступны построение
плоской сетки и назначение глубин из реального набора с паспортом.

У всех трёх сценариев размерности есть поле «Вид отчёта box-counting»:
берег с аналитической сеткой или график регрессии. Подтипы API —
`coastline_box_counting` и `box_counting_regression` в `input.reportType`.
Оба SVG и JSON строит Go на тех же выбранных данных; основной SVG выделен
на странице задания. Выбор сохраняется при повторе и в JSON-паспорте.
В ревизии `box-counting/reports-3` график согласован с JSON по округлённому
покрытию и свободному члену регрессии. D и R² вычисляются прежним методом.

Пользователь может сохранить не более 100 малых GeoJSON-наборов. При достижении
лимита API возвращает 409 и новый файл не сохраняет. Это пилотный предел;
самостоятельное удаление набора пока недоступно.
Для научных файлов действует пилотная квота 20 записей и 2 ГиБ заявленного
объёма на пользователя. Форма расчёта показывает текущий расход: в него
входят готовые и незавершённые загрузки. Счётчик обновляется после
резервирования или удаления незавершённой записи; при ошибке чтения квоты
форма не показывает ложный ноль. Неудачную загрузку можно продолжить или удалить
незавершённую запись; готовый файл через этот endpoint не удаляется.
Между шагами `mesh` → `seabed_build` →
`seabed_render`/`seabed_adapt` → `seabed_generate_adaptive`/
`seabed_compare_adaptive` совместимые MSH, паспорт экспорта и поле CSV/JSON
можно выбрать прямо из результатов собственных успешных расчётов. API
также можно вернуть принятую MSH из `seabed_generate_adaptive` в
`seabed_build`. MSH из сравнения `seabed_compare_adaptive` пока не предлагаются:
успех задания не гарантирует принятия каждого отдельного запуска генератора.
API предлагает только известные форматы; остальные файлы по-прежнему нужно
загрузить вручную. Повторно используемый артефакт ограничен 2 ГиБ, все
научные входы задания — 4 ГиБ; worker сверяет SHA-256 после скачивания.
Метаданные результата сохраняют UUID исходного расчёта, роль и SHA-256 такого
входа, поэтому цепочку можно проследить из кабинета и файла метаданных.
Для `seabed_check_full` MSH и `mesh-comparison.json` можно выбрать из одного
успешного задания `mesh`; Go сверит SHA-256 выбранной сетки с записью отчёта.
Старый отчёт без `mesh_sha256` после переноса в другое задание не подходит —
запустите `mesh` новой версией или используйте CLI в исходном каталоге. Web
ограничивает входную MSH 256 МиБ, но реальный расход RAM и диска на полном
море нужно проверить отдельно на тестовой инфраструктуре.

Новые расчёты CERC работают по собственным входам в тяжёлых сценариях
`erosion_file`, `all_file` и `calibrate_cerc`. Индекс разрушения, параметры
активного профиля, пористость, коэффициент CERC, расстояние отбора глубины,
радиус поиска и граничные потоки требуют явного ввода по данным участка.
Пустое значение не заменяется типовым числом или нулём. Для калибровки также
нужны кандидаты коэффициента, допустимая дистанция наблюдений и фактический
шаг батиметрии из паспорта (не больше 0.1°). Для сборки/проверки модели дна
радиус поиска глубины выбирается явно по покрытию источника.

Под полями показаны единицы, технические диапазоны и основания выбора.
Экспорт, ресурсные лимиты и алгоритмические начальные настройки предзаполнены,
но не являются научными рекомендациями для участка. Новое сравнение сеток не
выбирает географическое окно: Кызылырмак включается явным архивным пресетом.
Сохранённый расчёт переносит известные значения; это не подтверждает их
научную пригодность. API проверяет те же числовые ограничения и форматы,
что форма; содержимое файлов и научную совместимость проверяет Go.

Имя файла батиметрии должно быть простым ASCII-именем с суффиксом `.json`:
Go сверяет поле `dataset_file` и SHA-256 в паспорте, лежащем рядом с файлом
под именем `*.metadata.json`. Worker создаёт это соседство в приватном
каталоге задания; пользовательские пути не принимает. При `steps=0` Go
использует все состояния загруженного ряда (не более 10 000) на контуре до
200 точек и сохраняет полный `longshore-cerc.json`. Число SVG эрозии выбирается в
форме от 2 до 128: сохраняются начальное и конечное состояния, а промежуточные
распределяются равномерно. GIF и широкий CSV недоступны; длинный CSV остаётся
опцией. Длительный запуск может упереться в лимиты worker по времени и объёму
файлов. Индексные источники/стоки наносов и сооружения доступны по своим
приватным входам. Граничные потоки задаются в форме
для `erosion_file`/`all_file`/`calibrate_cerc`; результат не становится
калиброванным прогнозом лишь от загрузки собственных файлов.

Новые CERC-результаты дополнительно содержат приватный индекс интерактивной
карты и ограниченные части временного ряда. В `/lab/shoreline` владелец
переключает сохранённые положения берега и видит исходный контур, высоту волн,
смещение по ячейкам, временной ряд выбранного узла и баланс шага. Каждая точка
ряда — смещение за отдельный шаг; пропуск не равен нулю. API отдаёт только
запрошенные части после проверки владельца; браузер не загружает весь научный
JSON. Карта расчёта использует современную подложку OpenFreeMap: она помогает
различить сушу и воду, но не является снимком исторической даты. При отказе
тайлов контуры остаются на полной координатной сетке. При переключении кадров
масштаб карты сохраняется, а на время загрузки виден прежний контур с явным
сообщением. Геометрия сохраняет рассчитанные координаты при любом масштабе карты.
На странице обзора кабинета есть переход к карте. На `/lab/shoreline` сначала
выберите свой сохранённый CERC-результат. Если результатов нет, подготовьте
береговой контур, волновой ряд, батиметрию и паспорт участка, затем создайте расчёт
по своим данным. Встроенный пример автоматически не открывается. Исторические
демонстрационные результаты доступны при явном выборе и отмечены как демо.
Кнопка реплея
переключает только рассчитанные кадры; между ними положение берега не
интерполируется. Для исследования горизонта около года используйте исторический
ряд волн не короче 8766 часов, датированные независимые наблюдения, батиметрию
и параметры активного профиля: сначала сценарий калибровки CERC, затем свой
полный ряд с `steps=0`. Это проверяемый расчёт по заданным воздействиям, а не
готовый аттестованный прогноз будущей линии. Приливы, изменение уровня моря и
процессы вне одно-линейной модели нельзя считать автоматически учтёнными.
Квадратные фиолетовые метки показывают модельное смещение к
суше, круглые синие — к морю за выбранный шаг. Цвет и размер меток не означают
величину смещения; точное значение выбранного узла указано в метрах за шаг.
Слой показывает знак без порога чувствительности и не классифицирует значимый
размыв или накопление. В исходных SVG-отчётах Go нейтральная зона учитывается
отдельно. Знак внутреннего смещения CERC обратен знаку независимых наблюдений
годовой скорости.
Слой можно скрыть, а скорость реплея — изменить без пересчёта модели. Для
расчётного реплея за годы нужен соответствующий временной ряд во входных
данных и новый расчёт. При отсутствии дат шкала показывает шаги модели и длительность
выбранного шага, а не условные годы. Старые jobs без нового индекса остаются
доступными через прежние SVG/JSON.
Селектор карты показывает все страницы ваших успешных CERC-расчётов с
сохранённым индексом реплея. Сценарий можно отфильтровать; дата рядом с
названием — время запуска задания, а не дата состояния берега. Отсутствие
задания в этом списке означает, что индекс карты не зарегистрирован; открыть
старый результат можно из истории расчётов.

Отдельно в `/lab/shoreline` можно загрузить **наблюдаемые контуры CoastSat**
в GeoJSON и проигрывать даты спутниковых снимков. Используйте [экспорт линий
CoastSat](https://github.com/kvos/CoastSat/blob/master/example.py), затем
преобразуйте результат в EPSG:4326. В файле нужны `LineString`
с `date` и `satname`; `cloud_cover` и `geoaccuracy` показываются, если есть.
Координаты должны быть `[долгота, широта]`. Лимит — 16 МиБ,
2–2500 дат и не более 120 000 координат. Файл остаётся приватным. После
загрузки выберите его в разделе «Спутниковые наблюдения» над сценариями CERC.
Шкала показывает только реальные даты; пустые дни, недели и месяцы не
заполняются искусственными контурами. Это граница песка и воды на снимке, а не
непрерывный мониторинг или готовая оценка эрозии: облака, геопривязка и
уровень моря требуют проверки. `geoaccuracy` показывается как исходный
показатель без переименования в метры, поскольку смысл зависит от спутника.
Автоматического запуска CoastSat и Google Earth Engine в Litora пока нет.
Датированные линии на карте рисует D3 поверх географической подложки MapLibre
с данными OpenFreeMap/OpenStreetMap. Подложка показывает современную местность,
не спутниковый снимок выбранной даты. Её источник указан на карте. Если внешний
сервис недоступен, линии остаются на координатной сетке. При просмотре карты
браузер запрашивает у внешнего сервиса тайлы области просмотра; приватный
GeoJSON туда не передаётся.
При малом смещении линии могут совпадать в пределах экранного пикселя. Увеличьте
карту или включите «Сравнить миганием»: первый и выбранный контуры будут
показываться попеременно без изменения координат. В режиме уменьшенной
анимации мигание отключено.

На карте можно скрыть исходный контур и координатную сетку. Метки направления
смещения по узлам включаются отдельно и не перекрывают берег при первом открытии.
Выбранный узел
соединён с исходным положением в масштабе карты: малое смещение может быть
меньше толщины линии, поэтому точное число смотрите в таблице. Кнопка
«Крупный план узла» приближает камеру к исходной координате выбранного узла;
при смене кадров камера остаётся на месте. «Весь участок» возвращает обзор.
Приближение увеличивает масштаб карты, но не умножает смещение и не создаёт
дополнительный контур. На недоступной внешней подложке крупный план строится
локальной проекцией D3 с теми же точными координатами.
Ползунок сразу под картой перематывает все сохранённые кадры, в том числе через
границы календарных периодов. Дата и номер текущего шага остаются рядом с ним.
Если выбранный день, неделя или месяц не содержит кадров, карта не подставляет
старый контур под новую дату: шкала показывает ближайшие сохранённые кадры и
позволяет перейти к ним напрямую.

Исторические результаты `all_demo` получены составной командой Go на
закреплённом наборе Сочи с проверкой SHA-256 до и после расчёта. Повторное
выполнение этого сценария удалено. Сохранённые параметры CERC и экспорта можно просмотреть в результате.
Имя экспортируемого файла выбирает сервер; кабинет
показывает все артефакты приватного задания. Результат остаётся demo, а не
калиброванным прогнозом или моделью дна.
`all_file` запускает ту же команду по собственным четырём входным файлам,
первым 1–48 состояниям или всему ряду волн и выбранным параметрам. Он не включает
сеточное моделирование дна и не становится научно аттестованным прогнозом.

Демонстрация не является прогнозом годового размыва. Карта полного морского района
не заменяет локальную геодезическую съёмку. Остальные возможности
самостоятельного CLI (удалённый URL для `source` и часть экспертных сценариев)
пока не предоставлены через HTTP.
Перед запуском кабинет показывает для каждого доступного сценария источник
входов, ограничение применимости и ссылку на соответствующую методику.
`erosion` и `all_demo` исключены из новых запусков в web. При переходе
«Создать на основе» из старого демо предлагается соответствующий сценарий по
своим данным: выберите сохранённые входы или загрузите файлы и проверьте параметры
участка. Параметры демо не переносятся; прежний результат остаётся доступен с
отметкой о демонстрационном характере. API отклоняет новые запросы этих видов
с HTTP 400. Ранее принятые демо-задания worker завершает с понятной ошибкой
до подготовки файлов и запуска CLI. Записи и старые артефакты не удаляются.
В CLI удалены автоматическая подготовка Сочи и демо-флаги: `erosion`/`all`
работают только с явно выбранными контуром, волнами и батиметрией.
Встроенные `dimension` и `map` используют один закреплённый снимок MarineRegions
с проверкой размера/SHA-256 и паспорта до запуска. Worker проверяет комплект
обязательных отчётов и SHA-256 всех заявленных Go файлов до публикации в S3.
Ошибка записи обязательного SVG или интерактивной карты приводит к ошибке задания.
Карта Чёрного моря сохраняется как научный SVG с координатной сеткой, осями,
масштабом и сведениями об источнике; служебные карточки и предупреждения в неё
не включаются. Журналы и другие текстовые артефакты открываются с явным UTF-8.
Новые ссылки на старые журналы также задают кодировку, сохраняя исходные байты
и SHA-256; для получения новой подписанной ссылки обновите страницу расчёта.
Старые сохранённые расчёты не переписываются: для полного контура создайте новый.
Лимит пяти незавершённых заданий относится к статусам `queued` и `running`;
он не обозначает позицию конкретного задания в очереди.
Если файл не загружен, кабинет ищет сохранённый малый пример Сочи
(OpenStreetMap way 59530506, ODbL) по паспорту и SHA-256 и использует его UUID.
Если его ещё нет, при запуске создаётся один приватный набор. В каталоге
доступны ещё два отдельных учебных контура
OSM — Геленджик и Анапа; пользователь сохраняет их явно. Каталог показывает
фактически сохранённые записи и расход квоты без визуального объединения.
Это технический пример, а не пользовательская съёмка. Свой файл не подменяется
примером.

## Отказоустойчивость и ограничения

- По умолчанию worker исполняет одно задание за раз, лимит — пять минут
  (`JOB_TIMEOUT_MS`). Docker ограничивает worker двумя CPU и 2 ГБ памяти.
- Загруженные полные контуры и научные сценарии забирает только отдельный worker профиля `heavy` с Gmsh:
  локально 4 CPU, 12 ГБ RAM, до четырёх часов и до 8 ГиБ результата. Профиль
  включается `pnpm up:heavy`; обычный `pnpm up` скрывает тяжёлые сценарии и
  отклоняет их прямой запуск с 503. Это защитные
  пределы, а не измеренная достаточная конфигурация для каждого набора.
- Пока Go выполняется, worker примерно раз в секунду проверяет выходной
  каталог: не более 100 МиБ, 256 файлов и 256 вложенных каталогов для обычного
  профиля; для `heavy` — до 8 ГиБ и 512 файлов.
  Превышение останавливает процесс и завершает задание ошибкой. Проверка
  периодическая: это не жёсткая квота на мгновенный пик диска; для больших
  сценариев нужна отдельная квота контейнера или файловой системы.
- Для пользовательской линии worker сверяет размер и SHA-256 приватного объекта.
  Обычный результат ограничен 256 файлами и 100 МиБ, тяжёлый — 512 файлами
  и 8 ГиБ перед загрузкой в S3; пик временного диска в ходе работы CLI
  этим ещё не ограничен.
- Heartbeat обновляется каждые две секунды. При потере связи worker останавливает
  дочерний процесс. Задания с heartbeat старше минуты помечаются ошибкой при
  следующем проходе работающего worker. Автоматический повтор не выполняется.
- Отмена фиксируется в БД; worker останавливает процесс после очередной проверки.
  Финальное обновление статуса условное: отмена не перезаписывается успехом.
- Сохраняется журнал CLI; его текст ограничен примерно 1 МБ. Ошибки доступны
  владельцу задания. При ошибке или отмене worker удаляет результаты,
  загруженные этим запуском, из S3 и удаляет их записи из БД. Журнал ошибки
  сохраняется отдельно; у отменённого задания он не создаётся. При сбое самого
  worker или недоступности S3/БД всё ещё возможны оставшиеся объекты или
  метаданные. Для оператора есть ручная сверка S3/БД: по умолчанию она только
  показывает старые частичные результаты `failed`/`cancelled`; удаление требует
  явного подтверждающего флага. Отдельно она показывает подтверждённые HEAD
  отсутствующие файлы у старых завершённых заданий (до 100 проверок за запуск),
  но не меняет такие записи автоматически. Автоматический сборщик и полная
  проверка больших хранилищ ещё не реализованы.
- Обзор по-прежнему показывает выборку из последних 100 заданий; история
  листается через API. Общее число зависит от текущих фильтров и может
  измениться, если в это время создаются новые задания.
- Авторизационные запросы ограничены 30 попытками в минуту на IP. При превышении
  API отвечает 429 и указывает время ожидания в `Retry-After`. Пользователи за одним
  NAT делят лимит. За корректно настроенным доверенным proxy учитывается IP клиента;
  без такой настройки — адрес proxy. Защита ingress от перегрузки нужна отдельно.
- Локальный Compose публикует порты только на loopback. Для production нужны
  HTTPS, `COOKIE_SECURE=true`, точный `WEB_ORIGIN`, внешний S3 endpoint, резервные
  копии PostgreSQL/S3, политика хранения, мониторинг и восстановление паролей.

## Запуск и проверка

Полная инструкция запуска находится в корневом README. `pnpm up` собирает Go,
API и web и поднимает PostgreSQL, MinIO, API, worker, nginx. Миграции применяются
автоматически под advisory lock; таблица `schema_migrations` предотвращает повтор.
Существующие volumes сохраняются при обычном `pnpm down`.

`pnpm test:integration` проверяет регистрацию, вход, ротацию сессии, logout,
выполнение трёх встроенных сценариев и dimension на своей линии, SHA-256
скачанного манифеста, приватность bucket,
изоляцию двух пользователей, отмену и Swagger. Проверка создаёт тестовые аккаунты
и отчёты в выбранной БД; запускать на локальном или тестовом окружении.
Тест требует три заранее выпущенных приглашения в `TEST_INVITATIONS_JSON`;
операторские команды и порядок запуска описаны в корневом README.

## Удаление расчётов

В личном кабинете владелец может запросить удаление завершённого расчёта и его
доступных файлов либо всей истории на момент подтверждения. Для полной очистки
не должно быть активных или завершающихся расчётов; отдельный результат,
используемый другими расчётами, сначала потребует удаления зависимых. Операция
выполняется worker в фоне, а кабинет показывает число обработанных расчётов и
ошибки с автоматическим повтором. Загруженные исходные файлы и наборы данных
этим действием не удаляются. Отмены удаления через кабинет нет; старые версии
объектов в S3 и резервные копии следуют отдельной политике хранения. Функция
пока требует проверки на staging и настройки права удаления для worker.

## Следующие этапы

1. Другие типы пользовательских данных и большие файлы: отдельные контракты,
   проверка CRS/единиц/размера и научной применимости для каждой модели.
2. Связи результатов как входов следующих заданий без повторной загрузки,
   ресурсные замеры Gmsh/GEBCO и контрольный паритет с архивом статьи.
3. Выделение Go worker с прямыми вызовами Go-пакетов при сохранении внешнего
   API-контракта; текущий Node worker служит адаптером запуска CLI.
4. Сохранённые конфигурации и воспроизведение исторических версий расчёта,
   полный срок хранения и квоты S3,
   уборка незавершённых загрузок, email verification и восстановление пароля.
5. Наблюдаемость, worker health/alerts, резервирование, deployment с TLS и
   нагрузочные проверки. Redis добавлять только при подтверждённой необходимости.
